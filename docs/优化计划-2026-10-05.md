## 一、历史数据：能点开看、重开应用入口还在（S-M，用户已拍板简化）

**用户拍板（2026-10-05）**：不要做成独立功能页。需求只有两点——① 能点开看某次历史；
② 重开应用后**入口还在**（不要求重新展示那次的内容）。

**方案（简化版）**

1. **入口 = 看板那张「本次导入新增」卡本身，常驻**：只要有历史就渲染
   （`ImportResultCard` 的条件从「内存里有最新结果」放宽为「有最新结果 or 有历史」，历史从
   localStorage 读——入口自然跨重启存活，不做新 tab/新页面）。
2. **历史条目可点击** → 卡内展开/轻量弹层看那次导入明细（复用 analyzeImport 数据，每账号新增/更新数、
   精灵列表），同一卡片内完成，不加导航。
3. 不做 header 图标 / 第 5 个 tab / 详情页。

**影响文件**：ImportResultCard.tsx、lastImportStore.ts（只需暴露 history 读接口 + 是否有历史的判断）

## 三、收集展示（先对齐需求，分 6 个子项）

### 三.1 + 三.2 + 三.3 合并为「多账号展示排序优化」（中，用户拍板口径）

**用户拍板（2026-10-05 对齐）**：母本收集进度 = 各账号母本之和（**统计口径不变，不做分区统计**）。
真正的玩法是会开小号孵蛋传给大号，「全账号加起来」就是完整进度。核心问题只是**多账号精灵在展示里
排序杂糅，看不出各自账号的精灵**。所以方案 = **展示层排序/分组优化**，全部落到 3 处：

1. **看板·母本全收集**（原三.2）：档位 chip 组换**下拉（4 档）**，选中后自动展开；展示内容**按账号聚拢排序**。
   **范围确认（用户 2026-10-05）：只改「进度表下方按链列母本的那块展示区」，上方进度表不动。**
2. **我的精灵·种公 / 母本标签页**（原三.3）：多账号精灵**按账号聚拢展示**（排序/分组），不再杂糅。
3. **母本跨账号分布**（原三.1）：无需「分布标注」，排序聚拢后各账号的分布自然可见；
   同物种同性格跨账号的链仍算一条（口径不变）。

**影响文件**：Dashboard.tsx、MotherView.tsx、MyPets.tsx、（建议抽公共「账号聚拢」排序工具函数/组件复用）
**复杂度**：M　**开放问题**：账号聚拢用「排序」还是「分组 + 小标题」？（推荐分组 + 小标题，配窝建议已有该模式可直接复用）

## 四、覆盖度：加回「自选性格」+ 固定组排序 + 性别比例特殊模式（M-L，已对齐）

**用户拍板（2026-10-05）**

1. **「推荐性格 / 自选性格」开关**（不做模式切换页）：默认「推荐性格」= 现状（每蛋组按推荐前 3 + 急躁）；
   切「自选性格」→ 出现全局八大性格勾选器（`targetNaturePool`），勾选/取消的性格应用到全部蛋组，
   一键全选/清空。开关文案：**推荐性格 / 自选性格**。
2. **修体验问题①：蛋组行固定排序**——按 groupId 固定顺序，不再根据选中性格数量动态重排
   （现状 `CoverageMatrix` 行序受选择影响，要改固定）。
3. **修体验问题② + 特殊模式：性别比例 ≠ 5:5 的物种收集**。普通种公网络覆盖不了它们
   （如大耳帽兜只有母的，无法迭代补种公），新增「性别比例特殊物种」模式专门收集，分三类：
   - 纯母（male=0）：小夜、大耳帽兜、甜田螺、一窝蜂等
   - 公多母少（8:2）：拉特、火花、阿米亚特、石石、护主犬
   - 母多公少（2:8）：小草虫
     三类各给**一行系统内规则说明**（属于工具内部规则说明，不算过度解释——用户明确这是「系统内规则」）。
     **放置位置（已拍板）：覆盖度页新增第三块清单。**
     **名单来源（已拍板：用字段，不手维护）**：vendor 游戏数据每只精灵自带 `gender_ratio: {male, female}`
     （10 分比例，`tools/data-pipeline/src/pet-diff.mjs` 已收录、管线现只用它算 `maleCapable`）。
     改造成本评估：**小-中**——管线 `trim-catalog.mjs:94` 加一行把 `genderRatio` 烘焙进 `catalog.gen.json`，
     `SpeciesEntry` 加可空字段，UI 区块从 species 全量筛「比例 ≠ 5:5」自动分三类（不再维护固定名单，
     新精灵自动进）。需重新跑 `npm run trim:catalog` 重建目录。风险：vendor 数据是否覆盖全部精灵
     （`maleCapable` 已在用，覆盖面可信）。

**影响文件**：Coverage.tsx、CoverageMatrix.tsx、coverageFilterStore.ts、trim-catalog.mjs → catalog.gen.json、catalog.ts（SpeciesEntry 加 genderRatio）
**开放问题**：无（已全部拍板）

## 五、华为平板「导出全部数据」拉不起分享（S-M，本轮修复）

**现状（已核实）**：壳的 `ShareBridge.shareBackup`（`android-shell/.../MainActivity.java:400-435`）在
`@JavascriptInterface` 回调里直接 `startActivity(Intent.createChooser(...))`。JS 桥方法跑在独立的
JavaBridge 线程（非主线程），华为 EMUI/HarmonyOS 对**非主线程/后台弹出系统界面**限制比小米严格，
chooser 被静默拦下 → 表现为「点导出没反应」。

**方案（推荐，修一版 APK 在华为平板验证）**：

1. `startActivity` 包进 `runOnUiThread`，并给 Intent 加 `FLAG_ACTIVITY_NEW_TASK`（华为需要）。
2. 保留现有 FileProvider → EXTRA_STREAM → 文本兜底两级降级；异常时把错误带回网页提示。
3. 抽取 HTML 验证页/日志确认 JS 桥确实到了（排除变量）。

**影响文件**：`android-shell/.../MainActivity.java` → 重新打包 APK（JDK21/SDK35/NDK28/CMake 3.22.1 环境）
**复杂度**：M　**验证**：华为平板 + 小米手机各点一次导出
