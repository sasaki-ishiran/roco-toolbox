# HTML 设计稿与共用外壳规范

生效：2026-11-16。设计资产入口：[设计资产总览](README.md)。视觉尺寸与控件语义仍以[产品交互规范](../产品交互规范.md)为准。

## 开始做 UI

1. 先查设计资产总览和台账，找到同一场景的已采用稿、当前实现与后续替代记录。采用范围按条目核对；历史稿中未采用的选项不能一并继承。
2. 整页 HTML 复用 `docs/prototypes/shared/toolbox-shell.css` 与 `toolbox-shell.js`。卡片布局实验可以独立，但交付时必须有真实屏宽和整页上下文预览。
3. 只还原本次流程需要的页面内容。工具箱标题栏、主导航、当前小组与计划中心层级共用；其他模块保留真实入口与范围提示，无须每次重做全部页面。
4. 新增界面或明显改版先交可交互 HTML / 375、390 双宽截图，经用户确认再落业务代码。制作评审 HTML 的授权不等于打包、部署或发版授权。
5. 本次确认、采用部分、代码证据和剩余功能同步记入台账；最后运行台账校验。

## 外壳的职责和边界

- 当前实现参照：`src/App.tsx`、`src/ui/TabNav.tsx`。六个全局入口：看板、家园、收集、附近、小组、我的。产品导航变化时先核对实现，再同步共用外壳和规范。
- 已提供的场景适配：小组 → 当前小组 → 我的收集 / 组内广场。蛋仓、我的换蛋用完整列表；需求、单颗蛋、供给和轻量确认用二级弹窗，支持嵌套。关闭/返回恢复来源与位置，不能用切换页签冒充进入详情。
- “蛋仓”“我的换蛋”属于组内业务入口，不与六个全局入口平级。
- 外壳管理标题、导航、组头、页签和返回；业务原型管理卡片、数据、筛选、进度与状态。样例/API 密钥不放进共用外壳。
- 目前共用外壳是 HTML 评审设施，已提供小组场景；不是六个业务模块的完整实现，也不表示换蛋已经上线。新增其他场景时扩展同一外壳，避免复制一套导航。
- 接入示例与 API 见[共用外壳 README](../prototypes/shared/README.md)。当前示例入口：`2026-11-15/换蛋撮合原型/editor/index.html`。

## 视觉和流程验收

- 375 / 390 两宽核对层级、密度、长昵称、空态、失败态、缺图与横向溢出。重复卡片优先用合理列数，重要触区不重叠。
- 优先引用项目现有资源：需求物种用精灵头像，库存蛋和交易实物用蛋图，体型/声音用奖牌；资源缺失应明确标记。
- 常驻文案只保留必要事实与动作；教学进入教程体系。默认数量 1、省略条件与重复状态不额外占一行。
- 验证真实点击链路与返回来源。领域口径以本次已确认需求和领域文档为准，不从历史假数据推断新规则。
- 截图、原型和业务代码分别记录验收状态；仅有原型或代码不能标成“正式上线”。

## 设计稿生命周期

台账分别维护“采用状态”和“发布范围”。

| 采用状态 | 条件 |
| --- | --- |
| 已采用 | 有确认或明确落地证据，写清采用部分与未采用部分 |
| 评审中 | 当前可评审稿，尚未证明已落业务代码 |
| 已被替代 | 有后续稿或现行实现，写清替代目标及失效部分；可保留曾采用记录 |
| 未实现 | 有证据表明该方案对应功能未落地；未实现不等于取消 |
| 待核实 | 证据不足或互相冲突，列出缺失证据，核实前不指导实现 |
| 评审附件 | 对照图、同版副本或分享包装，无独立采用结论 |

发布范围另记正式发布记录、正式线实现、开发/内测、仅原型或待核实。“正式线实现”仅代表所核对 Git 基线，不能替代线上实时验收。

### 保存与归档

- 历史稿原位归档：保留文件、资源相对路径与历史链接，通过归档索引标记状态。移动、删除、覆盖历史产物另需用户明确授权。
- 一稿多方案只记录实际采用方案；“定稿”“正式版”文件名不是采用证据。被替代稿必须能追到后续稿或实现，未实现稿必须说明具体缺项。
- 新稿按 `docs/prototypes/<主题>/<日期或版本>/` 存放；现有日期目录及根目录历史稿保留原位。共用资源仍放 `docs/prototypes/shared/`。
- 当前被 `.gitignore` 忽略的原稿、截图和分享包仍是本机资产，台账链接不代表已入库或异机可恢复；本轮不改忽略策略、不上传个人样本。新稿验收时注明保存范围，缺少本机原件时先补齐，不自动略过。
- 台账为单一数据来源，索引从台账生成。每项保存原路径、用途、状态、采用范围、证据、替代关系与内容指纹。
- 后续 UI 交付同时更新台账：先登记评审稿，确认后补证据；落地后记录代码与发布范围；替代时双向可追溯。

## 权威顺序

用户本次明确指令 → 已确认需求/设计决策 → 当前业务实现及领域规范 → 本规范与产品控件规范 → 设计稿。发生口径冲突先核实；“待核实”保留证据缺口，不据此修改业务。
