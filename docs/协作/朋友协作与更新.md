## 二、同步代码（保留你本地的改动）

目标：把本地改动搬到新的协作分支上，不丢代码。

```bash
# 1. 拉最新
git fetch origin

# 2. 本地有未提交改动时先暂存
git stash push -u -m "friend-wip"

# 3. 切到协作分支（第一次需要 checkout）
git switch -c friend/20261119 origin/friend/20261119
# 已有本地分支时：
git switch friend/20261119
git reset --hard origin/friend/20261119

# 4. 把暂存改回来
git stash pop

# 5. 如果之前已经在旧分支上提交过：变基到新分支
git rebase origin/friend/20261119
```

发生冲突时：先保留你的界面改动，冲突文件里只读清单里的内容（账号、发版、迁移）一律取新分支版本，不要手工合并。

推送走你自己的 fork，然后向 `friend/20261119` 发 PR，不要直接推 `test` / `release`。
