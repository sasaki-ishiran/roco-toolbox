## 0. 先看这三条结论

1. **计划中心已经在 `main` 上，但不在正式线 `release/prod-1.5.0` 上。**
   - `main` 含 `src/ui/plan/**`（`git ls-tree main -- src/ui/plan` 可查到 13 个文件）。
   - `release/prod-1.5.0` **完全没有** `src/ui/plan/**`，也没有 `src/shared/collectionPlans.ts`、`functions/_lib/collectionPlans.ts`、两份 2026-11-08 迁移。

   - `release/prod-1.5.0` 已经有 1.5.5 的发版工作（清单 1.5.5 / 39、`deploy-web.mjs` 的正式清单断言、附近/悬浮窗改动）。

   - 直接 merge 任一方向都会把对方未验收的东西带过去，必须按文件摘取。

3. **“正式 bundle 不含『收集计划』”这条断言与本次目标正面冲突，必须改，且不能简单删掉。**
   - 断言在 [deploy-web.mjs](file:///d:/desk/洛克工具箱/scripts/deploy-web.mjs#L67-L70)，失败在 [deploy-web.mjs](file:///d:/desk/洛克工具箱/scripts/deploy-web.mjs#L139-L142)。

## 4. 冲突提醒：必须改“正式 bundle 不含『收集计划』”这条断言

### 4.1 冲突事实

- 脚本用四个汉字做代理断言：`text.includes('收集计划')`，`main` 要求为 `false`，`test` 要求为 `true`（[deploy-web.mjs](file:///d:/desk/洛克工具箱/scripts/deploy-web.mjs#L67-L70)）。
- 计划中心进正式后，bundle 一定含这四个字（[GroupPlanHub.tsx](file:///d:/desk/洛克工具箱/src/ui/plan/GroupPlanHub.tsx#L331) 的“返回收集计划”、[changelog.json](file:///d:/desk/洛克工具箱/src/data/changelog.json#L5) 的标题）。
- 因此**不改这条断言，正式部署 100% 被脚本拦下**（[deploy-web.mjs](file:///d:/desk/洛克工具箱/scripts/deploy-web.mjs#L139-L142)）。

### 4.2 不能简单删掉的理由

这条断言是 2026-11-10 正式站被误顶事故后的机械拦截，价值不在“收集计划”四个字，而在“**任何未验收批次都不许进正式**”。简单删除会同时失去这个保护；靠改名/改文案绕开更糟——断言会变成永远通过的空检查，属于**假绿**。

### 4.3 建议的替换方式（按推荐度）

**方案 A（推荐）：把“文案代理”换成“功能标记 + 显式放行清单”**

1. 新建一个构建期常量模块（例如 `src/build/shippedFeatures.ts`），导出一个稳定标记串，例如：
   - `FEATURE_PLAN_CENTER = 'feature:plan-center'`
   - 需要拦截的其他内测功能各自一个标记。
2. `deploy-web.mjs` 改为：
   - `main`：断言 `text.includes('feature:plan-center')` **为真**（正向）；同时断言未放行的内测标记**为假**（反向）。
   - `test`：保持正向断言。
3. 放行一个功能 = 在同一个提交里把它从“未放行清单”移到“已放行清单”，评审时能一眼看到。
4. 同时保留 `--expect-hash` 与正式清单断言。

**方案 B（次选）：保留文案断言，但改成“按功能分子串”**

- 把“收集计划”替换成更唯一的计划中心标记（例如 `group-plan-hub` 或 `plan-hub-tab-mine`），避免更新说明 / 教程文案误触发。
- 缺点仍然是字符串代理，代码结构变了就可能失配。

**方案 C（不推荐）：直接删除该条断言**

- 只在同时补上方案 A 的正向断言时才可接受；否则等于拆掉唯一机械门禁。

### 4.4 改断言带来的风险

| 风险 | 说明 |
| --- | --- |
| 假绿 | 只改文案或只删字符串，断言仍在但不再代表“功能是否进正式” |
| 误拦 | 用宽泛中文字符串（如“收集计划”）会因 changelog / 教程 / 提示语而误判 |
| 漏拦其他内测功能 | 只删这一条，未来别的内测批次没有对应反向断言 |
| 文档失同步 | `docs/发版与更新规范.md` §4.2 与 `AGENTS.md` 都明确写了这条断言，必须同批修改，否则下次发版又会按旧文档操作 |
