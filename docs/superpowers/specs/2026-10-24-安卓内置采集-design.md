# 安卓内置采集设计

用户已选择源码初审推荐路线并授权实施：将本机采集集成到洛克工具箱，不依赖作者上传服务。此为新增原生子系统。沿用原生采集 → PCAP → 现有解析导入，不引入第二套领域规则。

## 用户路径

「我的 → 游戏数据」在新 APK 中显示本机采集卡。用户开始采集，系统授权 VPN 后打开游戏，重新登录并查看精灵仓库／背包／蛋仓，再回工具箱停止保存。保存完成后明确点「解析并导入」，沿用已有导入反馈与私有同步；不自动发布小组。原始文件保留，可重试导入、导出和确认删除。

网页及旧 APK 继续提供外部采集文件导入。Android 6/7 可继续查看数据与导入文件，采集要求 Android 8+。保留包名及原有数据；版本升为 1.2.0 / versionCode 11。发布 APK 需核对与旧安装包签名兼容，不能以卸载丢数据作为更新路径。

## 原生边界

从用户提供的 1.2.6 源码引入 zdtun、JNI 隧道、TCP/8195 过滤及 PCAP 写入；记录来源、修改、许可证及对应源码。zdtun 保持独立动态库。Android VpnService 只接管 `com.tencent.nrc`，用户明确授权后启动前台服务。JNI 不在界面线程运行，写文件使用有界队列。启动、取消授权、失败、撤销 VPN、重复停止与后台恢复均有可理解状态。

不带入作者云端、凭据、强制更新、商人、会员或旧解析器模块。只展示实际包数与字节数，不承诺自动完整性判断。仅一个 VPN 可用，与 VPN 加速器冲突须说明。

原始 PCAP 上限 128MiB，正常停止必须排空队列并关闭文件后才允许导入。文件创建时写 incomplete 标记，成功关闭后才移除；队列丢包、空间不足、达到上限及进程中断保留标记，不把残缺抓包自动当作成功。停止不会自动导入或上传。最多保留 10 个文件，达到上限要求用户删除或导出，不自动删除未处理数据。

## 数据桥与界面

新增版本化异步 RocoCapture 桥：getState、startCapture、stopCapture、openGame、importCapture、shareCapture、deleteCapture，均返回 Promise。使用 AndroidX WebMessageListener 的准确来源白名单，并逐条校验 sourceOrigin 和 isMainFrame；不把采集控制器注入 addJavascriptInterface。启动文档脚本提供请求 ID、超时和错误回传。WebView 不支持消息监听与文档启动脚本时不提供采集桥，仍可手动导入，需更新系统 WebView 后使用采集。原生状态轮询仅在卡片挂载且页面可见时运行。文件仅通过枚举出的固定 ID 访问，不接受外部路径。

原生文件导入复用 roco-share 事件。新增随机令牌虚拟 HTTPS 地址，WebView 用 FileInputStream 读取本机文件，禁止 Base64 和原生整文件 byte[]；URL 不走互联网／SW。地址只在应用内部创建，旧外部分享链路保持兼容。

PCAP 解码迁至 Worker，避免 UI 假死；字节通过 transferable 移交，解析结束或失败后 terminate。无 Worker 的单测环境可调用原解码函数。内置文件超过 128MiB 时明确拒绝；保留原文件以便恢复，不能通过截断包记录凑大小。网页现有备份及 JSON 导入路径保持原样。

## 验证与交付

TDD 覆盖：文件 ID 与生命周期／中断保留、重复启动停止、错误恢复、桥不可用与旧 Android、前端开始停止与文件操作、解析 Worker 成功失败释放；实际 Chromium 导入合成 PCAP 验证 Worker 输出沿用 parseBackup 与保存流程。Android assembleDebug、testDebugUnitTest、lintDebug；原生三 ABI 构建；Web 单测／类型检查／构建／Playwright。

最终交付可安装 APK、源代码提交、测试证据与真机验收步骤。真机游戏采集与部分 OEM 后台限制需要实际设备，未经验证不能宣称通过。当前授权为实施接入，产品是否上线可在有可安装产物和验证记录后决定；未经请求不操作用户手机、不启动游戏采集。
