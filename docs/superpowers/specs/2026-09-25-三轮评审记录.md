# 洛克工具箱 三轮产品评审记录

**评审对象**：[2026-09-25-洛克工具箱-design.md](2026-09-25-洛克工具箱-design.md)
**日期**：2026-09-25

---

## 第一轮：产品策划评审

**评审人画像**：资深产品策划，12 年工具类产品经验，做过 3 款百万级用户效率工具。

### 发现

| # | 问题 | 级别 | 处置 |
|---|---|---|---|
| P1 | 主流程没有被表达出来。文档写的是"有哪几个页面"，用户要的是"我按什么顺序做事"：导入 → 看缺口 → 抓/孵 → 回填 → 再看缺口。缺一条闭环节奏。 | 高 | 采纳，补主流程图 |
| P2 | 42 个目标的说法会把用户吓退。既然性格可以靠学院小窝自由指定，就不该让用户一上来面对 42 格。核心指标应该是「14 个蛋组的种公网络通没通」，性格是执行细节。 | 高 | 采纳，主视图只留 14 格，42 格降级为明细 |
| P3 | 缺少进度正反馈。用户从 10/42 到 12/42 需要被明确奖励，否则做几天就弃坑。 | 中 | 采纳，加进度条与"本次新增覆盖"提示 |
| P4 | 没有回答"孵失败怎么办"。非大块头、非满分后代在用户眼里是废品，会挫伤积极性。需要明确"失败产物仍然入库并参与后续计算"。 | 中 | 采纳，配种建议里固定说明保留价值 |
| P5 | 缺少目标可裁剪。不是每个玩家都要 14 组全通，有人只做自己常用的 5 组。 | 中 | 采纳，目标蛋组可勾选 |
| P6 | 术语门槛。"大婉满分""满分贝""种公"是玩家黑话，新用户看不懂，需要在界面里带解释。 | 中 | 采纳，加术语提示层 |
| P7 | 建议缺少"为什么是它"。只给结论不给依据，用户不敢信。 | 高 | 采纳，每条建议显示评分依据（补几个缺口、是否已有母本） |
| P8 | 缺少"带走能力"。玩家抓精灵时人在游戏里，需要把清单复制/截图带走，而不是来回切浏览器。 | 中 | 采纳，建议可一键复制为文本 |

**产品结论**：定位成立，且切中真实痛点（第 8 条"带走能力"是加分项，市面上确实没人做）。要求把"下一步"页作为默认首页，建议数量控制在 3 条以内、可展开。

## 第二轮：技术评审

**评审人画像**：前端技术负责人，负责过移动端 Web 与性能优化。

### 发现

| # | 问题 | 级别 | 处置 |
|---|---|---|---|
| T1 | **局域网 HTTP 下无法真正安装 PWA**。Chrome 只在 secure context（HTTPS 或 localhost）注册 Service Worker，手机访问 `http://192.168.x.x` 只能"添加到主屏幕"当快捷方式，不能离线打开。这是设计文档里一句"PWA 可离线"掩盖不了的事实。 | 高 | 采纳，按 HTTP / HTTPS 两套说明，并提供自签 HTTPS 方案 |
| T2 | 抓包 JSON 单份约 4~7 MB，四份 20 MB+。主线程 `JSON.parse` + 遍历会明显卡顿。 | 高 | 采纳，放 Web Worker 解析 |
| T3 | 存储要裁剪。`rawProtocol` 是原始抓包（单份数百 KB 到数 MB 的 base64），对规划毫无用处，不能进 IndexedDB。 | 高 | 采纳，导入时只落必要字段 |
| T4 | 标签筛选若每次全表 filter，几千只精灵会掉帧。 | 中 | 采纳，预建 `标签 → id 集合` 索引，筛选做集合交 |
| T5 | 覆盖度计算依赖图鉴版本；上游更新后必须重算派生数据。 | 中 | 采纳，快照带图鉴版本号，版本变化时重算 |
| T6 | 导入的原子性。解析中途失败不能留下半份数据。 | 中 | 采纳，先解析校验、再单事务写入 |
| T7 | 移动端长列表（数千条）需要虚拟滚动。 | 中 | 采纳 |
| T8 | 手机浏览器存储可能被清理（iOS Safari 长期不访问会清）。 | 高 | 采纳，定期导出提醒 + 一键导出备份 |
| T9 | 判定逻辑应该与界面解耦，放纯函数目录，Node 侧也能跑。 | 中 | 采纳，`src/domain` 零依赖 |

**技术结论**：方案可行，无需后端。要求把"PWA 离线"的表述改准确，并把导入路径做成 Worker + 事务。

## 第三轮：真实用户评审

**评审人画像**：《洛克王国：世界》玩家，四账号并行，正在搭 14 蛋组种公网络，每天玩 1~2 小时。

### 体验反馈

| # | 反馈 | 级别 | 处置 |
|---|---|---|---|
| U1 | "我打开就想知道今天抓哪只，别让我翻页面。" | 高 | 采纳，默认进「下一步」 |
| U2 | "你告诉我去抓雪豆丁，可它在地图上哪儿？" → 需要显示野外分布区域。 | 高 | 采纳，数据里已有 `ecology.areas`，直接展示 |
| U3 | "建议一次给太多我就不看了。" | 高 | 采纳，默认 Top 3 |
| U4 | "我能打勾吗？抓到了想划掉。" | 中 | 采纳，待办清单 + 已抓标记 |
| U5 | "我抓到一只新的，难道要重新导入一次 7MB 的文件？" | 高 | 采纳，支持手动添加/编辑单只 |
| U6 | "自动判的大块头万一判错了，我要能改。" | 中 | 采纳，判定结果可手动覆盖 |
| U7 | "出新的精灵了，我怎么知道要不要抓？" | 高 | 采纳，刷新上游后给"新精灵 → 只需抓 1 只母本"清单 |
| U8 | "游戏里切出去看网页很麻烦，最好能离线。" | 高 | 与 T1 合并处理：给出 HTTPS 方案与导出备份 |
| U9 | "14 格点亮那种感觉，看着想冲。" | 中 | 采纳，进度可视化 |
| U10 | "异色、首领形态会不会被当成能用的种公？" | 中 | 采纳，特殊个体在列表与建议中显著标注 |
| U11 | "我想把清单发给我朋友一起抓。" | 低 | 采纳，复制文本即可分享 |

**用户结论**："这个就是我一直想要的东西——不是又一个图鉴，是告诉我怎么补齐。种公配齐后新精灵只要一只母本，这个逻辑你必须在首页讲清楚。"
