# 小组收集二期：母本组与种公组

日期：2026-10-25。状态：**已评审并修订（2026-10-25 夜），进入实施**。

用户已明确：把收集页的「求蛋」迁到小组；无需强行让同一小组同时收集母本和种公，优先保证流程顺畅和实现复杂度可控。本文推荐一个小组只收集一种目标，共用协作流程，分别计算领域目标。本文取代 2026-10-24 母本共享二期讨论稿的后续实施入口；旧稿作为需求历史保留。

## 0. 评审修订与实施决策（2026-10-25 夜）

产品、工程、领域三方评审结论：方向成立，但原文在「个人模式归属」「旧入口落点」「原子裁决落点」「迁移可重复」「口径可比性」五处会直接造成返工或错判。以下修订优先于后文，后文与之冲突时以本节为准。

### 0.1 产品决策

1. **个人求蛋是小组页的默认主态，不再要求登录**。未登录、无小组时先看到「个人求蛋」，可切换「求母本 / 求种公」；组选择器固定带一项「个人求蛋」用于随时切回。发布、邀请码、成员管理才要求登录。看板与收集页的「去小组找」在没有兼容组时落到个人求蛋，不落到登录墙。
2. **旧入口保留可升级语义**：`roco.lastTab=swap` + `swapView=eggs` 升级后落到「小组 · 个人求种公」，不落到已删除的求蛋子页；`swapView=sharing` 仍落到小组。收集页保留「覆盖矩阵」，不再保留「换蛋清单」子视图。
3. **视图压缩**：主分段只留「我缺的 / 共同寻找」。原「我能补谁」改为「全部资源」内按成员筛选；「全部资源」用文字入口，不再占一个 28px 分段（375px 下四段会挤）。
4. **共同寻找的范围来自需求，不是全图鉴**：只对「我的缺口 ∪ 组内成员关注的目标」生成，默认只看「已确认无来源 + 可孵」，其余折叠。避免 199 条永久待确认任务。
5. **创建流程不加重**：创建只选「母本收集 / 种公收集」+ 组名 + 昵称。种公目标默认从个人配置导入并预览确认，组页常显「本组目标待确认」，不把目标编辑器塞进创建第一步。母本首版仍用固定口径，自选口径在步骤 6 提供。
6. **两种组互不覆盖本机记忆**：`lastGroupId` 按类型分别保存；详情缓存按「身份 + 组 ID」保存，不再只留一个组。

### 0.2 工程决策

1. **不动旧表结构，新增配置表**：`collection_group_configs(group_id, group_type, target_revision, resource_epoch, target_json, updated_at)`。旧组没有行时按母本组 + 固定口径读取；创建时写入。类型不可修改（无更新接口）。这样避免 SQLite `ADD COLUMN` 无法 `IF NOT EXISTS` 导致的迁移不可重复。
2. **旧接口是母本组的窄门**：`/api/mother-groups` 只列出、只读写 `type='mother'` 的组；旧客户端看不到也写不进种公组。旧发布体必须仍是母本摘要；种公目标或摘要写回一律 400/409。
3. **目标修订与原子性**：组级 `target_revision` 由组长接口递增；发布体带 `baseTargetRevision`，不匹配返回 `TARGET_CHANGED`。发布、撤回、退出同批递增组级 `resource_epoch`；认领任务以 `(group_id, target_revision, target_key, round)` 唯一，认领用条件插入，冲突返回当前负责人。
4. **缓存信封**：缓存带 `schemaVersion + groupType + targetRevision + catalogVersion`，与当前不一致即丢弃；离线只读，认领/转交/发布必须联网确认。
5. **种公摘要独立限额**：不复用母本「50 账号 × 1024 ID / 128KiB」；槽位按 `groupId + natureId + grade` 去重，单账号上限 512 格，请求体 256KiB，超限显式报错，不截断。

### 0.3 领域修正（必须遵守）

1. **母本单位** = `eggGameId`；**种公单位** = 个体自身 `eggGroups × nature × grade`，不得用 `eggGameId` 归并（蛋物种与血脉的蛋组可能不同）。双蛋组覆盖两格的前提是**同性格、同档位、两组都选了该性格**。
2. **谓词单源**：母本用 `isQualifiedMother(criteria)`；种公用 `classifyGrade(pet, mode)` + `cellStateFor`。`covered` 必须是「公 + 目标性格 + 档位 + 蛋组」；`breedable` 另需母方物种 `maleCapable` 且**同一 uid 账号**内有公。
3. **同账号按 `accountKey`（uid）判定**，不能用显示名 `account`；可迭代不得跨账号取并集。
4. **可比性四元组** = `groupType + criteriaId（母本 criteria 哈希 / 种公 mode + slotKeySet 哈希）+ targetRevision + catalogVersion`，任一不等即「未知」，不得当作缺或已收齐。
5. **可迭代 ≠ 已收齐**：它只表示走学院小窝 100% 遗传的路径，不保证出公、不代表现货；每账号 1 个绿窝、12h CD。
6. **推荐清单不是拥有证明**：`rankSwapWishes` 排除了已覆盖/可迭代个体，空清单不能推出已收齐；覆盖与可迭代只能来自账号快照。
7. **只有目标性格母本不算完成**：还要求母方物种能出公（`maleCapable`）；只有公本、拿到未孵蛋、认领、复制文本同样不算。
8. **母本目标带模式**：`voices ⊆ motherVoicesForMode(mode)`；`+100` 是精确 100，与种公双牌 `≥96` 不是一回事。

### 0.4 本次实施边界

本轮已交付步骤 1—7：两类小组、求蛋迁入小组、母本自选口径、共同寻找与认领闭环均已实现。
认领采用「`(组 + 目标修订 + 目标键 + 轮次)` 唯一 + 版本 CAS」的服务器裁决；全员未确认时
只展示待确认、不开放认领；发布补齐后自动结束任务，改目标后旧任务只作历史。
旧组、旧邀请码、旧成员与旧摘要不要求重新发布。

## 1. 推荐取舍

| 方案                         | 使用与实现代价                                                                     | 结论                             |
| ---------------------------- | ---------------------------------------------------------------------------------- | -------------------------------- |
| 创建时选择母本组或种公组     | 每组一种口径和任务，复用已有成员、发布、刷新及资源页面；种公只增加自己的目标与摘要 | 推荐                             |
| 同组同时收两种，增加类型筛选 | 成员要理解两套目标、发布范围和更新状态，认领还要区分两类，迁移复杂                 | 本轮不做                         |
| 仅把现有求蛋组件挪到小组     | 能减少入口分散，但仍不知道谁有、全组缺什么，不能完成协作闭环                       | 只能作为迁移步骤，不能算二期完成 |

统一的是「发现缺口 → 找组内来源 → 没有来源则认领寻找/孵育 → 获得后导入并发布」，不是把两种资源压成同一种完成判据。

## 2. 页面分工

### 收集：查看个人进度，安排自己孵

- 母本保留未收集、已收集；缺口卡可点「去小组找」。
- 种公保留覆盖矩阵、自己孵；不再保留独立求蛋子页，缺口卡和工具区提供「去小组求蛋」。
- 精灵库仍只展示实际个体。看板上的求蛋建议同样直达小组，不再绕回收集。
- 跳转携带母本血脉或种公目标槽位，以及原有目标模式；不通过建议物种的临时推荐 ID 标记需求。

### 小组：集中处理协作收集

顶部为当前小组选择器、组类型与目标摘要；不再增加「母本/种公」组内切换。

同一种结构适用于两类组：

| 视图     | 回答的问题                           | 主要内容                                                       |
| -------- | ------------------------------------ | -------------------------------------------------------------- |
| 我缺的   | 我还缺什么，谁有相关资源             | 组内有来源优先；展示成员、来源游戏账号、数据更新时间及求蛋候选 |
| 我能补谁 | 我现有的资源能帮助哪些人             | 只根据对方可比较的已发布摘要判断，不推断其私人账号             |
| 共同寻找 | 当前共享范围内还没收集到什么，谁去找 | 已确认缺口、待确认、负责人；可筛选未认领/我认领                |

全量资源目录作为次级「全部资源」入口。我的共享资源状态常显，选号、预览、发布及成员管理按需展开。新建、加入保持次级位置，不挤占日常任务。

「我缺的」的种公卡展开后给现有算法生成的建议物种和可替代物种；它们是同一缺口的解决办法，不是多条独立收集任务。复制求蛋、批量选择、搜索、性格/蛋组筛选、绿窝/普通窝文案和复制预览能力继续保留。

## 3. 创建与加入：一个组只选一种目标

- 创建第一步选「母本收集」或「种公收集」，随后确认本组目标。组名不承担类型识别，界面始终显示类型标签。
- 旧组全部迁为母本组，保留成员、邀请码、选号、摘要与原达标口径，不要求重新建组。
- 二期不支持把已有母本组直接转换为种公组；需要另一种目标就创建另一个组，同一成员可以加入不同类型的小组。
- 邀请码仍唯一定位小组。加入确认展示组名、类型和目标，不让成员进组后才发现目标不符。
- 不做跨组资源自动发布，也不合并不同组的共同缺口或认领记录。

### 无小组、未登录也能求母本和种公

小组页面提供「个人求蛋」模式，其中可明确切换「求母本／求种公」。两种都不要求登录或加入小组，只依赖本机已导入数据及个人收集目标；沿用个人收集页的目标与选号，不额外维护一套配置。求种公保留原有推荐、筛选、批量选择及复制，求母本新增对应血脉、体型和声音条件的缺口清单及复制。两个类型分别保留搜索和勾选，不互相串用。

从母本或种公缺口直达时，携带明确类型与目标，优先进入上次使用且目标兼容的对应类型小组；没有兼容组时进入对应的个人求蛋清单，并提供加入/创建该类型小组的次级入口。直接打开个人模式时恢复上次选择的类型。即使已经加入小组，也可主动切回个人模式，不把本机求蛋强制绑定到某个组。

个人清单不是一个假小组：无组内拥有者、无共同缺口、无线上认领，不自动上传本机需求。正常点主导航「小组」时仍恢复之前选择的个人模式或小组；进入具体小组后只显示本组类型，不显示个人模式的母本/种公切换。

从母本缺口进入且没有兼容母本组时，使用相同的个人模式展示母本缺口和复制文案；不显示种公推荐。个人模式分别区分没导数据、没设目标、已收齐和筛选无结果。

## 4. 两类目标的边界

| 内容           | 母本组                                       | 种公组                                                          |
| -------------- | -------------------------------------------- | --------------------------------------------------------------- |
| 收集单位       | 蛋血脉 `eggGameId`                           | 蛋组 × 目标性格 × 档位                                          |
| 达标规则       | 同一只母精灵同时满足本组体型和声音要求       | 真实公精灵属于该蛋组、性格吻合、档位达标；满分/双牌采用本组模式 |
| 一只个体的贡献 | 进化和形态归对应蛋血脉，避免重复计数         | 双蛋组可覆盖两个目标槽位，不要求特定推荐物种                    |
| 缺口建议       | 寻找对应血脉及目标品质的母本资源             | 复用现有换蛋排序和性格可获得性规则；任何合法替代物种均可补格    |
| 不算收集完成   | 只有公本、拿到一颗未孵蛋、认领、复制求蛋文本 | 只有目标性格母本、可迭代、已预约、拿到蛋但尚未导入合格种公      |

组长维护本组目标，与个人看板设置分开。母本组首批沿用「母·大块头·+100dB」；种公组创建时明确选择模式、蛋组、各组目标性格和档位，可从个人配置导入后预览确认，但不暗中随个人筛选变化。

在小组页明确写「按本组目标、我的共享账号统计」，个人收集页写「按个人目标、当前选号统计」。从个人缺口跳转时，先匹配原模式和目标；若当前组不包含或不兼容该目标，保留个人求蛋清单并提示选择兼容组，不擅自修改个人或小组目标。

二期后半批开放母本自选体型/声音；种公组使用现有模式和档位体系，不扩展繁育规则。口径修改由组长确认，递增本组目标修订；成员按新目标重新预览并发布。旧摘要不能反推出新目标，缺证据时标「需更新」。这延续旧稿的同组同口径、变更后重发路线，避免一次发布完整资源池。

## 5. 发布与供给：有资源不等于有现货蛋

复用现有流程：明确选择游戏账号 → 预览资源覆盖的增减 → 手动发布。导入和私有同步不会自动公开发布；导入后仅提示「本机有更新，可更新小组资源」。

- 母本摘要继续只含达标血脉 ID 和来源账号。
- 种公摘要按游戏账号分别保存已覆盖槽位，以及必要的来源物种/性格/档位；另保存经领域算法确认的「本账号可迭代」证据，和已拥有分开。只公开本组所需摘要，不传完整背包或原始采集文件。
- 种公摘要从所选账号的原始快照生成，不能只从推荐清单生成。推荐清单排除了可迭代等情况，不能证明拥有或缺少。
- 必须以单只真实个体判定达标，不能把同账号三只精灵的性别、性格、体型拼成一只；可孵判定必须在同一个游戏账号内成立，不跨账号、跨成员拼父母。
- 多个游戏账号按成员取并集用于已覆盖统计，来源账号仍可查看。同一 UID 在同组只能归一个成员，继续保护当前约束。
- 仅有种公或母本时写「某成员有相关种公/母本」，不直接标「可提供蛋」。只有同账号亲本和对应产蛋条件经现有领域规则验证时才显示具体可孵建议；不推断有现货、愿意赠送或一定孵出目标性别。
- 不增加现货库存、聊天、订单或交易完成按钮。复制文本仍是用户主动操作，不代发消息。

本机缺少已发布账号时继续保留云端摘要，并按现有保护阻止静默缩小共享范围。发布、停止共享、恢复数据的提示都要明确当前组与统计范围。

自己尚未发布但本机有数据时，「我缺的」可先按本组目标和明确选号提供本机预览，并标注「尚未发布，组员还看不到」；他人视角仍为未知。已有发布与本机预览不同时显示差异，不能把预览当成已经共享，也不把未知显示成已收齐。

## 6. 共同寻找与认领

母本血脉或种公目标槽位在所有可比较的已发布资源中均无真实达标拥有者，且全体成员均已发布、版本兼容时，才能标「已确认未收集」。有任何未发布、停止共享或版本不兼容的成员时标「待确认」，不把未知写成全组没有。

- 种公目标尚无人拥有但某个账号可迭代时，仍是未收集，优先展示「组内可孵」和对应账号。可以认领去孵成，不强推对外求蛋；可迭代始终不计入已收齐。
- 已确认缺口一项一位负责人；待确认项可浏览，首版不进入正式认领队列。
- 成员可以认领、释放自己的任务；组长可以释放或转交给现有成员。负责人退出后释放，不因短暂离线或固定时限自动释放。
- 发布达标资源后，系统复核并结束对应共同寻找任务。其他成员个人仍缺时，转为「组内有来源」，不会把全组每个人都写成已收齐。
- 后来撤回资源，若仍有未知成员则待确认；再次全员确认缺少则创建新的未认领轮次，最小历史可查看。
- 种公按单槽位认领，不按推荐物种认领。一只双蛋组种公对应两个槽位；批量认领两个槽位必须原子裁决并明确展示结果，不能让两人对重叠格子都认领成功。
- 改口径后旧认领只作历史，不自动算作新目标任务。图鉴升级时暂停无法比较的判定，核实缺口后再恢复寻找意向，不复制出重复任务。

任务标识为「组 ID + 目标修订 + 标准目标键 + 重开轮次」。操作由服务器校验成员资格、当前目标、摘要版本和任务版本；竞争失败刷新后展示当前负责人，不用本地勾选模拟多人认领。

## 7. 实现结构与兼容

共用小组外壳、成员管理、发布交互、缺口列表、复制和认领逻辑；母本与种公分别实现目标生成、资源摘要和覆盖匹配，不复制两套小组系统，也不引入万能资源市场模型。

- 小组配置采用母本/种公的可区分联合类型，目标修订由服务端维护。组类型创建后不可修改。
- 母本复用 `isQualifiedMother`、`buildMotherResource`、`buildMotherCoverage`；种公复用 `buildCoverageSlots`、`computeStudCoverage`、`cellStateFor`、`rankSwapWishes`。建议物种过滤不能套到真实种公的已覆盖判定上。
- 不大规模改名已有 `mother_groups` 表和母本服务文件；增量增加组类型、目标配置、种公摘要与寻找任务存储。身份、邀请码和现有成员机制继续复用。
- 新统一接口使用 `/api/collection-groups`，与旧母本接口共用成员和身份服务。旧 `/api/mother-groups` 只读写母本组；不能让旧客户端把种公摘要当母本写回。自选口径启用后，旧固定口径写入也必须拒绝，不能静默覆盖新目标。
- 母本旧数据通过默认类型和默认目标读适配；不从旧母本 ID 摘要推算种公资源。种公组必须明确发布自己的新摘要。
- 组目标版本、成员资源版本与任务状态之间要有原子条件更新。认领与发布/撤回/退出并发时，不允许对已补齐、已失效目标继续分派任务。
- 小组缓存按工具箱身份和组 ID 隔离，增加摘要类型/版本校验；离线可看旧内容和复制，但认领、转交、发布需联网后由服务器确认，不能离线显示操作成功。
- 搜索、复制勾选和选号草稿按「身份 + 组 ID（或个人模式）+ 类型 + 目标修订」隔离。旧求蛋勾选只迁到个人种公清单，不直接带进某个小组；目标变化后失效候选不能继续进入复制或发布。
- 首版延续现有发布体积和账号数量上限，不通过截断摘要来凑限制。种公摘要按目标和来源去重；压力验证超限时给出明确错误，再评估存储与传输调整。

## 9. 必须覆盖的验收场景

1. 旧母本组直接打开，成员、邀请码、共享账号及统计不变；未重新发布不丢资源。
2. 同一人加入一个母本组和一个种公组，切组不串目标、选号草稿、筛选、勾选和缓存。
3. 无登录、完全无组时，个人求蛋可切换母本/种公，各自生成缺口、筛选和复制；只有母本组时仍可个人求种公，反之亦然。两类搜索与勾选不串用，不强制登录、建组或进入不兼容组。
4. 从看板、母本缺口、种公矩阵和旧 `lastTab/swapView` 进入，落点和目标模式正确。
5. 满分与双牌、四档、组内外目标差异明确；个人筛选不能悄悄改变小组目标或已发布内容。
6. 母本进化/形态归血脉、异色参与；一只达标种公覆盖双蛋组，真实拥有不受推荐物种白名单限制。
7. 同一人跨账号不能凑出虚假可孵配对；一只母本不能算种公，推荐、可迭代、拿到蛋都不算完成。
8. 未发布、停止共享、图鉴/口径版本不一致时为待确认；空但完整发布的摘要和未发布必须区分。
9. 两人同时认领、批量认领重叠格、认领同时他人发布补齐、切目标同时发布，均有唯一且一致的服务器结果。
10. 导入后仅提示更新；手动发布后共同任务结束，但其他成员个人缺口仍存在。
11. 撤回、退出、注销、解散和图鉴升级正确处理任务及历史；离线或请求超时不假报认领/发布成功。
12. 发布预览、缺本地账号保护、覆盖确认、切组草稿提醒、15 秒刷新及身份隔离不退化。
13. 375/390/1280 宽度、键盘导航、搜索无结果、复制失败/取消、缓存读取失败都有真实验证记录。

本次只落盘方案，无产品代码改动或公告。实施前需把当前工作区的其他改动作为真实基线核实，不能将本方案的目录位置当作代码已经存在。
