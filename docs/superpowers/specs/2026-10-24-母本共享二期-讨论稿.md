# 母本共享二期讨论稿

状态：2026-10-24 用户认可核心方案，术语改为「组长」「未收集」。排期调整为先做全应用产品评审及结构改造，再实施本文二期功能；界面落点以整体改造方案为准。

## 目标与一期差异

仍以「人」汇总其明确共享的多个游戏账号；不同设备登录同一工具箱身份为同一成员。知道谁有达标母本，协作让每个人补齐母本收藏。

一期落盘方案第 3.3 节将「小组资源」定义为全量资源目录，明确排除认领；第 8 节只明确自选体型/声音口径，其他列为评估项。因此「小组共同缺口、对外寻找、认领分工」没有落实，也未正式排入二期。本稿将它列为二期首要交付。

## 建议分两批交付

### 2A：共同缺口与认领分工

继续使用当前固定口径，先让协作闭环可用。

- 「我缺的」继续回答自己缺什么、可以找谁；「我能补谁」继续回答自己能帮谁。
- 第三个「小组资源」默认展示「未收集」，只列当前没有已知拥有者的蛋血脉。此处「未收集」特指小组当前共享账号的共同缺口，与「我缺的」区分，不推断未共享的私人背包；全量资源目录保留为次级入口，成员详情保留来源账号。
- 列表分为「已确认组内无」和「待确认」：全体成员已发布且版本可比较、无人拥有，才能确认为共同缺口。存在未发布、停止共享、需更新的成员时显示具体人数，不声称全组都没有。待确认仍可浏览，但建议先不进入正式认领队列。
- 每条展示母本名、缺口状态、负责人、认领时间；支持搜索、未认领、我认领、全部筛选。
- 第一版一项只有一位负责人。成员可认领、放弃自己任务；组长可释放或转交给现有成员。并发认领由服务器裁决，后来者刷新后看到已有负责人。
- 不自动超时释放，不因负责人短暂离线丢任务；负责人退出/被移除后释放其未完成任务，组解散时删除组内任务。
- 认领只表示「我负责去找」。某成员导入并发布达标母本后，系统自动从未收集清单移走，资源目录出现持有者；其他成员自己的缺口仍保留，直到各自获得并发布。
- 补齐后保留最小历史记录。资源后来撤回且再次确认全组缺少时，新开未认领项；若撤回后成员状态未知，则回到待确认，不直接判定重新缺少。

示例：甲乙丙都确认缺布灵 → 甲认领寻找 → 甲获得并发布 → 小组有了布灵来源 → 乙丙继续在「我缺的」里找到甲 → 乙丙各自获得并发布后，个人缺口消失。

### 2B：用户自选母本口径

建议按小组设置一个共同收集目标，由组长选择，所有成员按同一条件查看；不隐式跟随全站或各自看板筛选。

- 复用 `MotherCriteria`：体型可选大块头、小不点或不限；声音复用 +100、-100、婉转声、粗嗓门或不限。需要支持多选时沿用现有语义；同一只母本须同时满足体型与声音条件。
- 异色与普通色都参与统计，进化形态仍归蛋血脉；多个号仍按人取并集。
- 老组默认保留一期「母·大块头·+100dB」，原摘要可继续比较。
- 更改口径要确认影响；新条件下成员重新计算、预览并发布。旧 ID 摘要不能反推出其他体型/声音资源，未更新前标「需更新」。
- 认领按小组、口径修订、蛋血脉隔离。切换口径不自动把旧认领算成新任务；提供历史查看，避免错误沿用。图鉴升级保留寻找意向，但重新核实当前缺口，数据未齐时标待确认。

备选方案是一次发布多个体型/声音档位的最小摘要，方便切换口径；它会扩大摘要、接口和迁移范围。本稿推荐先采用「同组同口径＋变更后重发」，减少二期初次改造范围。若频繁切换条件是主要使用方式，应在实施前改选分档摘要方案。

## 技术边界与实施顺序

1. 从现有覆盖结果派生共同缺口，明确已知空与未知；沿用小组刷新、搜索和统一控件。
2. 新增组内寻找任务存储，保存蛋血脉、口径修订、负责人、状态、时间、版本，不存精灵背包。资源持有事实仍由已发布摘要决定。
3. 认领/释放/转交使用认证接口，检查当前成员资格、口径、目标及缺口状态，用原子写入和版本冲突防止相互覆盖；客户端不自报成员身份。
4. 资源发布、停止共享、退出/移除、注销、解散、口径变化时重新核实任务状态。任务状态与摘要版本变化需要一致性保护，防止认领已补齐的条目。
5. 完成 2A 后，再加入组口径配置、兼容迁移和重发提示，交付 2B。
6. 验收包括三人协作、双设备同一人、并发认领、未知成员、版本变化、发布后自动补齐、撤回后待确认/重开、退出释放、多账号并集、异色及进化形态、手机布局。

## 暂列后续评估

- 组长转让、移除成员：有使用需要可插在 2A 后，不与口径重构捆绑。
- 导入后提示发布：可优先做提醒；自动公开更新应另行提供明确开关及预览策略。
- 每个小号独立全收集：会改变「按人汇总」目标，先保留当前模型，需要时作为独立模式设计。

## 已确认方向与重构时待细化事项

- 已认可：小组默认呈现未收集与认领，全量目录退到次级入口；整体导航落点在全应用改造中细化。
- 已认可：第一版一项一位负责人，待确认缺口暂不正式认领。
- 已认可：小组统一口径、变更后重发；若后续确认频繁切换，再评估分档摘要。
- 组长管理、导入后提醒是否需要提升到 2A。
