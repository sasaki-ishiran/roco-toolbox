# 原版采集器辅助上传设计（已否决）

日期：2026-10-24。状态：用户看过后明确表示不可接受。本稿仅保留为已否决方案的调查记录，产品尚未实施；不得按此稿继续实现。用户最新目标是找到工具箱内完成采集、导入并进入蛋神助手交易的其他可行路径。

## 目标与成功条件

用户已在工具箱成功采集；新增采集能力应保留在日常入口中，不能退回原版采集后分享文件到工具箱的旧路径。

目标流程为：工具箱开始采集 → 游戏查看数据 → 返回工具箱停止、保存并导入 → 用户点击一次「同步到蛋神助手」 → 前台自动打开已安装的真正原版 → 自动进入文件导入、选择本次文件、确认上传 → 识别原版的最终状态。日常不要求用户手动导出、寻找目录、选分享目标或重复采集。

这次“一次点击”限定为保存和本机导入完成后的同步动作。已有停止保存和本地解析步骤不计作已优化；后续可以单独增加「停止并导入」组合动作，但本次不将它作为同步接入的前置重构。

首次需要安装原版、开启系统辅助操作权限，部分系统可能要求手动允许受限设置。权限步骤由用户完成，产品不自动替用户点授权。执行中须解锁并保持前台，可随时取消或由用户接管。

## 路线选择

| 路线 | 可省掉的操作 | 调查结论 |
| --- | --- | --- |
| 系统 DocumentsProvider + 原版手动导入 | 不用先导出到公共目录、不用分享文件 | 官方平台机制支持；原版确实调用 ACTION_OPEN_DOCUMENT，适合作为稳定底座与人工兜底，但单独采用仍有多次点击，不是用户期望的主路径 |
| DocumentsProvider + 用户主动启动的前台辅助操作 | 在上一项基础上自动执行原版导航、选择本次文件、上传确认 | 推荐探索；原版网页按钮及状态可由无障碍语义识别，Android WebView/系统选择器端仍待真机验证 |
| 网页直接上传或让工具箱直连采集接口 | 理论上可完全留在工具箱 | 当前公开网页未找到抓包上传入口；公开 uploadFile 代码是头像等2MiB文件上传，不是采集入库。页面分块请求需要授权，未继续访问。直连接口对工具箱身份返回426，不纳入本路线 |

原版没有 ACTION_SEND / PCAP 文件接收入口，也没有现成的一键上传深链。仅发送一个 intent 或跳到原版首页不能完成交接。重打包原版、提取其应用凭据或伪造发布身份不在设计中。

## 组件与数据流

### 本次文件的系统文档入口

工具箱新增只读 DocumentsProvider，与现有 FileProvider 并存。后者用于用户主动分享，前者让原版的系统文件选择器直接读取工具箱保存的 PCAP。

只有用户本次选择同步且已完整保存的文件进入交接会话。文档根以「洛克工具箱 · 本次采集」命名，只列本次文件，带清晰采集时间和大小；不暴露整个应用目录，不提供写入、创建或删除能力。系统通过用户在文件选择器中的选择授予目标应用读取权限。仅允许原版采集器及系统选择器参与本次交接，不接受任意路径或URL。

开始时检查采集已停止、文件有效、没有 incomplete 标记、大小符合原版原包接口5MiB上限。本机128MiB能力保留；超限直接提示此路径不支持，不截断、不上传工具箱精简备份。锁定文件，取消、失败或任务结束时释放；正在读取的已打开只读句柄要允许完成，不能因为会话切换截断文件流。

### 前台辅助流程

用户点击同步后建立有时限的单次会话，界面提示将把该 PCAP 发给蛋神助手，并打开已安装的原版。用户同意本次发送是触发上传动作的前提，不因仅开启权限就在后台自动同步。

辅助服务以可访问性节点的文字、角色、上下文和文件标识驱动，依次执行：

1. 校验原版包名、已安装版本及签名，打开原版；不替换或修改原版安装包。
2. 进入「文件」，点击「导入 PCAP / PCAPNG」。
3. 在系统文件选择器中找到工具箱本次文档根，并选择本次唯一文件；不选“最近”列表里同名文件，不依据全屏固定坐标盲点。
4. 识别原版导入完成后弹出的「上传云端」及对应文件。若弹窗出现更新、报错、文件不一致、重复条目或无法唯一定位，则停止并交给用户；不连点重试。
5. 用户在工具箱发起的本次同步明确包含上传授权，匹配后可代点原版上传确认。若原版状态已上传、正在处理或待查询，应查询/等待，不重复发起上传。
6. 持续读取这一个文件卡片的状态。显示「服务器解析中」「等待云端结果」不报成功；只有原版卡片出现明确的已入库状态与有效 UID 才显示「原版显示已上传，UID…」。这属于从原版界面观察到的结果，不冒充工具箱独立查询了服务端；验收时还需用户在蛋神助手核对对应数据。

权限仅服务于用户主动发起的这一流程。仅在原版、系统 DocumentsUI 和工具箱范围执行操作，超出预期应用、锁屏、超时、用户取消或页面变化即停止。会话外不读页面、不点按钮，不收集截图、聊天、账号密码或全局输入，不通过无障碍扩大服务端访问。

Android选择器包名因厂商而异，不能仅硬编码一个包名；从系统解析出的选择器组件建立允许范围。若厂商选择器不能按语义可靠定位，就停留人工选本次文件，不能降级为不受控的坐标点击。

### 与现有网页桥接

新增的原生同步与取消动作复用现有逐请求检查 origin 和主框架的 WebMessage桥；不恢复 addJavascriptInterface，不把上传凭据、任意文件路径或页面自动操作能力暴露给网页。网页展示本机导入与外部同步两份独立结果。

旧APK不显示已可用的辅助上传按钮；原版未安装、系统未授权、版本不支持时展示明确的准备步骤。不开权限也可保留“打开原版并从工具箱文档入口选文件”的兜底，但不把这条多步路径描述成一键。

## 状态与错误处理

状态为：准备检查 → 打开原版 → 等待系统选择器 → 原版导入中 → 确认对应文件 → 上传处理中 → 原版显示已上传 / 需要人工处理 / 已取消。

整个会话设置超时与步骤次数上限，过期后清理可枚举的本次交接文档并保留本机原包。文件被原版导入后会另存新文件名：需要在受控探针/真机中验证能否通过导入基线、弹窗和大小/时间唯一关联；无法关联即阻止自动上传。工具箱不能假装自己已取得原版的私有 captureId。

上传时断网、原版退出、无障碍被关闭时，保持结果未知或待用户查询；不因看不到成功就自动再次上传。取消发生在原版已接受任务之后只能停止辅助操作，不能声称撤回了服务端上传。

## 已有证据与实际限制

- 原版 MainActivity.importCapture 使用 ACTION_OPEN_DOCUMENT、*/*、CATEGORY_OPENABLE；onActivityResult 收到URI后通过 ContentResolver.openInputStream 复制PCAP。这可对接标准 DocumentsProvider。
- 原版 app.js 在新文件导入完成后弹上传框；按钮文字是「上传云端」，文件卡片包含「服务器解析中」「已上传云端」「角色 UID …」。
- `node .superpowers/probe-original-ui.mjs`：使用原版未修改HTML/JS、模拟原生桥，以浏览器角色/按钮语义完成文件页→导入按钮→模拟导入→上传弹窗→上传按钮→模拟已入库卡片，调用顺序与文件名匹配，pageerror=[]。无真实文件读取、无网络上传。产物在 `.superpowers/artifacts/original-ui-probe/`，浏览器层结果不能替代 Android AccessibilityNodeInfo 验证。
- Android官方文档说明 DocumentsProvider 可让 ACTION_OPEN_DOCUMENT 客户端选择其他应用提供的文档；AccessibilityService 可通过 AccessibilityNodeInfo.performAction 代用户执行点击。它们只建立机制可行性，不证明此应用的真机兼容。
- 当前 `adb devices -l` 无设备，SDK无已安装模拟器。没有测试Android WebView节点、选择器导航、辅助权限、原版实际上传或OEM行为。不得称一键同步已完成。

## 实施与验收边界

先做本地原型验证文档提供器和原版可访问性树，再决定是否交付完整功能。第一阶段只自动选本次合成PCAP并停在原版上传确认前，不向服务端发送测试垃圾；验证节点唯一性、取消、换文件、拒绝权限与版本变化。该原型通过后，用用户选择的一份真实抓包验证端到端上传。

关键验收包括：系统选择器能读取同一份完整PCAP；不完整/超限文件不可进入交接；不会误选旧文件；原版界面可以稳定定位；每次只上传一次；关闭权限与锁屏立即停止；断网结果保持未知；原版真的入库且用户在蛋神助手看到对应UID与蛋数据；本机导入失败与外部同步失败分别反馈。对比用户旧流程记录首次准备成本和日常手动点击次数，只有日常不再处理文件且达到一次同步动作才算达成便捷目标。

本设计尚待用户审阅，未创建产品实现分支、未更改Android或网页产品代码、未提交新APK、未部署。
