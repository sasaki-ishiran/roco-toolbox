## 1. 背景与核心价值

《洛克王国：世界》里集齐精灵的主要手段是孵蛋，而不是满地图一只一只抓。当前市面上的小程序和攻略都只解决"查数据"，没解决真正的痛点：

> 我知道自己有什么，但不知道还要抓什么、怎么抓才最快补齐。

一只一只抓工作量极大；但游戏机制允许"配好种公网络 → 后续每出一只新精灵只需抓一只母本 → 批量产蛋"。本工具的主线价值就是把这条路铺出来：

1. 算清楚 14 个蛋组各自缺什么，把种公网络补齐。
2. 网络补齐后，新精灵只需要一只母本即可批量产出后续个体（含体型、声音、性格）。

**成功标准**：打开工具，30 秒内知道——我现在覆盖了多少、下一步该抓哪只（为什么是它）、该配哪一窝（期望产出是什么）。种子数据导入后无需手工录入即可开始。

## 2. 术语

| 术语           | 含义                                                                   |
| -------------- | ---------------------------------------------------------------------- |
| 蛋组           | 14 个可孵蛋组（未发现组不可孵蛋，不参与配种）                          |
| 种公           | 可用于配种的雄性个体，需满足「在目标蛋组内 + 大块头 + 目标声音」       |
| 大块头         | 蛋重 ≥ 该物种阈值；父母都是大块头时，后代基本也是大块头                |
| 婉转声         | 声音分贝为 +96 ~ +100                                                  |
| 满分（满分贝） | 声音分贝正好 100，婉转声中的最高档                                     |
| 满分大婉       | 大块头 + 婉转声 + 满分 的合称，是本工具的终极目标形态                  |
| 母本           | 任意雌性个体；后代物种与蛋组跟随母方。**每条可孵蛋进化链只需一只母本** |
| 母本集齐度     | 已有母本的进化链数 / 可孵蛋进化链总数（当前 190 / 255 = 74.5%）        |
| 覆盖           | 某个「蛋组 × 目标性格」目标上已有一只合格的种公                        |

## 3. 目标模型

- **目标 = 14 蛋组 × 每蛋组前 3 个目标性格 = 42 个目标**（性格名单由 PVP 推荐统计得出，见 `docs/domain/蛋组推荐性格.md`）。
- 合格种公需同时满足：在该蛋组内 + 大块头 + 满分 + 公 + 目标性格。
- **性格不是稀缺资源**：学院小窝是**性格供体窝**——把一只带目标性格的精灵放进学院小窝，**相邻窝孵出的蛋就 100% 遗传它的性格**（放种公或任意精灵都行，不限性别）。所以性格属于"最后一步贴标签"，可以按需批量产出。真正稀缺的是「蛋组 × 大块头 × 满分」的亲本资源。
- 因此覆盖度主视图按 **14 个蛋组**呈现"通/未通"，性格是次级维度（点开看明细）。

**关键约束**：

1. 图鉴与账号数据的连接键是 `speciesPetId` ↔ `game_id`。备份里的 `runtimePetId` 与 wiki 的 `key` 不是同一套编号，混用会错配（实测会把机械方方识别成菊花梨）。
2. **形态与进化阶段必须分开处理**：同一 `evolution_id` 的不同进化阶段是同一条链；不同形态 `evolution_id` 不同且种族值不同（如鸭吉吉六种样子），各自独立。
3. 游戏素材（立绘、图标、截图）不适用 CC BY-SA，本项目不使用。

## 5. 领域规则（已确认）

| 规则               | 内容                                                                                                                                                                                                             |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 后代物种 / 蛋组    | 跟随母方                                                                                                                                                                                                         |
| 声音遗传           | 子代 =（父 + 母）/ 2 **向零取整**；因此满分只能由双满分父母产出                                                                                                                                                  |
| 体型遗传           | 父母都是大块头 → 后代基本也是大块头（高概率，非 100%）                                                                                                                                                           |
| 性格遗传           | 绿窝（学院小窝）里那只精灵的性格 100% 遗传给配对蛋；**普通窝 60%**（见下一条"家园小窝与配对"）。两者都只影响性格，体型 / 声音 / 满分判定不受影响（2026-10-03 确认）                                              |
| 家园小窝与配对     | 家园共 **11 个窝：10 个普通小窝 + 1 个学院小窝**。两个窝的**曼哈顿距离 ≤ 2** 才能配对；可生蛋还需满足孵蛋规则（**父母同属一个蛋组**即可）。学院小窝只有一个                                                      |
| 学院小窝的特殊性   | **学院小窝里的那只精灵本身就是配对方**（不是给别的配对加属性）。所以要点目标性格，必须把「该蛋组 + 大块头 + 100dB + 目标性格」的那只精灵亲自放进学院小窝                                                         |
| 产蛋节奏           | 产蛋**串行**：一个公同一时刻最多和一只母本生蛋，生完后范围内其他可配对的母窝继续进入生蛋状态；一个母窝同一时刻只能有一颗蛋，**蛋被取走后**才会继续。默认一公一母配对，**多出来的窝默认摆母本**、排在公窝旁边排队 |
| 摆位建议的呈现口径 | 摆位过于复杂，**配窝建议里不展示距离**，只告诉用户"这只放学院小窝、那只放普通小窝"，其余由用户在游戏里自行摆放                                                                                                   |
| 大块头判定         | 蛋重 ≥ 该物种 `huge_min`；等于最大值时称为"满重"                                                                                                                                                                 |
| 满重判定           | 蛋重 = 该物种蛋重上限                                                                                                                                                                                            |

## 6. 数据模型

前端本地存储（IndexedDB）保存三类数据：

1. **图鉴缓存**：从 `data/pets.json`、`data/natures.json`、`data/pvp-natures.json` 导入，只读。
2. **账号快照**：**账号名单完全由用户导入的数据决定**（可多可少，不写死数量），每个账号一份，字段含账号名、导入时间、精灵列表。每只精灵保留：`game_id`（连接键）、名称、形态、性别、性格、声音分贝、体型奖牌、体重与百分位、异色标记、获取方式、账号与盒子位置。
3. **规划设置**：目标蛋组与目标性格（默认取每蛋组前 3）、每蛋组取几个性格、是否只看某些账号。

覆盖度、抓取建议、配种建议**全部实时从上述数据计算**，不落库缓存，避免数据与结论不一致。

## 7. 功能设计

### 7.1 我的精灵（标签筛选）

- 叠加式标签，点击即收窄结果；每个标签显示当前命中数量。
- 筛选维度：大块头 → 婉转声 → 满分（递进门槛）、公 / 母、异色、蛋组、性格、账号。
- 典型用法：只选「大块头」看体型库存；再点「婉转声」→ 大块头且 96dB 以上；再点「满分」→ 只剩 100dB 的大块头。
- 卡片展示：名称、形态、图鉴号、蛋组、性格、性别、分贝、体型、账号、异色。

### 7.2 覆盖度

- 主视图：14 个蛋组的通/未通状态，一格显示该组已有几个种公、缺几个目标。
- 明细视图：展开后是「蛋组 × 目标性格」矩阵，单元格区分四种状态：**已有种公** / **有母本可孵**（有满分大块头母本，孵一窝即可） / **有满分但缺种公**（配一窝即可） / **完全空白**（必须去抓）。
- 顶部显示总进度：已覆盖 N / 42。

四种状态的判定口径（按优先级从上到下匹配，全部只看"该蛋组内"的个体）：

| 状态           | 判定条件                                                 | 含义                                 |
| -------------- | -------------------------------------------------------- | ------------------------------------ |
| 已有种公       | 存在「大块头 + 满分 + 公 + 该目标性格」的个体            | 该目标已完成                         |
| 有母本可孵     | 存在「大块头 + 满分 + 母」的个体，且全局存在任意满分的公 | 用自己的完美公配这只母本，孵一窝即可 |
| 有满分但缺种公 | 存在满分个体，但不满足上面两条                           | 需要先解决体型，或先补齐该组的种公   |
| 完全空白       | 该蛋组没有任何满分个体                                   | 孵蛋永远孵不出满分，必须去抓         |

### 7.3 看板（核心页，默认首页）

产品形态是一个**看板**：用户看板了解状态 → 去游戏里抓 → 抓到后重新导入抓包数据 → 看板刷新进度。
因此看板必须让人"看一眼就够"，不需要带走任何东西。

**进度区（两个维度，分开呈现）**：

| 维度       | 计数单位               | 含义                        | 当前              |
| ---------- | ---------------------- | --------------------------- | ----------------- |
| 种公网络   | 蛋组（14）             | 决定"能产出什么品质"        | 待接入            |
| 母本集齐度 | 形态级进化链（255 条） | 决定"能产出哪些物种 / 形态" | 190 / 255 = 74.5% |

母本口径：**每条可孵蛋进化链只需要一只母本**。数据里的进化链本身就是形态级的——
同形态的不同进化阶段共享一条链（岚鸟"本来的样子"的阶级 1/2/3 是同一条），
不同形态各有一条独立链（岚鸟的本来 / 春天 / 夏天 / 秋天是 4 条；鸭吉吉 6 种样子是 6 条）。
因此"没有多形态的按链算、有多形态的按形态算"与链级统计天然一致：用某形态做母本，
孵出来必定是该形态，所以每种样子都要单独抓一只。
缺母本的链按蛋组分布：软体组 20、妖精组 17、魔力组 13、大地组 10、两栖组 8、巨灵组 7、
动物组 7、天空组 5、海洋组 5、昆虫组 4、植物组 4、拟人组 2、飞龙组 1、机械组 1。

**建议区（一次只推一条主目标 + 两条备选）**：这就是看板上"下一步做什么"的卡片数量，
共 3 条，避免信息过载；可以展开查看全部候选。

**去抓种公**：按"一只顶两个蛋组"的性价比排序，列出物种、基础形态、目标性格、能补哪些缺口、是否已有母本。排名依据：

1. 能一次补齐的**缺失**目标数（两个蛋组目标性格重合时最高，如巨灵组 × 拟人组）；
2. 该组的稀缺程度（无任何满分资源的蛋组优先，目前是大地组）；
3. 是否已有同物种的满分大块头母本（有则可直接孵，不必抓）。

**去孵**：给定当前资源，推荐下一窝配对，列出父本、母本、目标产出（物种 / 蛋组 / 体型 / 声音 / 性格）与这一窝补上的目标；并说明失败产物的保留价值（非大块头后代仍入库，不当作浪费）。

**去抓母本**：按形态级进化链列出母本清单，**先展示已收集、再展示未收集**，让用户看到逐步收集的
成就感；可分蛋组分批查看。

**策略顺序固定为：先补种公网络（决定批量产能），再补母本（决定覆盖面）。** 种公齐了之后，
补母本的成本会降到"抓一只 → 孵一批"。

**数据新鲜度**：看板顶部显示上次导入时间与图鉴版本；**超过一周未更新时，打开即提醒重新导入**。

### 7.4 数据

- **上传抓包 JSON**：在 Web Worker 中解析（单份 4~7 MB，避免卡顿）→ 只保留必要字段（丢弃 `rawProtocol`）→ 预览（新增多少只、覆盖度变化）→ 校验通过后单事务写入；重复上传不重复计数。
- **不提供手动录入与手动改判**：分贝值只能从抓包数据获得（游戏内只显示是否婉转声），因此抓包数据是唯一可信来源；导入失败时保留旧数据并明确报错。
- **静态看板导出（候选能力，待定）**：把看板导出成单个 HTML 文件，可离线打开也可发给别人；同时解决"局域网 HTTP 不能离线"与"分享"两件事。
- **刷新上游**：调用数据管线刷新图鉴、性格、PVP 推荐（联网），显示本次变更报告。
- **导入 / 导出**：本地规划数据可导出 JSON 备份。
- **数据版本与署名**：显示上游数据版本、抓取时间与 CC BY-SA 4.0 署名链接。

## 8. 技术方案

- **形态**：移动优先的 Web 应用 + PWA。
- **部署方式（不依赖电脑）**：构建产物是纯静态文件，部署到免费 HTTPS 静态托管（GitHub Pages / Cloudflare Pages / Vercel 任选）。手机浏览器打开一次 → 添加到主屏幕 → 之后**不需要电脑**、断网也能打开。账号数据与图鉴缓存都存在手机本地 IndexedDB，托管方只提供代码，接触不到个人数据。
- **上游刷新也不需要电脑**：wiki 的 API 允许跨域（已实测响应头 `Access-Control-Allow-Origin: *`），浏览器里可直接抓取并用内置的 Lua 解析器转换，因此"刷新图鉴 / 性格 / PVP 推荐"可以在手机上完成。`刷新数据.cmd` 与 `tools/data-pipeline` 保留作为开发与排障用的备用通道。
- **局域网访问仅用于开发调试**：此时 `http://192.168.x.x` 不是安全上下文，无法注册 Service Worker，只能当普通网页用（数据照常保存）。
- **技术栈**：Vite + React + TypeScript + Tailwind CSS。组件按需自建，暂不引入组件库。
- **存储**：IndexedDB（薄封装），除导入导出外不依赖后端。
- **性能**：导入解析放 Web Worker；标签筛选预建 `标签 → id 集合` 索引，筛选做集合交；长列表虚拟滚动。
- **数据安全**：支持一键导出备份，并在长期未导出时提醒（移动端浏览器可能清理站点存储）。
- **本地运行**：`npm run dev`，或 `npm run build && npm run preview`；手机通过局域网地址访问。
- **代码结构**（单包应用，不引入 monorepo，降低维护成本）：
  - `src/domain/`：纯函数领域引擎（覆盖度计算、抓取评分、配种建议、标签筛选），全部可单测，不依赖 React 与浏览器 API。
  - `src/ui/`：界面组件、标签筛选、矩阵视图。
  - `src/storage/`：IndexedDB 封装与文件导入导出。
  - `tools/data-pipeline/`：已有的上游刷新管线（已完成，含 33 个测试），保持独立。
- **复用**：图鉴与账号数据的连接、蛋组排名、目标性格表直接复用 `tools/data-pipeline` 的产物（`data/pets.json`、`data/pvp-natures.json`、`data/natures.json`）。

## 9. 非目标（本期不做）

- 截图 / OCR 识别录入。
- **云同步**、账号体系（数据仍只存在各自设备上）。
  多设备的需求改由「**合并导入**」满足（2026-10-03 落地）：两台设备各导出一次、互相合并导入一次，
  两边就有全部账号；本地独有的账号不会被清掉，同账号取导入时间较新的那份。
  收到的备份可以直接在微信/QQ 里「分享给洛克工具箱」导入。详见 [多设备数据合并](../plans/2026-10-03-多设备数据合并.md)。
- 孵化成功率的概率与期望轮数计算（只做定性建议）。
- 战斗、技能、培养等其他玩法模块。

## 10. 测试策略

- `packages/domain`：每个规则一条单测——覆盖度判定（含母本可孵、缺种公、空白三态）、标签叠加筛选、抓取评分排序、配种建议、声音均值向零取整、形态与进化阶段的区分。
- 导入解析：用真实抓包 JSON 的裁剪样本做测试数据，覆盖四账号合并与重复上传。
- 界面：Playwright 真实浏览器验证关键流程（导入 → 筛选 → 查看覆盖度 → 看下一步建议），并在手机视口下检查布局。

## 11. 已确认的决策

1. 覆盖度主视图**以 14 蛋组为主、性格为明细**。
2. 账号**跟随实际导入数据**，支持多账号合并与单账号筛选，默认全选。
3. 目标性格**默认取每蛋组前 3**，界面里可调整。
4. 已在三轮评审（产品 / 技术 / 用户）中确认的 14 项变更，见
   [三轮评审记录](2026-09-25-三轮评审记录.md)。
5. 产品形态是**看板**：照着看板去游戏里抓，抓完重新导入数据看进度，不需要"带走"清单。
6. **取消**野外分布区域、手动添加单只、手动改判三项（依据：分贝值与判定只能来自抓包数据）。
7. **新增母本集齐度**：种公按蛋组算（14 组），母本按进化链算（255 条）。
