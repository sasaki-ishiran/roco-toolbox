# 多人母本资源共享 MVP 设计

日期：2026-10-23。状态：供用户评审的完整设计；本次只编写设计与实施计划，不实施、不发布。

## 1. 用户目标与范围

用户希望几个熟人进入同一个小组，互相查看各自已有的母本，知道自己缺的母本在哪位成员手里，通过线下协商互换逐步补齐各人的母本全收集。同一个人可以有多台设备、多个游戏账号。

本轮已确认：

- 采用成员之间互相可见的小组，而非多份彼此隔离的双人清单。
- 一期只做资源共享和缺口对照；交换在游戏中自行完成。
- 不创建交换订单，不记录提供者到接收者的任务、已收到、交换确认或分工归属。
- 一期固定达标口径为母 + 大块头 + +100dB，不限制性格；用户选择其他母本口径放到二期。
- 一期支持多人，双人是只有两名成员的小组。

以下为本方案的具体默认决策，供整体评审：

- 按人汇总：选中游戏账号的资源取并集，一个号拥有即算这个人拥有；保留来源账号便于查找。不做每个小号各补一套。
- 手动发布/更新资源；导入新数据后提醒更新，不后台自动覆盖共享资源。
- 每组最多 20 人；可加入多个组，各组单独选择共享账号，当前界面只打开一个组。
- 组主负责重置邀请码和解散；普通成员可以退出。组主退出通过解散完成，一期不做转让和移除其他成员。
- 旧双人清单保留为兼容入口，新建共享引导到多人资源组，不自动迁移旧数据。

成功标准：A、B、C 三位成员分别发布资源；A 的手机和电脑是同一个成员；大家能看到准确的来源和缺口；重新导入并主动更新后覆盖随数据变化；不需要人为勾选收集完成。

## 2. 基于仓库的事实与边界

| 位置 | 当前事实 | 改造含义 |
| --- | --- | --- |
| `src/api/session.ts`、`functions/_lib/auth.ts` | 已有云端账号、Bearer token、恢复码、多设备登录 | 复用云端 accountId 代表一个工具箱身份，不新建登录系统 |
| `src/domain/parseBackup.ts` | `accountKeyOf()` 优先返回 `uid:<游戏UID>`；旧数据回退姓名 | 资源关联采用稳定游戏 UID；无 UID 的旧账号先重新导入，不作为多人共享账号 |
| `src/storage/snapshots.ts` | IndexedDB 存放按游戏账号区分的完整快照 | 共享摘要从原始快照和明确选号生成 |
| `src/ui/useOwnedPets.ts` | 输出会受顶部账号筛选影响，account 字段是显示标签 | 不能直接用这个 hook 作为共享资源数据源 |
| `src/domain/petFilters.ts` | `groupMothersByEgg()` 按 `eggGameId` 分组 | 母本收集单位复用现有蛋血脉，不使用过时文档里的进化链口径 |
| `src/domain/motherCriteria.ts` | `isQualifiedMother()` 统一判定性别、声音、体型 | 不另写一套达标规则 |
| `src/domain/swapChecklist.ts` | 默认大婉口径，名单分 mine/theirs，每种蛋一份勾选状态 | 新模型独立实现；不把两方状态扩成多人交易状态 |
| `src/ui/Swap.tsx` | 无本地账号时，整个换什么页面进入空状态 | 新资源组入口必须在无本地数据时也可访问 |
| `functions/_lib/lists.ts` | 分享码即读写权限，保存整份名单 | 新接口必须登录并校验组员；不复用旧匿名写权限 |
| `src/api/sync.ts` | 私有云同步是全量快照和设置，并非共享组发现机制 | 通过组列表恢复成员资格，不能仅依赖本地存储 |

这是玩家自报的资源目录，不验证玩家对游戏账号的真实所有权。服务器验证的是“谁有权修改这一名工具箱成员的共享摘要”。即使用户本地保存了朋友的备份，也只能明确勾选自己准备共享的账号，不把其余账号自动算作他人。

“某成员拥有母本”只说明其发布数据符合口径，不承诺一定可以即时生产目标蛋，不校验种公、窝位、性格概率和在线状态，也不生成跨游戏账号的配窝方案。

## 3. 用户流程与界面

### 3.1 入口

保留“换什么”页面，顶部主分段改为“换蛋清单 / 母本共享”。“换蛋清单”保持当前种公建议算法；“母本共享”支持没有导入任何账号的用户进入。

母本共享首页：

1. 未登录：解释登录用于识别同一个人，提供复用现有账号面板的入口；先保留用户输入的待加入邀请码。
2. 已登录：拉取我加入的小组，提供新建和输入邀请码加入。
3. 加入时填写组内昵称；昵称可重复，界面重复时加成员 ID 短尾码以区分，不把昵称当身份键。
4. 加入后即使未发布资源也可浏览。状态显示“尚未发布”，个人缺口暂不计算。

### 3.2 发布我的资源

“我的共享资源”面板列出当前组选中账号、游戏 UID、数据导出时间、合格母本种数、上次发布时间。

- 从 `useSnapshots()` / `listSnapshots()` 获取完整账号快照，不使用全局筛选后的精灵。
- 用户勾选自己要共享的账号，预览总覆盖、增加和移除的母本种数，再点“发布我的资源/更新我的资源”。
- 新设备默认显示服务器记录的选中账号；若本机缺少其中某个账号，提示先用现有云同步拉齐或导入。不得默默缩小为本机现有账号并覆盖。
- 主动取消某账号是明确的撤回动作；预览标明将移除的账号与覆盖。取消全部账号时按钮改成“停止共享我的资源”，确认后保留组员身份、清空该成员摘要。
- 修改选号仅是本地草稿，不改变已发布摘要；退出页面或刷新前提醒未发布修改。
- 导入或私有云同步改变本地快照时，只显示“本地数据有变化，更新后组员才能看到”；摘要未变不重复提示。
- 成功后服务器版本和发布时间更新；失败保持草稿和原服务器数据，不显示成功。

### 3.3 小组资源视图

三个视图，默认“我缺的”：

| 视图 | 行内容 | 计算前提 |
| --- | --- | --- |
| 我缺的 | 母本名称、拥有的组员、各自来源账号；无人拥有时显示相应说明 | 我已发布且版本可比较 |
| 我能补谁 | 我拥有的母本、已发布且缺少的成员 | 我与被比较成员的数据均有效 |
| 小组资源 | 全部母本目标，谁有、谁缺、谁尚未发布或需更新 | 随时可浏览 |

共同支持：按母本名称/同血脉名称搜索、按某位成员筛选、只看“组内有人拥有”。成员面板可查看某人的全部共享母本和来源账号。

“我缺的”包含两类，并按此顺序显示：组内已有人拥有；已发布成员均无。不要把缺口强行解释成交换任务。没有“已收/完成/认领/对方收”等控件。

顶部明确显示“一期口径：母 · 大块头 · +100dB”和“按已共享账号汇总”。不跟随全站追满分/追双牌及母本筛选设置；这样小组成员读到的是同一条件。

尚未发布或图鉴/口径不兼容的成员为未知。未知成员存在时不能写“小组都没有”，改写“已发布成员均无，另 N 人待发布/更新”。

## 4. 母本领域模型

### 4.1 类型与计算

新增 `src/domain/motherResource.ts` 和 `src/domain/motherSharing.ts`：

```ts
export const MOTHER_CRITERIA_ID = 'female-huge-voice100-v1';

export interface SharedMotherAccount {
  accountKey: string; // uid:<正整数>，服务端校验规范形式
  accountName: string;
  sourceExportedAt: string; // 有效 ISO 时间，来自游戏数据导出
  eggGameIds: number[]; // 去重、升序，仅达标母本的蛋血脉 ID
}

export interface MotherResourceDraft {
  schemaVersion: 1;
  criteriaId: typeof MOTHER_CRITERIA_ID;
  catalogVersion: string;
  accounts: SharedMotherAccount[];
}

export interface PublishedMotherResource extends MotherResourceDraft {
  revision: number;
  publishedAt: number; // 服务器毫秒时间
}

export interface MotherGroupMember {
  accountId: string; // 工具箱身份，服务器从 token 获取写入方
  displayName: string;
  joinedAt: number;
  resourceRevision: number; // 撤回资源也递增，不因空摘要归零
  resource: PublishedMotherResource | null;
}

export interface MotherCoverageRow {
  eggGameId: number;
  name: string;
  holders: Array<{ accountId: string; accountKeys: string[] }>;
  missingMemberIds: string[];
  unknownMemberIds: string[];
}
```

函数边界：

- `buildMotherResource({ snapshots, selectedAccountKeys, species, catalogVersion }): MotherResourceDraft`。找不到任何选中账号、UID 无效或导出时间无效时抛出明确错误；不产生半份摘要。
- `buildMotherCoverage({ species, members, catalogVersion }): MotherCoverageRow[]`。只派生目录，不产生持久化进度。
- `selectMotherSharingViews(rows, viewerAccountId, comparableMemberIds)` 返回 `{ missingForMe, mineForOthers, all }`。第三个参数来自当前有效、口径与图鉴一致的成员集合；自己的有效摘要不存在时前两项用 `null` 表示不可计算，不能用空数组伪装已补齐。即使当前图鉴没有目标行，也不能丢失发布状态。

### 4.2 口径

- 目标全集是 `eggGameId === gameId` 且至少有一个可孵蛋组的图鉴蛋物种。
- 每只精灵先通过 `isQualifiedMother(pet, { bodies: ['大块头'], voices: ['+100'] })`，再按其物种的 `eggGameId` 归并。
- 公、未知性别、+99dB、小不点、无蛋血脉、未发现组、图鉴未知的精灵不增加达标覆盖。
- 不要求母本性格，不要求物种能出公；这里是母本收集，不是种公网络。
- 同一蛋下不同进化形态和重复个体只算一个目标。同一个人不同账号拥有时计数一次，但保留多个来源账号。
- 匹配的游戏账号不靠 `pet.account` 显示名判断，直接遍历账号快照；重名和改名不影响身份。
- 不把组员资源写入自己的 IndexedDB，不修改自己的看板、精灵列表和私有云快照。
- 图鉴版本或口径 ID 与当前客户端不同的摘要标记“需更新”，不用于推断缺失；本地未知的 eggGameId 不生成虚假图鉴行。

## 5. 数据库存储与原子性

在 `functions/schema.sql` 追加三张表，并新增仅含这些新表/索引的增量文件 `functions/migrations/2026-10-23-mother-groups.sql`；两处建表定义保持一致。D1 外键约束必须在本地集成测试中验证开启。

### 5.1 `mother_groups`

- `id TEXT PRIMARY KEY`：UUID。
- `owner_account_id TEXT NOT NULL REFERENCES accounts(id) ON DELETE CASCADE`。
- `name TEXT NOT NULL`，1–40 个 Unicode 码点，修剪首尾空白。
- `invite_hash TEXT NOT NULL UNIQUE`：8 位邀请码的 SHA-256；明文仅创建/重置返回，客户端本机可保存供复制；换设备需组主重置才能重新展示明文。
- `created_at INTEGER NOT NULL`。

### 5.2 `mother_group_members`

- 复合主键 `(group_id, account_id)`；分别关联组、工具箱账号，均 `ON DELETE CASCADE`。
- `display_name TEXT NOT NULL`，1–20 个 Unicode 码点。
- `joined_at INTEGER NOT NULL`。
- `resource_revision INTEGER NOT NULL DEFAULT 0`。
- `published_at INTEGER NULL`、`catalog_version TEXT NULL`、`criteria_id TEXT NULL`。
- `write_token TEXT NULL`：服务端每次资源写入生成的随机事务标识，永不接受客户端传值。
- 增加 `(account_id, group_id)` 索引，支持跨设备发现我加入的组。

### 5.3 `mother_group_accounts`

- 主键 `(group_id, game_account_key)`：同一个游戏 UID 在一个组内只归一位成员共享。
- `member_account_id TEXT NOT NULL`，复合外键 `(group_id, member_account_id)` 指向成员表并级联删除。
- `account_name TEXT NOT NULL`、`source_exported_at TEXT NOT NULL`。
- `egg_game_ids TEXT NOT NULL`：规范化整数数组 JSON。
- 增加 `(group_id, member_account_id)` 索引。

同 UID 被另一位成员选中时返回 `409 GAME_ACCOUNT_ALREADY_SHARED`，说明已由哪位组员共享；不自动合并两个工具箱身份。用户应取消该账号，或原共享者先撤回。

### 5.4 原子更新

一次发布是该组内该成员的完整所选账号集合替换，包含账号删除；不做只增不减的集合合并。

- 请求携带 `baseRevision`；服务器使用 `UPDATE ... WHERE resource_revision = ?` 乐观锁。
- 使用 D1 `batch()` 同一事务完成成员版本更新、该成员旧账号删除、新账号插入。
- 服务端生成全新 `write_token`；删除/插入语句必须以本次令牌匹配的成员行为条件。首条 CAS 没命中时后续语句全无操作，不得出现“冲突但已删资源”。
- UID 唯一约束或任一插入失败时整批回滚，旧摘要完整保留。
- 更新前对保留账号校验 `sourceExportedAt`。比当前共享时间更旧返回 `409 STALE_SOURCE`；相同时间、相同图鉴与口径而覆盖内容不同返回 `409 SOURCE_MISMATCH`；同时间同覆盖允许重发和改显示名。图鉴升级后允许从同一原始快照重新计算不同覆盖，仍不接受更旧的源数据。
- 时间比较转换为时间戳，不按字符串排序；同源覆盖比较使用排序去重后的 ID 数组。
- 新设备没有的所选账号必须先补齐本地数据，或者用户在预览里明确撤回。发生 409 后刷新并重新预览，不自动用旧草稿套新版本重试。
- 全部撤回仍递增成员版本，清空 `published_at/catalog_version/criteria_id`；此后该成员是未知，而非“已确认零母本”。
- 至少一个有效账号且 ID 数组为空则表示“已发布、目前无达标母本”，是可比较的已知空资源。

## 6. API 合同

新建 `/api/mother-groups` 系列；所有接口都使用 `authenticate()`。不接受客户端 accountId 作为写入归属。成功返回 `{ ok: true, ... }`；错误 `{ ok: false, code, error }`，供 UI 分支处理。

| 方法与路径 | 输入 | 输出/权限 |
| --- | --- | --- |
| `GET /api/mother-groups` | 无 | `groups: [{id,name,ownerAccountId,memberCount}]`；只返回当前身份加入的组 |
| `POST /api/mother-groups` | `{name, displayName}` | `{group, inviteCode}`；创建组及组主成员原子完成 |
| `POST /api/mother-groups/join` | `{inviteCode, displayName}` | `{groupId}`；同身份重复加入幂等，不重复创建成员 |
| `GET /api/mother-groups/:id` | 无 | `{group:{id,name,ownerAccountId,createdAt}, members}`；仅组员；不返回邀请码哈希 |
| `PUT /api/mother-groups/:id/resources/me` | `{baseRevision, resource: MotherResourceDraft}` | `{resourceRevision,publishedAt}`；只替换自己的摘要，`accounts:[]` 表示停止共享 |
| `PUT /api/mother-groups/:id/profile/me` | `{displayName}` | 更新当前组自己的昵称；不影响资源版本 |
| `POST /api/mother-groups/:id/invite/reset` | 无 | `{inviteCode}`；仅组主；旧码失效，现有成员保留 |
| `DELETE /api/mother-groups/:id/members/me` | 无 | 普通成员退出，同时删其资源；组主返回 `409 OWNER_MUST_DISSOLVE` |
| `DELETE /api/mother-groups/:id` | 无 | 组主解散，成员/摘要级联删除；普通成员 403 |

错误：未登录 401；非成员/非组主 403；已解散组 404；达到 20 人 409；无效 JSON/字段/口径/时间/UID/整数 400；UTF-8 请求体超过 128KiB 返回 413；超限 429。

资源输入限制：最多 50 个游戏账号；账号名 1–80 个 Unicode 码点；每账号最多 1024 个正安全整数 ID；`schemaVersion` 必须是 1，`criteriaId` 必须等于一期固定值；`catalogVersion` 1–80 字符；ID 排序去重；重复账号键拒绝。未知 JSON 字段不持久化。不接收完整宠物、令牌、邮箱或恢复码字段。

读取限流按已认证 accountId 计，每小时 1800 次；同一身份下多设备共享额度。资源写入每小时 120 次；创建/加入/重置每小时各 30 次；删除每小时 30 次。另给创建/加入按 IP 每小时 120 次的探测上限。同一公网多成员不共用低额度轮询桶。所有 429 返回 `Retry-After: 60`。

组详情使用同一个 D1 `batch()` 读取组、成员与账号摘要，避免读取过程中某个成员发布导致版本与账号列表不一致。

加入人数检查必须在插入成员的 SQL 条件内；并发抢最后名额不能超过 20。组已满时，已在组内的同身份重试仍返回成功。加入和重置邀请码需要在数据库操作中确认码仍有效，不能用重置前读到的组记录继续加入。

`corsHeaders()` 的允许方法补 `DELETE`。已认证数据响应设置 `Cache-Control: no-store`；Service Worker 不缓存这组 API。

## 7. 前端同步与身份切换

- 新增 `src/api/motherGroups.ts`，复用 `authFetch()`；API 类型来自无运行时依赖的 `src/shared/motherGroups.ts`，Functions 可类型导入这个文件。
- 前端记录当前 accountId 的组列表与当前组，服务器是真相来源；持久化键按 `roco.motherGroups:<accountId>` 隔离，只保存当前组 ID 和组主本机邀请码，不保存 token。
- 会话变化订阅 `subscribeSession()`。退出/换人立即清组内容、发布草稿、定时器和旧身份缓存；同一设备不能短暂显示上个身份的小组资源。
- 使用 `AbortController` 和请求代数丢弃切组、退出、晚到轮询响应。发布请求也绑定开始时的身份和 groupId，晚到响应不得覆盖当前组。
- 页面可见且当前组打开时每 15 秒拉一次；切回前台立即拉。后台停止定时器；不并发重叠拉取；卸载清理。
- 第一次成功读取前显示加载态；断网后保留当前会话内最后一次成功结果并注明“离线，显示上次获取的数据”。首次读取失败不计算缺失。
- 403/404 后移除当前组内容并刷新组列表；401 按现有机制退出会话。429 尊重 `Retry-After`，没有该头则至少 60 秒后再轮询；不能每 15 秒继续撞限流。
- 不做离线自动重放发布。网络失败后保留选号草稿，用户重试前重新获取当前版本并再次预览。
- 换设备登录同一身份后从 `GET /api/mother-groups` 找回所有小组，不用再次输入邀请码；查看云端共享摘要不要求下载私有完整快照。

## 8. 生命周期、兼容与二期

- 普通成员退出后，其账号共享资格及资源同时删除；保留玩家本地导入数据和私有云快照。
- 组主解散删除整个组和全部摘要；其他成员下次拉取看到组已解散。
- 注销工具箱账号时，新增外键使其创建的组级联解散、在其他组的成员与资源级联删除。更新现有注销确认文案，列出影响，不让人误以为仅删私人快照。
- 旧 `shared_lists`、`/api/list`、本地 `roco.swapChecklist` 不重写、不删除；存在旧清单的用户显示“查看旧版双人清单”。旧状态不能映射成真实成员或新资源。
- 一期不再主动引导创建旧清单；旧组件保留原功能，便于兼容与回滚。
- 不把新组共享资源加入 `SYNCED_PREF_KEYS`：组成员关系本身已在服务器，避免私有快照恢复时把别人摘要导入本地。
- 二期加入用户自选体型/声音口径，优先复用 `MotherCriteria`。一期已保存 `schemaVersion/criteriaId/catalogVersion`，二期通过重新发布生成新摘要；一期摘要无法反推其他档位，不能凭旧摘要声称支持新口径。
- 二期可再评估每个小号独立全收集、组主转让/移除成员、发布自动化；这些均不纳入一期任务。

## 9. 验收矩阵

| 编号 | 场景 | 必须观察到的行为 |
| --- | --- | --- |
| S01 | A/B/C 三人，各有部分母本 | 每人能看见正确来源与自己的缺口；A/B 有而 C 缺仍展示给 C |
| S02 | A 两个游戏 UID 同名，均有同一种母本 | A 覆盖计一次，来源显示两个账号；选号不靠名字 |

| S05 | B 刚加入未发布、C 已发布空母本 | B 未知；C 已知无；文案不能把 B 算成缺所有母本 |
| S06 | 新数据移除原有母本、用户更新 | 对应覆盖消失，缺口重算；没有交换完成勾选 |
| S07 | 旧设备/并发发布 | CAS 冲突或旧源时间被拦，原摘要不丢，必须重新预览 |

## 10. 交付与发布原则

本次交付本设计和配套实施计划。实施从领域测试开始，依次建立 D1 原子写入、认证 API、客户端与 UI，再做多身份、多设备联调。

测试必须分开证明：Vitest 证明领域与状态、mock 浏览器测试证明界面流程、本地 Wrangler + D1 证明真实 SQL 和认证、真实浏览器连接本地 Functions 证明跨身份共享。静态 preview 的 mock 结果不能替代真实 API 验收。

生产发布前核实 Cloudflare test 是否与生产共用 D1；当前仓库只有一个绑定库，不能把 test 当成天然隔离的数据环境。增量建表可兼容旧版；试验小组使用专用测试身份并清理，不把用户生产数据当测试样本。

回滚前端不删除新表，不破坏旧版接口。小组新 API 与旧清单 API 并存，使前端回滚可单独完成。
