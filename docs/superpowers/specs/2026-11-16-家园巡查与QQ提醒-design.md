# 家园巡查与换蛋QQ提醒：接入设计（2026-11-16）

状态：用户已确认一次性群关联码、本人主UID和每半小时巡查（2026-11-16）；现有换蛋页面已验收，本设计只补新增服务与必要接入状态。执行仍由当前会话直接完成。

## 已确认的目标

本期补齐家园巡查和孵好QQ提醒后，再直接发布正式网页。普通蛋可换、异色/特殊蛋禁换；只有需求方确认收到。巡查发现对应蛋已产出后，在群里@孵蛋方，让他收蛋并交给该任务另一方。QQ身份复用RocomUID明确绑定的全部UID（主uid与home_uids），一个QQ可绑定多个游戏账号；临时查询的UID不建立身份关联。两条旧蛋组承接取消，原始数据与历史保留。

用户授权未包含APK、更新清单、其他内测模块。现有AGENTS中的“机器人后续接入”条款由本次明确范围更新覆盖。

## 选择的接入方式

采用云端巡查状态与通知队列 + 本机GsCore插件主动拉取 + 原有QQ订阅发送。

对比：云端直接调用本机8765不可达且接口语义不对；开放公网机器人端口增加运维和鉴权负担；由本机主动拉取可复用现有连接与守护，不需要开放入站端口。云端队列保留重试和去重记录，本机掉线期间不伪称已通知。

第三方请求只在服务端执行，网页不持有API Key。本机插件不使用空WS_TOKEN的HTTP入口；经gs_subscribe取得持久化订阅，再调用sub.send，沿当前NoneBot/LLBot7链路出站。

## 小组、游戏UID与QQ群如何对应

- 工具箱当前小组已有成员共享资源的accountKey=uid:数字；接受的现孵任务保存gameAccountKey和两个亲本captureId。
- 群管理员/组主在网页当前小组设置领取10分钟有效、单次使用的接入码。仅组主可领取或撤销，服务端只存摘要。
- 接入码用于一次性确认“工具箱这个小组的提醒发到哪个QQ群”，不要求每位成员领取，也不用于个人QQ绑定。
- 在目标QQ群由群主或管理员发送 rc换蛋接入 <码>；插件验证群管理身份，向云端兑换接入码。一个工具箱小组绑定一个QQ群，换群需网页组主重新发码并明确替换。
- 插件通过gs_subscribe保存该群订阅与工具箱组ID，重启后恢复。停用命令 rc换蛋停用 仅群管理员使用。
- 按任务准确UID在RocomUID明确绑定的主uid与home_uids中查孵蛋方QQ；同一QQ多个UID均可提醒本人，同QQ重复记录去重。用户说明同UID对应多个不同QQ不会出现，不将此作为常规产品流程；实现遇到数据异常不任意选人。未匹配时提示绑定，沿用现有rc绑定uid功能。匹配机器人实例用bot_self_id，和绑定写入保持一致。
- 不因查询过某家园、昵称相同或组员手填QQ而建立身份。云端不公开成员QQ；插件只持有必要的任务/UID/交接摘要。

## 巡查与产出判定

只巡查已接受、未结束的现孵任务涉及账号；同UID跨组/多任务合并为一次查询，现货不巡查。云端由本机插件每分钟唤起一次内部tick，单次有界处理，避免依赖Pages缺少定时触发器的问题。

用户已确认每半小时巡查：同UID30分钟缓存，全天第三方请求上限100次（本次答复确认暂保留），可配置；总额80,000不是可无限消费的授权。每个实际HTTP调用均先原子占用配额，失败调用也计数；超额停止第三方请求，不影响换蛋主流程。超时10秒，不在同轮自动重试；仅保存最后成功确认时间。

首选scene-info单次请求，只有缺少判定字段才按明确需要补home/info，且每次补查单独计费。错误只记录脱敏状态，不返回密钥或原始账户载荷。

解析规则：
- 保留actor_id、pet_gid和GUID为字符串；优先furniture_guid_exact。仅有不精确数值时按其精度区间匹配，候选不唯一即不绑定，不能任意截前缀命中。
- 用任务gameAccountKey + 亲本实例pet_gid，与scene-info当前配对匹配。captureId中的实例部分解析失败时标待确认，不用同物种代替实例。
- 接单后首次成功巡查建立现有蛋基线，不把早已在窝里的蛋当成本单新产出。只有基线之后出现的新增蛋、匹配唯一亲本/窝并且任务仍有效时，生成产出观察。
- 一颗家园蛋只绑定一笔任务；多单命中待用户在接单弹窗中分配，不在后台任选。
- 推算到时间只表示预计可产，不当作已产出；通知依据真实eggs[]新实例或明确可收集状态。家园蛋不伪造背包实例，不直接挂为现货。
- 当前配对候选标“游戏未确认”；游戏明确biological_parentage_confirmed时才能显示确认父母。家园蛋无体重，不标确定满重。

## 通知与用户操作

观察到新蛋后生成事件键：任务ID+产出侧+家园蛋actorId。相同事件只生成一条通知；任务取消或完成后不再发。双边现孵各自通知对应孵蛋方。

示例：@孵蛋方 菊花梨已产出，请收蛋后交给「对方昵称」。附工具箱同源入口；不暴露恢复码、token或内部ID。

巡查观察不自动标上窝、交付或收货，也不累计已完成数量。用户收进背包后，由真实采集库存分配给任务；最后需求方点“已收到”。对方未绑定QQ时仍可按小组显示名交接，孵蛋方按任务UID对应的已绑定QQ进行@。

队列领取带租约，发送成功后确认；失败指数退避。插件本地持久化已发送事件ID，重启不重复发送。网络异常导致“已发但未确认”的窄窗口保留审计，不承诺绝对恰好一次。一次检查合并同人同群提醒，最多一次消息列出多个新蛋。
