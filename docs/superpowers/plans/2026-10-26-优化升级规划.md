# 优化升级规划（2026-10-26，v1.3 → v1.5）

> 依据：[三方评审：项目健康度与实际价值](../reviews/2026-10-26-三方评审-健康度与实际价值.md)
> 状态：已按用户授权「先代拍板」制定；所有决策见 §6，可在审核时逐条推翻。
> 本规划**不含工期承诺**；执行顺序按依赖关系排列，每批次独立可发布、可回滚。

## 0. 先看这 5 件事（如果只看一段）

1. **先把工作区提交掉**：现在有 38 项未提交改动，生产可能领先于 git。没有这一步，后面所有「回滚」都是假的。
2. **做只读示例看板**：84% 的设备从未导入，先让他们看到「这东西能算出什么」。
3. **导入成功后给一个出口**：「看我还缺什么 →」。不自动跳页，尊重 2026-10-25 的决定。
4. **把统计改成真匿名 + 写清数据去向**：现在的「匿名埋点」会关联账号，文档还写着「数据只在本机」。
5. **补 4 组关键测试**（DB 迁移 / 客户端解析 / 小组 hook / 云同步 409），再谈拆大文件。

## 1. 目标与北极星指标

### 1.1 一句话目标

**让第一次打开的人拿到第一条有用结论，让已经导入的人每周有理由回来一次。**

### 1.2 北极星指标

**每周有效收集用户（WEU）** = 当周至少成功导入 1 次、且查看看板或小组的设备数。

- 当前基线：约 5–13 台/日有导入，累计 13 台导入设备。
- 目标：在触达不变的前提下，把「新设备首次导入率」从 16% 提到 ≥35%，WEU 至少翻倍。

### 1.3 三个硬指标

| 指标                  | 当前          | 目标                       | 采集方式                           |
| --------------------- | ------------- | -------------------------- | ---------------------------------- |
| 新设备首次导入率      | 13 / 80 = 16% | ≥35%（按新设备队列）       | `app_open` + `import_success` 去重 |
| 只打开 1 次的设备占比 | 59 / 80 = 74% | ≤60%                       | `app_open` 按设备计数              |
| 导入用户人均导入次数  | 12.1          | ≥8（不要为了转化牺牲深度） | `import_success` / 设备            |

## 2. 原则与边界

### 2.1 做

- 先把「价值闭环」修好，再加功能。
- 所有改动小步、可回滚、有验收。
- 优先复用已有能力（`unlockedCells`、`lastImportStore`、`ModalSurface`、`primitives`）。
- 数据与隐私：默认最小化、可关闭、可撤回、说得清。

### 2.2 不做（本规划明确排除）

- 不重写、不换技术栈、不拆多包。
- 不做成就系统、赛季通行证、交易系统。
- 不做种公组需求承接（先验证采用）。
- 不做逆向对抗上游（只做可降级）。
- 不做 61 份文档的全量归档迁移（只纠错）。
- 不引入整套组件库（继续用 `src/ui/primitives/`）。

### V1 提交当前工作区并建立发布基线

**做什么**

- 把当前 38 项改动（含需求承接、图鉴更新、口径修正）分组提交；至少拆成「功能」「数据」「文档」三类。

### V2 只读示例看板（首次价值验证）

**做什么**

- 无本机数据时，在「看板 / 收集 / 覆盖度」的空态提供「用示例看看」。
- 用现有 fixture（`src/domain/__fixtures__/backup-sample.json`）在内存里跑一遍完整计算，渲染真实看板。
- 三处明确标注：顶部条「示例数据，未保存」、数据卡角标、以及退出示例后回到空态。
- 示例模式**禁止**写入 IndexedDB / localStorage、禁止自动发布、禁止云同步、禁止埋点上报精灵数。

**为什么**：84% 的设备从未导入；先看到结论，才有可能愿意去找文件。

**验收**

- 空态 → 示例看板 ≤ 1 次点击。
- 示例模式下刷新页面不残留任何数据；`indexedDB.databases()` 无新增库/表。
- e2e：示例模式可看板、可覆盖度；退出后回到空态；无 `import_success` / 自动发布请求。

**涉及**：`src/ui/EmptyState.tsx`、`src/ui/Dashboard.tsx`、`src/ui/Collection.tsx`、`src/ui/useOwnedPets.ts`、`src/ui/useCollectionSummary.ts`（支持传入只读快照）

**风险**：示例被误当真实进度 → 三处标注 + 顶部固定条；示例内不显示账号名。

### V9 统一校验与发布脚本

**做什么**

- `package.json` 增加：
  - `verify:types` = 前端 `tsc -b` + 后端 `tsc -p functions/tsconfig.json`
  - `verify` = types + `vitest run` + `test:mother-groups:api` + `build`
  - `verify:all` = `verify` + `playwright test --workers=4`
- `tools/release.ps1`：
  1. 检查工作区干净（脏则中止）。
  2. 跑 `verify:all`。
  3. 记录 `dist` 哈希。
  4. 部署 test → 提示人工冒烟 → 部署 main。
  5. 用远端 HTML 的 `assets/index-*.js` 与本地哈希比对。
- 明确禁止 `--commit-dirty=true` 进入正式发布路径。

**为什么**：消除「忘了跑后端 tsc」「带脏工作区发生产」「哈希对不上」三类事故。

**验收**

- 故意留一个后端类型错误，`npm run verify` 必须失败。
- 工作区脏时 `release.ps1` 拒绝执行。

**涉及**：`package.json`、`tools/release.ps1`（新建）、`.gitignore`

### V10 第三方上传：默认不打包凭据 + 明确披露

**做什么**

- 安卓构建默认不注入 `capture.token`；需要上传能力时显式 `-RequireUpload`。
- 未配置时隐藏上传按钮，并提示「此安装包未启用上传」。
- 上传前弹一次确认：以第三方客户端身份、上传内容含游戏账号数据、对方可能留存。
- `README` / `docs/手机使用说明.md` 不提供带凭据 APK 的公开分发。
- 保留手动路径：导出 PCAP → 原版导入上传。

**为什么**：这是唯一可能让整个项目下线的风险；但不砍掉用户明确要求的能力。

**验收**

- 默认构建产物中不存在令牌常量（`strings`/grep 检查）。
- 未配置时无上传入口；配置后才出现。
- 确认弹层只在上传路径出现，且可取消。

**涉及**：`android-shell/build.gradle`、`android-shell/app/build.gradle`、`CaptureUploadManager.java`、`NativeCollectorPanel.tsx`、`README.md`

> 备注：如果你希望保留现状（默认带凭据），只回退这一条即可，不影响其它任务。

## 5. 批次二：留存与协作（P1）

### R1 进度趋势（本地聚合）

**做什么**

- 每次导入成功后写一条聚合记录：日期、账号数、母本链达标数、种公槽位数、本次新增达标数。
- 最多保留 90 条（超出删最旧）；只存聚合数，不存个体。
- 看板进度卡显示「较上次 +N」；「我的 · 数据」给最近 4 次的迷你趋势。
- 不参与云同步（避免冲突）。

**验收**：连续两次导入能看到增量；清除导入数据时一并清除；存储上限生效。

**涉及**：`src/storage/`（新增 `progressHistoryStore`）、`src/ui/Dashboard.tsx`、`src/ui/ImportPanel.tsx`

### 8.1 批次一验收（发布前必须全绿）

## 11. 竞品差距对策（2026-10-26 追加）

> 依据：[竞品评审：蛋神助手](../reviews/2026-10-26-竞品评审-蛋神助手.md)。
> 结论先行：**不自建市集/积分/机器人；学「产线化、零门槛、需求单」，把交易履约留给现有市场。**

### K1 产线化（P0，最高 ROI）

**做什么**

- 新增「产线」实体：名称、目标精灵/蛋组、性格、奖牌、目标数量、优先级、状态。
- 从覆盖度/配窝建议一键「加入产线」；首页显示「已完成 X 条 / 共 Y 条产线」。
- 每条产线展开：缺口 + 配窝方案 + 求蛋卡；完成时给本地/组内徽章，不做积分。
- 由现有 `collectionTargets` 派生，不做双记账；首批最多 3 条，支持归档。

**为什么**：这是竞品最强的留存单位，也是本项目最缺的「可完成感」；复用现有 domain，不造新算法。

**验收**

- 导入用户可创建/完成产线；完成数变化可见。
- 产线进度与覆盖度、配窝建议口径一致（同一数据源）。
- 删除产线不影响目标/筛选/草稿。

**涉及**：`src/domain/`（新增 `productionLine` 纯函数）、`src/ui/Dashboard.tsx`、`src/ui/Collection.tsx`、`src/ui/collectionTargetStore`（或现有 target store）

**与现有任务**：扩展 V2（示例看板）与 R2（本周 3 件）。

---

### K2 求蛋卡 / 换蛋清单导出（P0）

**做什么**

- 从缺口一键生成「求蛋卡」：蛋种/蛋组、性格、体型、声音、数量、优先级、数据版本。
- 一键复制为群聊友好文本；可选带参链接（若外部市场支持）；**默认不含账号名/UID**。
- 支持「已换到」回填（只记状态，不写快照；沿用 V11 的提示）。

**为什么**：解决「算完还得去别处交易」的最后一厘米；不接管交付、不依赖第三方 API。

**验收**

- 复制文本包含完整筛选条件，且不含 UID/账号名。
- 回填后进度卡显示「未纳入数据」提示。
- 外链不可用时自动退化为复制，不报错。

**涉及**：`src/domain/swapPlan.ts`、`src/ui/SwapWishCard.tsx`、`src/ui/CopySheet.tsx`、`src/ui/SuggestionCard.tsx`

---

### K3 验蛋清单 + 本地交易记录（P1）

**做什么**

- 交易前 checklist：声音 dB、体型、性格、绿窝、父母本、截图/录屏、对方 ID。
- 本地交易笔记（谁、什么蛋、何时、结果）；可选组内共享笔记。
- **不做**全局黑名单、公开裁判、自动验货。

**为什么**：信息不对称是交易层最大坑；我们只做「交易前知道看什么、交易后留证据」。

**验收**

- checklist 可勾选、可复制；交易笔记本地可查、可删。
- 不出现「官方认证」「保证满分」等承诺性文案。

**涉及**：`src/ui/`（新增 `TradeChecklist` / `TradeNotes`）、`src/storage/`

---

### K4 组内供需匹配与回填（P1，合并 R3/R4）

**做什么**

- 缺口 ↔ 组内成员资源自动匹配；命中时在成员/资源卡上标「可补」。
- 需求发布/接单/完成/贡献记录；完成后回填产线与进度提示。
- 复用现有 `collection_group_demands` 与认领 API，不新增交易语义。

**为什么**：把已有小组能力从「看板」变成「撮合 + 回填」，与竞品的公开大市场形成互补。

**验收**

- 组内缺口命中时可见；接单/完成状态与需求表一致。
- 贡献记录只统计需求方确认完成的条目。

**涉及**：`src/ui/MotherGroupResources.tsx`、`src/ui/useCollectionGroups.ts`、`functions/_lib/collectionGroupsStore.ts`

---

### K5 采集器收窄为管道 + 多腿取数（P1，合并 V3）

**做什么**

- APK 只做「采集 / 角色 / 文件」，不再堆查询/商人/提醒；价值留在 PWA。
- 增加「朋友导出文件 / 分享导入 / 示例」路径；iOS 明确「让朋友代导」。
- 导入页三步指引 + 配置化下载入口（未配置不显示链接）。

**为什么**：竞品 1.2.4 已把采集器收窄为管道，这是正确方向；本项目维护面有限，更不该把采集器做成第二产品。

**验收**

- 采集器新增功能需单独评审；PWA 主路径不依赖采集器新功能。
- iOS 用户能在导入页看到可执行路径。

**涉及**：`android-shell/`、`src/ui/NativeCollectorPanel.tsx`、`src/ui/ImportPanel.tsx`

---

### K6 市场文本粘贴解析（P2，探索）

**做什么**

- 用户主动粘贴市集/群聊文本，本地解析出「蛋种/性格/奖牌/价格」，与自己的缺口匹配，提示「买这个能补几格」。
- **不爬虫、不调第三方 API、不自动下单、不代登录。**

**为什么**：把外部流动性「只读」地接进决策层；成本低，风险可控。

**验收**

- 解析失败有明确提示，不猜测；不发起任何网络请求。
- 识别结果可一键加入求蛋卡/产线。

**涉及**：`src/domain/`（文本解析纯函数）、`src/ui/`（粘贴面板）

**触发条件**：K2 上线后，观察求蛋卡导出次数；若导出高但成交低，再做。

---

### K7 轻提醒（P2）

**做什么**

- 本地通知 / ICS 日历：生蛋窗口、远行商人、每周回顾。
- **不做**进家园查询、自动收蛋、账号代管、机器人。

**为什么**：提醒是高频留存钩子；机器人履约是竞品护城河也是最大风险。

**验收**

- 提醒可关闭；文案写「建议窗口」，不承诺精确。
- 不申请与游戏账号相关的权限。

**涉及**：`src/ui/`、`public/`（如 ICS）

---

### K8 明确不做清单

- 不自建市集/积分/托管/提现/RMT。
- 不做机器人进家园、自动收蛋、账号池、批量注册/多开。
- 不做全局黑名单/点赞排行/公开裁判/管理员后台。
- 不追 30 多页广度、色卡/闪卡/彩球模拟、VIP 墙。
- 不做 PC 客户端与多端功能对齐（除非有真实需求）。
- 不逆向对抗、不绕过反作弊、不复用竞品凭据。
