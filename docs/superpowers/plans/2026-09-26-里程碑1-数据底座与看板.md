# 里程碑 1：数据底座与看板 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: 用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务执行本计划。步骤用复选框（`- [ ]`）跟踪。

**Goal:** 做出一个能在手机上打开、导入抓包数据、并看到「种公网络 + 母本集齐度」两块进度的看板。

**Architecture:** 单包 Vite React 应用。纯函数领域层（`src/domain`）不依赖 React 与浏览器 API，覆盖度与解析逻辑全部在此层并被单测覆盖；界面层（`src/ui`）只做展示与交互；存储层（`src/storage`）用 IndexedDB 封装。上游图鉴数据由已完成的 `tools/data-pipeline` 产出，应用启动时打包进静态资源。

**Tech Stack:** Vite、React 18、TypeScript、Tailwind CSS、Vitest、Playwright。

**Spec:** [2026-09-25-洛克工具箱-design.md](../specs/2026-09-25-洛克工具箱-design.md)

## Global Constraints

- 移动优先，Android Chrome 为主；单手可操作，点击区不小于 44px。
- 无后端；账号数据只存手机本地 IndexedDB，不上传。
- 图鉴与账号数据的连接键是 `speciesPetId` ↔ `game_id`；**禁止**使用备份里的 `runtimePetId`。
- 母本计数单位 = `evolution_id`（形态级进化链）。可孵蛋链共 255 条。
- 蛋组 id：1 = 未发现（不可孵蛋，任何统计都要排除），2~15 为 14 个可孵蛋组。
- 分贝值与体型判定只能来自抓包数据；**不提供**手动录入与手动改判。
- 界面必须显示数据来源与 CC BY-SA 4.0 署名链接。
- 所有实现走 TDD：先写失败的测试，看到它失败，再写实现。

## Review Focus

1. 导入的 JSON 字段缺失或来自更旧的导出工具 → 必须给出可读错误并保留本地旧数据，不能崩溃或写入半份。
2. 同一份文件重复导入 → 精灵不重复计数，进度不虚高。
3. 空数据（新用户、零精灵）→ 两块进度显示 0 / 255 与 0 / 14，不出现除零或空白页。
4. 图鉴里查不到的 `game_id`（上游还没收录的新精灵）→ 归入"图鉴未收录"分类单独展示，不计入进度分母。
5. 一只精灵属于两个蛋组 → 两个蛋组的覆盖度都要计入，不能只算第一个。

- [ ] **Step 1: 写失败的测试** —— `src/domain/motherCoverage.test.ts`

```ts
import { describe, expect, test } from 'vitest';
import { computeMotherCoverage } from './motherCoverage';
import type { OwnedPet, SpeciesEntry } from './types';

const species: SpeciesEntry[] = [
  // 单形态：三个阶段共享一条链
  { key: 'pet_a1', gameId: 101, name: '伊雷龙', number: '203', stage: 1, evolutionId: 'evo_ilan', eggGroups: [14] },
  { key: 'pet_a2', gameId: 102, name: '伊兰亚龙', number: '204', stage: 2, evolutionId: 'evo_ilan', eggGroups: [14] },
  { key: 'pet_a3', gameId: 103, name: '伊兰龙', number: '204', stage: 4, evolutionId: 'evo_ilan', eggGroups: [14] },
  // 多形态：两种样子各一条链
  { key: 'pet_b1', gameId: 201, name: '岚鸟', form: '春天的样子', number: '020', stage: 3, evolutionId: 'evo_bird_spring', eggGroups: [5] },
  { key: 'pet_b2', gameId: 202, name: '岚鸟', form: '夏天的样子', number: '020', stage: 3, evolutionId: 'evo_bird_summer', eggGroups: [5] },
  // 不可孵蛋
  { key: 'pet_c1', gameId: 301, name: '迪莫', number: '001', stage: 1, evolutionId: 'evo_dimo', eggGroups: [1] },
];

const mother = (gameId: number, account = '账号A'): OwnedPet => ({
  gameId, name: 'x', gender: '母', nature: '开朗', voiceDb: 99, medalBody: '', isShiny: false, account,
});
const male = (gameId: number): OwnedPet => ({ ...mother(gameId), gender: '公' });

describe('computeMotherCoverage', () => {
  test('母本计数单位是形态级进化链，不区分阶级', () => {
    const result = computeMotherCoverage(species, [mother(102)]);
    expect(result.total).toBe(3); // 伊兰链 + 岚鸟两种样子；迪莫不可孵蛋不计
    const ilan = result.items.find((item) => item.chainKey === 'evo_ilan');
    expect(ilan?.collected).toBe(true);
    expect(ilan?.motherName).toBe('伊兰亚龙');
    expect(result.collected).toBe(1);
  });

  test('多形态精灵按形态分别统计', () => {
    const result = computeMotherCoverage(species, [mother(201)]);
    const spring = result.items.find((item) => item.chainKey === 'evo_bird_spring');
    const summer = result.items.find((item) => item.chainKey === 'evo_bird_summer');
    expect(spring?.collected).toBe(true);
    expect(summer?.collected).toBe(false);
    expect(spring?.formLabel).toBe('岚鸟 春天的样子');
  });

  test('只有公的不算母本', () => {
    const result = computeMotherCoverage(species, [male(103)]);
    expect(result.collected).toBe(0);
  });

  test('没有可孵蛋链时不除零', () => {
    const result = computeMotherCoverage([species[5]], []);
    expect(result.total).toBe(0);
    expect(result.collected).toBe(0);
  });
});
```

```ts
export type CoverageState = 'covered' | 'breedable' | 'missingStud' | 'empty';
export interface TargetNature { groupId: number; natureId: number; name: string }
export interface CoverageCell { groupId: number; natureId: number; natureName: string; state: CoverageState; owner?: string }
export interface StudCoverageResult {
  total: number;
  covered: number;
  cells: CoverageCell[];
  groupSummary: Array<{ groupId: number; covered: number; total: number; state: CoverageState }>;
}

  targets: TargetNature[],
  species: SpeciesEntry[],
  owned: OwnedPet[],
  eggGroupNames: Record<number, string>,
): StudCoverageResult;
```

- [ ] **Step 1: 写失败的测试** —— 覆盖四种状态各一条：
  - `covered`：存在同蛋组、同性格、大块头、满分、公的个体；
  - `breedable`：该蛋组有「大块头 + 满分 + 母」，且全局存在任意满分的公；
  - `missingStud`：该蛋组有满分个体，但既非大块头公也非大块头母；
  - `empty`：该蛋组没有任何满分个体。
  另加一条：**双蛋组精灵在两个蛋组都计入**。
- [ ] **Step 2: 运行测试确认失败** —— 预期模块不存在。
- [ ] **Step 3: 实现** —— 先按 `gameId` 把 owned 映射到图鉴条目；对每个目标按上面四条优先级判定；`groupSummary` 由该蛋组的 cells 聚合（全部 covered 才是 covered，有 breedable 次之，有 missingStud 再次，全 empty 才 empty）。
- [ ] **Step 4: 运行测试确认通过** —— 全部通过。
- [ ] **Step 5: 用真实数据核对** —— 目标 42 个、已覆盖 10 个（与设计文档一致）。
- [ ] **Step 6: 提交** —— `git commit -m "feat(domain): 种公覆盖度四态判定"`
