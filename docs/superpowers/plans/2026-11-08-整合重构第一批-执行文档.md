## 3. 各轨任务详情

### Track A · 埋点补齐

**目标**：换蛋核心链路 + 新计划功能的每个关键动作都有数据。事件只带数量与状态，不带内容（隐私口径与现状一致）。

新增事件（沿用 `src/api/analytics.ts` 现有通道，后端 events 表无需改结构）：

| 事件 | 触发时机 | 关键 props |
| --- | --- | --- |
| `demand_publish` | 发布需求成功 | demand 计数 |
| `demand_claim` | 认领成功 | demand 计数 |
| `demand_complete` | 结单成功 | demand 计数 |
| `demand_withdraw` | 撤回需求 | demand 计数 |
| `placement_mark` | 家园标记上窝 | 数量 |
| `group_join` | 加入小组成功 | — |
| `plan_create` | 手动创建计划 | 单条/批量标记 |
| `plan_import` | 批量导入缺口到计划 | 导入条数 |
| `plan_start` | 计划项从想收→进行中 | 计数 |
| `offer_mark` | 点「我能提供」 | 计数 |

验收：`npx vitest run`（A 涉及的测试文件）+ `npx tsc -b`；本地 `npm run preview` 手动触发 2~3 个事件确认上报。

### Track C · 收集计划功能（一期全部）

**C1 数据模型**（新 D1 表，风格对齐 `functions/schema.sql` 现有表；记得走 schema 门禁登记流程）：

`collection_plans`（组内可见的计划）：
- 字段建议：`id, group_id, member_id, chain_key/game_id（物种/链级目标）, note（可选自由备注）, status（backlog「想收」/ active「进行中」/ done）, demand_id（可选，关联的需求）, created_at, updated_at`
- 计划粒度为**物种/链级**，粗于需求的五字段；发需求时再细化

`plan_offers`（「我能提供」标记）：
- 字段建议：`id, plan_id, offer_member_id, note（自由文本，如「有现成的蛋，大概开朗」）, created_at, status（pending/seen）`
- 最轻版本：只产生标记 + 计划主人可见提示，不做智能匹配、不做撮合

**C2 「我的收集」页**（替代「我缺的」，宿主文件 `MotherGroupResources.tsx` 重构为分文件：列表/详情/发布/状态机，顺带处理 74 处文案）：

- 主视图：**进行中**计划卡（典型使用量 3~5 条，**仅作展示层收敛依据，不设数量上限**——2026-11-09 用户决策）——压力不回归的关键
- 「想收」折叠区 + 「批量导入全部缺口」入口（批量导入直接落 active，与「开始」一致；进行中不设上限）
- 计划卡操作：`开始`（backlog→active）/ `发需求`（按推荐性格预填五字段，用户微调）/ `完成` / `删除`
- **求助中计划卡的状态徽标流**（修复「需求漂走」问题）：`待接单 → {认领人}已认领 → 已上窝 → 待我确认 → 已完成`；「待我确认」高亮（需要发布人结单的时刻）
- 「我能提供」提示：别人对我的计划点了 offer，计划卡显示「{成员} 说有你要的」+ 备注一句
- 现有「我缺的」全量缺口列表降级为次要入口（「全部缺口」折叠/切换，供系统性盘货）

**C3 「组内广场」页**（替代需求中心 + 共同寻找）：

- 置顶：**「你能补的（N 条）」**——已发布资源 × 组内 active 计划的匹配计算（服务端算，注意与现有轮询/缓存机制整合）
- 「成员的计划」：浏览全部成员计划，每项可点「我能提供」+ 自由备注
- 「求助中的需求」：现有接单-上窝-结单闭环**完全不动**，仅列表迁入广场；增加「我发布的」筛选（发布人视角双保险）
- **共同寻找删除**：其「发现集体目标」价值由成员计划聚合继承（多人重复计划天然可见）

**C4 收集页-母本-未收集整合**：同一份计划数据，个人管理视角（「我的收集」为组内可见版，母本页为纯个人版），不再各算各的。

**C5 UI 原型先行（流程要求）**：「我的收集」主视图与「组内广场」的排版，先出可交互 HTML 给用户确认后再写代码。使用根目录 `需求卡-3列-布局编辑器.html` 模板体系（真实屏宽画布 + 整页预览 + 复制 JSON），交付本地文件 + 可访问预览 URL。

**C6 埋点对接**：计划四事件（plan_create / plan_import / plan_start / offer_mark）在功能内埋好，与 Track A 对齐事件名。

验收：单测 + 组件测试（新页面照现有 `*.test.tsx` 风格）+ e2e 主路径（创建计划→发需求→他人认领→结单→计划自动完成）+ `npx tsc -b` + functions 类型检查。
