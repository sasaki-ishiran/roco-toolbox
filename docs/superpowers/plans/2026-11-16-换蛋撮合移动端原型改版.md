# 换蛋撮合移动端高仿真原型改版 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 v3 换蛋撮合静态原型改成符合 375/390 移动端密度、项目图标资源与真实“需求方确认已收到”流程的高仿真 HTML 原型。

**Architecture:** 保留单文件静态原型与现有七屏演示切换结构，重写 CSS 的响应式容器、卡片网格和资源渲染，并把主链路收敛为“我要 → 匹配详情 → 需求方已收到”。s6 仅作为多单命中时的次级演示，不进入默认主链路。所有点击继续是本地演示状态，不接 API。

**Tech Stack:** 原生 HTML/CSS/JavaScript；现有 PNG 奖牌与绿窝资源；项目既有官方精灵头像 URL 约定。

**Spec:** 用户已确认的聊天设计：移动端高密度、移除“在哪见/几点/谁先给”、使用现有项目图标、需求方单边确认收货；同一种蛋的多个需求性格在一张需求卡内合并展示。

## Global Constraints

- 只改 `2026-11-15/换蛋撮合原型/editor/index.html` 与 `2026-11-15/换蛋撮合原型/outputs/index.html`。
- 不改 `src/`，不调真实接口，不写入 API Key。
- 不打包，不部署正式站或 test，不改 `latest.apk`、任何 `version.json`。
- 375 与 390 两种屏宽都必须检查；卡片不使用固定 375px 宽。
- 不自行删除已有产物；允许在本任务授权范围内更新这两个原型 HTML。
- 列表卡只保留蛋名、合并性格、体型/声音图标、现货/现孵、数量与状态；解释性规则放详情。
- 换蛋完成按钮只由需求方显示为“已收到”；供给方显示等待对方确认。

## Review Focus

- 375px 下两列需求卡、三列蛋仓卡不能横向溢出；由响应式布局回归检查覆盖。
- 390px 下卡片不能被拉成稀疏大横卡；由截图核对覆盖。
- 页面任何主链路卡片不能再出现“在哪见 / 几点 / 谁先给 / 约好一起上线”；由内容扫描测试覆盖。
- 体型/声音不能用纯文字替代图标，且绿窝必须走本地资源；由资源路径扫描测试覆盖。
- 同一种蛋的多性格必须保持一张需求卡、一个数量，不得渲染成两颗蛋；由 HTML 内容检查覆盖。
- 需求方点击“已收到”后状态必须变为“已完成”，供给方视角不出现第二个确认按钮；由脚本行为测试覆盖。

- Produces: 响应式 375/390 画布、两列主卡、三列蛋仓、真实图标渲染、无会议式交接字段的七屏原型。
