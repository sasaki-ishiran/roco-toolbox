## 1. 全局目标模式（追满分 / 追双牌）

领域事实（见 [数据字段说明](../../domain/数据字段说明.md)）：声音牌 = `|voiceDb| ≥ 96`（正婉转声 / 负粗嗓门）；
体型牌 = `大块头 / 小不点`；上游对四组合的叫法是 **大婉 / 小婉 / 大粗 / 小粗**。

- **档位 id 固定为 4 个**：`大婉 / 小婉 / 大粗 / 小粗`（不再以「满分大婉」当 id）。
- **显示名** `gradeLabel(id, mode)`：追满分 → 「满分大婉」；追双牌 → 「大婉」。
- **判定** `classifyGrade(pet, mode)`：两种模式都要求体型牌；
  追满分要求 `|dB| == 100`，追双牌要求 `|dB| ≥ 96`。
- **存储**：localStorage（本机）+ 写入备份；导入时**本机优先**（本机从未显式选过才采用备份里的值）。
- **开关位置**：看板顶部（与账号筛选并列）；覆盖度 / 换什么 / 我的精灵在标题处显示当前模式。
- **影响面**：覆盖度槽位与状态、种公列表与四档筛选、母本四档与合格判定、换蛋清单与复制文本的档位行、
  配窝建议、待补母本候选池。全部读同一个模式（不改数据的存储格式，判定实时计算）。
- 默认筛选档位不变：id `大婉`（追满分显示「满分大婉」，追双牌显示「大婉」）。

## 2. 「换什么」：列表项与复制格式

**列表项**：主文案 **`{性格}{显示名}`**（如「平和白发懒人」「固执雪绒鸟\_夏天的样子」）；
保留「补 N 组」徽标；第二行 `{档位} · {组1 × 组2}`（档位按模式显示）。

**复制**（`formatSwapWishes`）：

```
绿窝满分大婉
平和白发懒人
固执雪绒鸟_夏天的样子

普通窝满分小婉
……
```

- 组头 = `{绿窝|普通窝}{档位}`；行 = `{性格}{显示名}`；档位块之间空行。
- 领域：`SwapOption` 用 `displayName` 取代 `eggName`；`eggNameOf` / `eggName` 删除。
  `formatSwapWish`（单条）同步改新格式（aria-label 用）。

- **未收集 / 不够满分**：按蛋组拆的多个分节**撤掉**，合并为 §5 的「待补齐母本」候选区。

## 5. 「待补齐母本」待办

**解决的问题**：原先「该补哪些母本」只由系统在建议里代挑一条；改成用户自己挑目标并跟踪进度。

- **候选池**：按当前模式判定没有合格母本的链（无母本 ∪ 有母本但不够档）——「合格」= 该链有母本落在
  当前模式的 4 档里。
- **候选区**：标题「待补齐母本（N）」，**默认收起**；搜索框（显示名 / 图鉴号）；每行 = 勾选框 +
  显示名 + `#号` + 蛋组 + 现状（「无母本」/「现有母本不够满分」）；分页 20；已勾选的不再出现在候选里。
- **计划区**「计划收集（M）」置顶（M=0 不显示）：每行一条 + 移除按钮；已达成（该链已有合格母本）标绿
  「已达成」，提供「清除已达成」。
- **导入提示**：导入/合并后，计划里有链从不合格变合格 → `数据` 区提示「计划收集达成 N 个：A、B…」。
- **持久化**：localStorage（不进「重置导入数据」的清空范围）+ 写入备份；合并取并集。

## 6. 下一步建议与配窝建议

- **下一步建议**：最多 3 条纯文本 `去换{性格}{显示名}（{组1 × 组2}）`，按换蛋清单现有排序取前 3；
  取消「补齐母本」项；没有缺口时一行「当前没有要去换的缺口」。
- **配窝建议**：一次列 **≤6 条**，每条两行、默认一公一母：
  `{蛋组} · {性格} · {档位}` / `学院小窝 A 性别 dB ↔ 普通小窝 B 性别 dB`；
  无可配对时保留 `BREED_EMPTY_NOTE`。

## 9. 补丁：种公口径放宽（2026-10-03 晚）

用户报缺陷：小号的「满分小婉 · 懒散」梦游**不算种公**——导入报告不报、种公视角不列（原口径把
"性格 ∈ 该蛋组目标性格"当成了种公门槛）。

处置原则：**覆盖度的 slot 口径不动**——「组 × 性格 × 档位」里的性格是**目标本身**
（学院小窝那只必须带目标性格才能 100% 遗传），去掉它"还缺什么"就失去意义。
放宽的只是**名单与报告**：

- 种公视角：名单放宽为「公 + 档位达标」，性格降为**可选筛选**（八大性格池，多选）；
  覆盖目标数只用于排序与提示（「N 只 · 其中覆盖当前目标 M 只」）；
- 导入报告（`analyzeImport`）：不再按目标性格过滤，`naturesByGroup` 入参删除；
  档位达标的公一律列出（`groupLabels` = 它所属的可孵蛋组）；
- 回归：`importDiff.test.ts`（非目标性格的合格公必须列出）+ e2e `my-pets.spec.ts`、
  `dashboard.spec.ts` 各新增一条（fixture：`backup-offtarget-stud.json`）。
