## 1. P0：APK 里「导入抓包数据 / 导入备份 / 重置导入数据」按了没反应

### 诊断（已定位到代码）

三个按钮挂在同一个根因上：**壳从来没有设置 `WebChromeClient`**。

[MainActivity.java](file:///d:/desk/洛克工具箱/android-shell/app/src/main/java/com/localdatatool/toolbox/MainActivity.java#L81-L115) 里只 `new WebView(this)` + `setWebViewClient(...)` + `setJavaScriptEnabled` / `setDomStorageEnabled`，**没有 `setWebChromeClient`**。而：

| 按钮         | 走的原生回调                                                      | 没有 WebChromeClient 时                                                                                      |
| ------------ | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 导入抓包数据 | `<input type=file>.click()` → `WebChromeClient.onShowFileChooser` | 默认实现返回 false，文件选择器**根本不弹**，点上去没有任何反应                                               |
| 导入备份     | 同上                                                              | 同上                                                                                                         |
| 重置导入数据 | `window.confirm()` → `WebChromeClient.onJsConfirm`                | 默认实现返回 **false**，`confirm` 恒为假 → 函数在 `if (!confirmed) return;` 处直接早退，看起来像「按钮坏了」 |

**这不是本次网页改动引入的回归。** 壳只改了 `targetSdk` 那次（1.0.2）之后就没动过；而之前的真机验收清单里只列了「分享 JSON / 分享 .pcap」两条，这三个按钮从来**没在真机上验过**——`<input type=file>` 在桌面浏览器里正常，所以一直没暴露。

### 修复

在壳里补一个 `WebChromeClient`：

1. `onShowFileChooser`：用 `fileChooserParams.createIntent()` 起 `startActivityForResult`，在 `onActivityResult` 里回调 `filePathCallback.onReceiveValue(...)`；支持 `multiple`（网页侧两个 input 一个 multiple、一个单选）与 `accept` 类型。必须处理「用户取消」时返回 `null`，否则 WebView 会卡住不再响应下一次点击。
2. `onJsConfirm` / `onJsAlert`：用 `AlertDialog` 实现并把结果回给 `JsResult`；`onJsConfirm` 必须调 `confirm()`（不能只 `dismiss`），否则 JS 侧拿到 undefined。
3. 顺手加 `onPermissionRequest` 的拒绝实现（默认行为即可，显式写清避免以后踩坑）。

构建：`versionCode 5 → 6`、`versionName 1.1.1 → 1.1.2`（同 debug 签名，可覆盖安装，[build.gradle](file:///d:/desk/洛克工具箱/android-shell/app/build.gradle#L14-L15)）。环境按项目约定：JDK 21 / SDK 35 / NDK 28.2.13676358 / CMake 3.22.1。

> 注意：外壳修好前，APK 里**没法重置数据、也没法手动选备份文件**，只能靠采集器的「分享」把抓包送进来。

## 4. 换什么

### 4.1 展示改为「蛋名」

现状：一条显示「建议物种 + 组组合 + 性格」，复制出来是 `满分大婉平和白发懒人绿窝蛋`。

改为：显示与复制都用**蛋名**，形如 `雪绒鸟蛋（夏天的样子）`。

数据：已查过——

- 本地图鉴（`catalog.gen.json` / `pets.json` / `Index.lua`）**没有**蛋名字段；
- 上游 wiki **有**这类页面，标题规则是「{物种名}的蛋（物品）」（例：`雪绒鸟的蛋（物品）`），但页面内容只是空模板 `{{物品}}`，取不到权威显示名。

所以两种做法：

- **A（本次做，0 依赖）**：按规则推导 `{物种名}蛋`，有形态则 `（{形态}）` → 正好等于你举的例子 `雪绒鸟蛋（夏天的样子）`。风险：个别物种的蛋名可能不遵循这个规则。
- **B（后续单独立项）**：给数据管线加一个上游蛋道具模块的抓取，拿到权威名字。需要先确认 wiki 有没有对应的数据 Module（页面本身是空的）。

建议先做 A，B 作为后续。

### 4.2 复制文本聚合

现在每行都把「满分大婉」「绿窝蛋」重复一遍，几百行全是重复词。改为**按档位 + 窝类型分组，组内一行一个蛋**：

```
【满分大婉 · 绿窝蛋】
平和 雪绒鸟的蛋
固执 白发懒人的蛋
```

注意：**蛋名不带形态**。已核实（2026-10-03，见 [数据字段说明 §五](../../domain/数据字段说明.md)）：上游物品模块里 193 个精灵蛋，**0 条**带形态后缀 —— 「雪绒鸟的蛋（夏天的样子）」不是道具名，道具只有「雪绒鸟的蛋」。但**形态本身是可分辨的**（蛋记录带 `petConfId` → 解码器的 `eggConfigIdentities` 表直接给出 `雪绒鸟_夏天的样子`；每个形态的蛋还有各自的花纹图标），所以蛋神助手能分辨。形态不影响蛋组，换蛋时无需指定。

同一轮还修掉一个真问题：**蛋道具只存在于基础形态**（`stage === 1`；进化形态一个都没有蛋），而候选池原本没排除进化形态——候选从 532 收到 188，建议物种不再可能是「根本没有蛋的火神」。蛋名同时纠正为真实道具名 `{物种名}的蛋`（原来漏了「的」，写成 `火花蛋`）。

### 4.3 删掉「可选 N 种」

`optionCount` 对用户没有行动含义（顾问意见一致）：**直接删，不替代**。

## 9. 补充：我的精灵「种公 / 母本」两个视角的重做（同日）

用户追加「种公与母本的展示都需要做个优化」。原实现的两个问题与处置：

**种公视角**——原来只是一组固定标签（满分 + 大块头/小不点 + 公 + 性格∈八大池）筛出来的平铺列表：

**母本视角**——未收集是「该去抓什么」的清单，却把 200+ 条一次铺完、行里还看不到蛋组；已收集只有「满分大婉」+「其他满分档位」两节，与看板的四档计数口径不一致。

改为新增 [MotherView.tsx](file:///d:/desk/洛克工具箱/src/ui/MotherView.tsx)：

- 已收集拆成**满分四档各自一节**（与看板一致，满分大婉默认展开）；
- 未收集按**蛋组**折叠成多节（按未收集数降序），每节分页 20 条，行里带图鉴号与全部蛋组；
  双蛋组链只归入最小蛋组，不重复出现；
- 每一节都是「可折叠 + 分页」，默认收起（满分大婉例外），不再一进页面就被几百条铺满。

顺带清掉的死代码：`presetTagsForView`（种公视角改口径后无人引用）与其单测；`PetCard` 的「母本类型」冗余行。

## 10. 本次未做

- **【已确认待修 · 数据风险】APK 里「导出全部数据」失效**（2026-10-03 用户拍板「先验完这轮再修」）。
  [MainActivity.java](../../../android-shell/app/src/main/java/com/localdatatool/toolbox/MainActivity.java) 没有
  `setDownloadListener`、也没有 JavascriptInterface，而网页导出走的是 `blob:` + `<a download>`；
  WebView 对这种下载**静默忽略**，不保存也不报错。
  后果不止按钮坏了：APK 的数据在 WebView 私有目录（`/data/data/…/app_webview/`），
  **换手机浏览器打开同一网址也不行**（那是另一份存储），等于 APK 里的数据目前没有任何导出路径。
  修法（已定）：壳里加 JS 桥，原生用 **MediaStore.Downloads 写到系统下载目录**（Android 10+ 免存储权限，
  更低版本退回应用私有目录并在提示里说明路径）；网页检测到壳就走桥，普通浏览器仍走浏览器下载。
  版本 1.1.4（versionCode 8）——1.1.3 已先用于补「用其他应用打开」入口。
- **文案专项**：`breedPlan.reason`（长段机制解释）现在**没有任何界面渲染**，属于死代码，待清理；`MyPets` 母本视角原有的「只有满分母本才能…」提示段已随本次重写删除。

- `eggSize`（蛋重阈值）字段仍无消费方。
