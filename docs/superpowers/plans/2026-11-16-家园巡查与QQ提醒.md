# 家园巡查与 QQ 提醒实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 用户已选择当前会话直接执行，不派子代理；本计划供审核。

**Goal:** 在正式网页换蛋主流程发布前，补齐每半小时家园巡查和正确 QQ 群内的产蛋提醒。

**Architecture:** 云端保存 UID 巡查缓存、产出观察、群关联及通知队列；本机 RocomUID 插件主动拉取并通过 gs_subscribe 发送。纯解析模块不读网络或数据库，云端 API 处理鉴权、额度和并发，机器人仅负责本人多 UID 识别和订阅出站。生产迁移和网页发布在全部本地验收后执行。

**Tech Stack:** TypeScript / React / Cloudflare Pages Functions / D1；Python 3.12 / GsCore / APScheduler / gs_subscribe；Vitest / node:test / pytest / Playwright。

**Spec:** `docs/superpowers/specs/2026-11-16-家园巡查与QQ提醒-design.md`

## Global Constraints

- 唯一发布工作区：`D:/roco-build/egg-web-20261116`，基线 `9fbfec0`；主仓库混合改动不得整体加入提交。
- 每 UID 30 分钟缓存；每日总额 100 次真实第三方调用，失败也计数，额度先原子预占；北京时间自然日归零。每次超时 10 秒，同轮不重试。
- 一次性组码 10 分钟有效，只存摘要；工具箱组主发码，QQ 群管理员兑换；一个工具箱小组对应一个 QQ 群。
- QQ 取 RocomUser 全部显式绑定 UID（uid + home_uids），同一QQ支持多个UID；临时查询不参与。绑定按 bot_self_id 实例匹配，不填固定QQ。用户说明跨QQ重复UID不会发生，不新增常规冲突流程。
- 只巡查已接受、未结束现孵任务；现货、取消、完成、已分配实蛋的一侧不产生巡查需求。跨组同 UID 合并请求。
- 新蛋观察只触发提醒，不自动改上窝、交付和收货；需求方独自确认已收到。
- 不读取机器人 .env、data/config.json 或运行配置实体；凭据只从受限进程环境取得，不入库、不回显。
- 新 UI 仅做既有共用外壳内的接入弹窗与任务事实行；375/390 HTML 审核后再写 React。
- 两条负物种 ID 旧承接取消且保留历史，原表作为证据不删除；不臆造物种。
- 直接 main 正式网页，既有授权有效；不发 test/dev，不打 APK/EXE，不改 latest.apk/version.json，不删除产物。

## Review Focus

1. 首次巡查已有蛋、API 暂时返回不完整场景：不发新蛋提醒、不把错误当空基线。任务 1/3 覆盖。
2. 大整数 GUID 失真、当前配对变更：歧义不认领；当前候选不得标实际父母。任务 1 覆盖。
3. 并发巡查和跨组任务抢同一颗蛋：一次计费、一颗蛋只绑定一单；多单候选进入待分配。任务 3 覆盖。
4. 换群、离组、取消与通知领取并发：旧目标不再发送，领取和确认校验当前有效关联。任务 2/4 覆盖。
5. 发送成功但云端确认丢失、机器人重启：本地已发记录阻止再次发送，再补确认；离线不伪称成功。任务 4 覆盖。
