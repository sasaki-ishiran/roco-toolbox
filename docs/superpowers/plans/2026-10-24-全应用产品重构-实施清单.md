# 全应用产品重构实施清单

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 `executing-plans` 按任务逐项执行；只有用户另行选择子代理执行方式时才使用 `subagent-driven-development`。所有步骤用复选框记录状态。本文交给另一位 Agent 实施，计划作者本轮不实施产品代码。

**Goal:** 将应用整理为「看板／收集／小组／我的」，让新人导入后能看懂进度并找到具体补齐动作，同时保留熟手能力和已有数据。

**Architecture:** 先建立明确导航意图与兼容桥，再提炼少量基础控件，最后组合现有领域计算和业务组件形成四页。个人目标、局部查看条件、小组发布分别管理；不通过改算法、重置存储或自动公开数据来简化界面。

**Tech Stack:** React 18、TypeScript、Tailwind、Vite/PWA、IndexedDB、Vitest、Testing Library、Playwright；后端仍为 Cloudflare Pages Functions＋D1。

**Spec:** [已认可的全应用产品评审](../reviews/2026-10-24-全应用产品评审.md)。补充参考：[页面架构](../reviews/2026-10-24-产品评审-页面架构.md)、[控件规范](../reviews/2026-10-24-产品评审-控件规范.md)、[用户旅程](../reviews/2026-10-24-产品评审-用户旅程.md)。

## Global Constraints

- 用户已认可四入口方向；看板的母本收集与种公收集**同等重要**。
- 核心目标：「让收集变得轻松简单」。默认先展示进度／结果，再按需解释或编辑；高级能力仍有固定入口。
- 保留现有 React、Tailwind 和白卡片／翠绿风格；不默认新增路由库、状态库或整套 UI 库。
- 统一「组长」「游戏账号」「工具箱身份」「私有云同步」「发布我的资源」；「未收集」必须带个人或小组范围。
- 游戏账号范围、收集目标／达标条件、本页显示筛选分开；清除本页筛选不能清目标、其他视角、计划、复制勾选或发布草稿。
- 首轮不改领域算法、数据库 schema、旧 `roco.*` 键和云端合并优先级；不执行 D1 迁移。不得删除旧数据或初始化用户存储来通过测试。
- 个人母本与小组标准独立，允许数字不同。小组当前仍固定母＋大块头＋+100dB。
- 保留体型漏算修复、异色与普通色同口径、进化形态归蛋血脉、多号按人并集、未知不能算无人拥有。
- 个人计划是意向，收集达成来自导入事实；小组拥有来自已发布摘要。不得增加手工完成勾选冒充实际拥有。
- 母本共享二期共同未收集、认领、自选口径**不在本次实施范围**；不得只把现有全量目录改名「未收集」。
- 已入组的新建／加入表单保留在底部，切组保留在顶部。无本地数据仍能浏览已加入小组。
- 小组请求与轮询只在小组页面可见时运行；保留旧请求、旧身份、旧小组异步隔离保护。
- 系统分享／原生壳分享／手选文件／备份恢复都必须可用。导入本机、私有同步、小组发布分别反馈，不自动公开。
- 搜索独立于高级筛选；单选沿用看板页内展开样式；多选不自动收起；高频触区至少 44×44 CSS px。
- Windows 命令使用 PowerShell，Node 可用 `D:\nodejs`。不得修改或提交用户原有 `vite.config.ts` 改动。

## Review Focus

1. **旧版安装直接升级**：`roco.lastTab=swap` 且 `roco.swapView=sharing` 必须恢复小组；从看板点求蛋又必须准确进入求蛋。（任务 1、8、11）
2. **空选择与筛选交叉污染**：账号全取消仍可恢复；母本条件空数组表示该维度不限；种公目标空表示未设置；清全部库存筛选不清种公条件。（任务 4、5、11）
3. **导入成功后网络延迟／失败**：离开导入页、同步晚返回或 409 时不吞提示、不覆盖本机成功；分享事件只消费一次。（任务 6、11）
4. **同一身份的第二设备及缺本地共享账号**：恢复成员资格不新建成员，发布不静默撤回缺失账号，切身份不闪旧资源。（任务 9、11）
5. **有已知空资源与未知成员同时存在**：已发布成员无人持有不能被写成「全组没有」；离线缓存不是最新事实，未发布不是已集齐。（任务 4、9、11）

每一项都必须在所属任务加入可失败的断言，并在最终验收矩阵填证据。只写「已检查」不算完成。
