# 换蛋场景与覆盖度改造 · 方案

**日期**：2026-10-03
**状态**：已实施
**触发**：用户验收 1.1.1 时发现「换蛋」这条主线的输出粒度跑偏——给的是蛋组，玩家要的是精灵。

## 0. 产品定位（本轮重新确认）

目标不变：集齐精灵。路径不变：先补齐种公网络 → 之后每出一只新精灵只需一只母本 → 批量产蛋。

**变化的是路线：一律走换蛋。**

抓野生不再作为推荐路线。理由（用户确认）：抓一只满分大婉要自己迭代（满分只能由双满分父母产出），成本远高于直接跟人换蛋。因此：

- `catchable`（能否野外遇到）不再是任何候选的门槛，也不再是排序信号；
- 「能抓 vs 只能靠换」这个区分整体取消；
- 「去抓」从建议里退场。

**主场景重定义为**：**「我要孵 X」→ 找一只种公精灵**。单位是精灵，蛋组是精灵的属性，不是输出单位。

## 1. 已确认的决策（本轮）

| #   | 决策                                                 | 说明                                                                     |
| --- | ---------------------------------------------------- | ------------------------------------------------------------------------ |
| 1   | 路线一律换蛋                                         | 取消 `catchable` 门槛与「能抓/只能换」的区分                             |
| 2   | 「未拥有」= 该物种一只都没有                         | 按 `gameId` 严格比对；**仅参与排序**，不作硬门槛                         |
| 3   | 推荐性格保留，改为「组内筛选 + 默认勾选 + 标注推荐」 | 取消顶部的全局性格批量开关那一栏                                         |
| 4   | 明细与清单分工                                       | 明细只回答「我手里现在是什么状态、该怎么配」；清单只回答「我要去换什么」 |
| 5   | 普通窝 60% **只影响性格**遗传                        | 体型 / 声音 / 满分不受影响；仓库此前无此记录                             |
| 6   | UI 文案不解释玩家常识                                | 单开专项任务，不与本次功能改动混做                                       |

**为什么保留推荐性格**（用户说明的历史原因）：某些性格在某些组里几乎没用，例如巨灵组的「胆小」——该组 PVP 推荐里胆小根本不进前列。所以「每组推荐前 3」这个预设本身是有价值的，问题在于它被做成了**顶部的全局三态开关**，用户既看不懂当前是哪一态，也没法只改一组。改造方向是把它下沉到组内。

## 2. 改造设计

### A. 覆盖度筛选

**现状问题**（[coverageFilterStore.ts](file:///d:/desk/洛克工具箱/src/ui/coverageFilterStore.ts)、[CoverageFilterBar.tsx](file:///d:/desk/洛克工具箱/src/ui/CoverageFilterBar.tsx)）：

1. 顶部性格按钮是三态（全用 / 部分用 / 没用，`active` 与 `partial`），用户说不清当前状态；
2. 点一下是「对所有已勾蛋组批量加减」，做不到只改一组；
3. 分母随每组性格集合浮动，无法回答「14 组我通了几个」。

**改成**：

| 维度           | 现在                              | 改成                                                   |
| -------------- | --------------------------------- | ------------------------------------------------------ |
| 档位           | 4 多选，默认满分大婉              | 不变                                                   |
| 蛋组           | 14 多选，常驻展开                 | 14 多选，**默认收起**，点击展开                        |
| 性格           | 顶部全局三态开关 + 按蛋组各存一套 | **取消顶部那一栏**；下沉到蛋组展开区，作为组内筛选     |
| 组内性格默认值 | 推荐前 3                          | 推荐前 3（不变），但**标注「推荐」**，且可自由增减     |
| 主数字         | 已覆盖 N / 42                     | **已通 N / 14 组**（组内选中的性格全部达标才算「通」） |

性格数据流分两个来源，UI 上区分：**推荐**（来自 `targetNatures`，数据推导）与**用户手动添加**（从八大池里加的）。推荐项在组内筛选里加视觉标注。

### B. 覆盖度明细（bug 修复）

用户在真机上看到的：同组的六个性格格**全部显示同一只母本**「水滴蛇」，而「已有种公」那格根本看不到种公是谁。

根因：

1. `cell.stud` 领域层早已算出（[coverageDetail.ts:96](file:///d:/desk/洛克工具箱/src/domain/coverageDetail.ts#L96)、[coverageDetail.ts:127](file:///d:/desk/洛克工具箱/src/domain/coverageDetail.ts#L127)，连单测都覆盖了 [coverageDetail.test.ts:97](file:///d:/desk/洛克工具箱/src/domain/coverageDetail.test.ts#L97)），但 [CoverageMatrix.tsx:188-200](file:///d:/desk/洛克工具箱/src/ui/CoverageMatrix.tsx#L188-L200) **从未渲染 `stud`**；
2. `mother` 的定义是「该组同档位里第一只母」（[coverageDetail.ts:97](file:///d:/desk/洛克工具箱/src/domain/coverageDetail.ts#L97)），**不看性格、不看状态**，且被无条件渲染 → 同组所有性格格显示同一只；
3. `partner`（要配的那只异性）从未渲染，`academyParent` 那行也没写盒子位置。

**改成按状态渲染**：

| 状态         | 显示                                    | 现在错误地显示               |
| ------------ | --------------------------------------- | ---------------------------- |
| 已有种公     | **种公是谁**（账号 + 盒子）             | 一只无关母本                 |
| 有母本可孵   | 学院小窝放谁 + 普通小窝配谁（都带盒子） | 无关母本；partner 完全没渲染 |
| 有满分缺种公 | 那只满分母本（此时才有意义）            | 母本（碰巧对）               |
| 完全空白     | 不显示任何精灵                          | 无关母本                     |

### C. 求蛋清单（重写为物种级）

**现状**（原 `eggWishList.ts` / `EggWishListCard.tsx`，已删除）：每条是 `巨灵组平和满分大婉绿窝蛋`，输出单位是蛋组；只能全选复制或点单条复制，没有多选。

**实施后的形态**（[swapPlan.ts](file:///d:/desk/洛克工具箱/src/domain/swapPlan.ts) + [SwapWishCard.tsx](file:///d:/desk/洛克工具箱/src/ui/SwapWishCard.tsx)）：

| 项                 | 设计                                                                                   |
| ------------------ | -------------------------------------------------------------------------------------- |
| 单位               | **一条 = 要补的蛋组（1~2 个）× 性格 × 档位**，附一只建议物种                           |
| 为什么按组组合聚合 | 实测：按「物种 × 性格」逐条列最坏 2500+ 条；按组组合聚合后 277 条，其中「一顶二」86 条 |
| 复制标签           | `满分大婉平和白发懒人`（档位 + 性格 + 物种），按窝类型可加 `绿窝蛋` / `普通窝蛋`       |
| 建议物种           | 候选池 = 蛋组集合包含「要补的组」的全部可出公物种；取「未拥有 + 图鉴号最小」的那只     |
| 排序               | 能补的目标数降序 → 未拥有候选数降序 → 组 id → 性格 → 档位                              |
| 多选复制           | 每条带勾选框，全选 / 多选 / 取消；按钮在「复制全部」与「复制选中 N」之间切换           |
| 绿窝 / 普通窝      | 清单级开关，只影响复制出去的文本                                                       |
| 一蛋多目标         | 数字 = 该物种的组集合里、本性格 + 本档位下还没覆盖的组数；两组性格无交集时如实显示为 1 |

**落在哪**：只在「换什么」页（原「抓什么」页改造）。覆盖度页只保留矩阵与明细——清单最坏 277 条，放在矩阵上方会把矩阵挤到屏幕外，分工也不清。

### D. 「抓什么」页的处置（已定：方案 1）

`catchable` 退场后，「抓什么」页的排序依据就没了。**已实施方案 1**：把「抓什么」改造为「换什么」，
页签仍是 4 个（看板 / 我的精灵 / 覆盖度 / 换什么）。原 `catchPlan.ts`、`Catch.tsx`、`CatchList.tsx`、
`useCatchCandidates.ts` 与 `e2e/catch.spec.ts` 已删除，由同名的 swap 版本取代。

### E. 筛选控件外观

用户反馈：蛋组与性格占页面太多。改动：

- 蛋组、性格默认**收起**，点击标题行再展开；
- 控件尺寸整体缩小（当前 chip 是 `min-h-[40px]`，缩到 `min-h-[32px]` 一档）。

## 3. 领域规则入档

新增一条此前仓库完全没有的规则，写进 `docs/domain/` 与 design.md 的领域规则表：

| 规则           | 内容                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------ |
| 普通窝性格遗传 | **只影响性格**：60% 概率遗传到目标性格；体型、声音、满分判定不受影响（满分仍需双满分父母） |

这决定了「换普通窝蛋」的代价是「可能要孵几次赌性格」，而不是「体型也保不住」。
