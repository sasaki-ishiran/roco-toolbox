# 多人母本资源共享 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 用户已指定由其他模型执行、当前模型审查；执行者先阅读设计和本计划，不自行派发子代理。

**Goal:** 熟人以各自工具箱身份进入小组，发布自己的母本摘要，查看谁有自己缺的母本，帮助成员自行互换补齐母本全收集。

**Architecture:** 复用云端身份和游戏 UID；D1 按组、成员、共享游戏账号保存摘要。客户端从完整本地账号快照提取固定口径的母本覆盖；服务器只允许修改自己的摘要；覆盖与缺口按人实时派生，不保存交换任务或完成状态。

**Tech Stack:** Node >=22、React 18、TypeScript、Tailwind、Cloudflare Pages Functions + D1、Vitest、Testing Library、Playwright。用现有技术栈；新增精确开发依赖 Wrangler 4.151.3（本次通过 npm registry 核实，要求 Node >=22.0.0）。用本地 Wrangler 集成测试真实 SQL，不引入业务服务或新状态库。

**Spec:** `docs/superpowers/specs/2026-10-23-多人母本资源共享-design.md`。

## Global Constraints

- 一期固定达标口径为母 + 大块头 + +100dB，不限制性格；用户选择其他母本口径放到二期。
- 不创建交换订单，不记录提供者到接收者的任务、已收到、交换确认或分工归属。
- 按人汇总选中账号，保留来源账号；选择以游戏 UID 为键，不靠名字；无 UID 的旧账号必须重新导入后才能共享。
- 手动发布/更新资源；导入新数据只提示有变化，不自动上传共享资源。
- 每组最多 20 人，各组单独选择共享账号；一个游戏 UID 在一个组内只能由一个成员共享。
- 新共享入口允许无本地导入数据的用户进入；尚未发布是未知，不是缺少全部母本。
- 新资源从原始账号快照提取，不受顶部账号筛选、全站目标模式、母本筛选影响。
- 保留 `/api/list` 和旧双人清单，不自动迁移或删除旧状态。
- 共享结果不写入个人 IndexedDB 或私有云同步快照。
- 当前工作区已有 `vite.config.ts` 用户修改。执行前记录 diff；如需调整测试配置必须保留已有修改，不能还原或打包进无关提交。
- 本计划只获授权进行方案与交接；实施、远端建表和生产发布由后续执行阶段分别按会话授权处理。计划中的部署命令是操作说明，不代表已执行。

## Review Focus

1. 未发布、已发布空资源、图鉴不兼容必须区分；Task 1、5、6 的测试覆盖。
2. 新设备只持有部分选中账号、旧快照和同身份并发写不能造成静默资源丢失；Task 3、5 覆盖。
3. 非组员读、冒充他人写、同 UID 抢占及发布中途失败不能破坏原资源；Task 2、3、4 覆盖。
4. 退出/切身份/切组后晚到响应不能展示前一人的数据；Task 5、6 覆盖。
5. 本地 preview 没有 Functions，mock 浏览器测试不能替代 D1 与跨身份真实 API 测试；Task 2、7、8 分开取证。
