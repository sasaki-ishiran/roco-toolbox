# 里程碑 3：覆盖度矩阵与点名建议 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: 用 superpowers:subagent-driven-development 逐任务执行。步骤用复选框跟踪。

**Goal:** 把「知道缺什么」升级为「知道抓哪只、配哪一窝」——新增覆盖度四态矩阵、点名到物种的抓取清单、配窝建议。

**Architecture:** 沿用现有结构。领域层新增两个纯函数模块（抓取候选评分、配窝建议），界面层新增「覆盖度」与「抓什么」两个页签；看板的 3 条建议升级为点名到物种。

**Spec:** [2026-09-25-洛克工具箱-design.md](../specs/2026-09-25-洛克工具箱-design.md)（§7.2、§7.3）

## Global Constraints

- 移动优先，Android Chrome 为主；点击区 ≥ 44px。
- 无后端；账号数据只存手机本地 IndexedDB。
- 图鉴与账号数据连接键 `speciesPetId` ↔ `game_id`；禁止使用 `runtimePetId`。
- 母本计数单位 = `evolution_id`（形态级进化链，255 条）。
- 蛋组 1（未发现）必须排除。
- 分贝与体型判定只能来自抓包数据。
- 领域层纯函数不得 import React 或浏览器 API。
- TDD：先写失败测试，看到失败，再实现。

## 目标性格口径（本里程碑沿用，不在本期改动）

- **覆盖度分母仍为 42**（14 蛋组 × 数据推导的前 3 名）。
- 「急躁」作为**额外可接受性格**：不计入 42 个目标的分母，但出现在种公/母本列表的筛选中（已在里程碑 2 实现）。
  → 若用户要求把急躁也纳入每个蛋组的目标，分母会变成 56，属另一处一行配置的改动。

## Review Focus

1. 覆盖度矩阵里「有母本可孵」的判定必须用**优质母本**（大块头+满分），普通母本不算。
2. 抓取清单里的候选必须能野外抓（`ecology.areas` 非空）且能出公（`gender_ratio.male > 0`）。
3. 双蛋组候选要能一次补两个组的目标（交集性格），排序以"能补齐的**缺失**目标数"优先。
4. 图鉴未收录的 `game_id` 不得进入矩阵与清单，也不得让分母变化。
5. 空数据（零精灵）时三个页面都要有可读空状态，不崩、不出现 NaN。

**Interfaces:**

```ts
export interface CatchCandidate {
  gameId: number;
  name: string;
  number: string;
  form?: string;
  eggGroups: number[];          // 恰好两个可孵蛋组
  recommendedNature: string;    // PVP 推荐性格（图鉴侧）
  sharedNatures: string[];      // 两个蛋组共同的目标性格
  missingTargets: Array<{ groupId: number; natureId: number; natureName: string }>;
  catchable: boolean;           // ecology.areas 非空
}
export function rankCatchCandidates(input: {
  species: SpeciesEntry[];
  targetNatures: TargetNature[];
  coverage: StudCoverageResult;
  eggGroupNames: Record<number, string>;
  catchableGameIds: Set<number>;   // 由图鉴 ecology.areas 预先算出
  maleCapableGameIds: Set<number>; // gender_ratio.male > 0
}): CatchCandidate[];
```

- [ ] **Step 4: 运行确认通过** —— 新测试 + 全量 `npm test` 全绿。
