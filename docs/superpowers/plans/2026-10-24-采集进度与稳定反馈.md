# 采集进度与稳定反馈

目标：采集时能看到真实数据接收和解析进度，已识别内容持续稳定后提示停止保存，避免把空流量或未打开的页面误报为成功。用户已要求直接修复并上线，本轮沿用现有采集服务和 Worker，不新增领域解析算法。

1. [ ] 先写失败测试：角色/密钥/仓库详情/蛋仓缺失时不得进入就绪；心跳不重置内容稳定；同数量字段变化必须重置；会话切换、后台暂停和解析错误撤销旧判定。
2. [ ] 原生写入器发布已 flush 的完整记录边界；只读、限长、同源授权快照供后台 Worker 检查；旧 APK 继续可用。原文件仍不可在采集时导入/删除。
3. [ ] Worker 复用 extractPcap/inspectExtractedCapture 输出摘要和内容指纹；界面显示等待连接、等待登录、角色、精灵详情、蛋仓、稳定倒计时与可停止状态。不自动停采，不自动上传。
4. [ ] 前台每 3 秒检查快照，后台不运行网页解析；原生通知持续显示包数与大小。返回前台重新确认稳定，不能把后台等待直接算作已验证。
5. [ ] Vitest 全套、Playwright 全套、tsc、Android 单测/lint/build；核对生产部署与 APK 签名/版本。无法真机验证的项目如实注明。

上传边界：不提取/复用官方 APK 的应用凭据，不伪装原版发布身份。真实协议实验已被服务接受并返回去重记录，但本轮不发布该凭据驱动的直传功能。
