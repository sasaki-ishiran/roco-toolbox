# 入门、日常收集与跨设备协作评审

评审日期：2026-10-24。基于当前源码静态走查，未使用生产账号，未做真实用户研究或浏览器实测。以下“障碍”是依据界面结构推断的产品风险；验收数字是建议目标，不是已有测量结果。只写评审文档，不修改产品、Git 或部署。

使用 rock-kingdom-breeding-planner 技能核对资源池、已获得与计划的边界；当前实现的四档、满分/双牌与母本标准以代码为准，不套用技能中的默认性格或窝数。

## 1. 主要判断

工具已经能算出有用的答案，入门成本主要来自“先理解全部口径，才找到自己的下一步”。建议把第一次成功定义为：导入后能指出一个自己尚未收集的目标，知道可以找哪位组员、换哪种蛋或用已有资源怎么配，并把它加入计划。无需先读懂蛋组矩阵。

默认界面按“我的进度 → 下一步行动 → 需要时解释原因”展开。专家能力继续保留，目标口径、搜索、来源与更新时间必须可见；高级选项默认折叠，不改变既有统计事实。

用户已经同意的“组长”“未收集”和已有小组时新建/加入表单下沉是本轮约束，不计为新发现。小组二期讨论稿包含旧词与待定顺序，以本轮用户约定为准：先整理产品，再做二期；认领不等于拥有；未发布/不兼容不能算缺少。

## 2. 当前旅程与建议旅程

### 新用户：先看见价值，再学习规则

当前入口默认为导入页（`src/ui/lastTab.ts:15`），首次还会先显示最新更新，再显示五步教程（`src/data/changelog.ts:37`、`src/App.tsx:196`）。教程前两步已涉及种公、11 个窝、四档和推荐性格，第三步才说明怎么导入（`src/ui/GuideModal.tsx:18`、`:26`、`:34`）。导入页已有不错的基础：统一文件入口、无数据默认展开三步上手、错误紧跟按钮（`src/ui/ImportPanel.tsx:67`、`:408`、`:433`）。

建议旅程：

1. 首屏一句价值说明：“帮你查还缺什么，找到下一只该收的精灵。”主按钮“导入游戏数据”，次入口“已有恢复码，继续我的收集”。有邀请待办时展示“加入朋友的小组”；无文件用户可查看一张明确标注的静态示例，不创建示例收藏。
2. 无文件时展开“安装采集器 → 按提示采集 → 分享到工具箱”；文件导入与系统分享走同一业务入口。采集器获取方式必须是项目方确认的真实入口，不能临时编造下载地址。
3. 导入成功先显示“已保存到本机、包含哪些游戏账号、数据时间”，再给“查看我的收集”。分享路径可保留当前自动转看板；手选路径提供清晰的下一步按钮，用户主动留在数据管理页时不强制跳走。
4. 看板第一屏先展示进度和一个可执行的下一步。例：“你还没有达标的某母本；组内甲已发布，可查看来源账号”，或“已有一对资源可尝试孵出一个未完成目标”。推荐必须来自实际计算，不以计划当成拥有。
5. 第一次调整目标时再解释满分、双牌、体型和声音；第一次进入覆盖度时使用已有页内说明，不再要求完整重看五页教程。

保留手选、系统分享、备份恢复三条真实入口；不要求注册或入组后才能看到个人价值。

### 回访用户：回来继续做事，导入后知道变化

现有应用记住主页签（`src/App.tsx:93`）和换什么子视图（`src/ui/Swap.tsx:85`），这是应保留的连续性。看板已具备本次新增、双进度、推荐和配窝汇总（`src/ui/Dashboard.tsx:169`、`:225`、`:326`）。

建议日常闭环：“打开上次位置 → 看有无新变化/未发布更新 → 选一个计划 → 在游戏里获取 → 导入 → 实际达标后更新进度 → 按需发布给小组”。

看板承担“我的进度和下一步”，不是每次必须回来的首页。保留上次位置，不用新看板把正在查看小组的用户带走。顶部轻量显示“当前游戏账号范围、目标摘要、数据更新时间”；完整筛选和规则进入“调整目标”。无新增就显示“本次没有新增达标目标，可继续原计划”，不要营造导入失败感。

推荐分成可解释的行动入口：“找组员补齐”“查看建议换蛋”“用已有资源配窝”。排序依据在重构时单独确定，不未经用户确认就把某一种收集方式设为绝对优先；无适用资源时不显示空的主行动。

### 跨设备：一个工具箱身份，多个游戏账号

当前恢复码登录会合并云端数据（`src/ui/AccountPanel.tsx:128`），立即同步已经实现拉取、合并、推回（`:147`）。这是可以继续使用的简化基础。

建议“我的”页分三块，但维持原有功能兼容：

- 工具箱身份：本人身份/设备登录、恢复码保存和换设备恢复。已有身份用户先恢复，首次用户才创建。
- 游戏数据：已导入哪些游戏账号、UID、数据时间、导入、备份。明确同名游戏账号用 UID 区分。
- 私有云同步：上次成功时间、当前结果、立即同步；高级数据操作折叠。

新设备流程：“输入原恢复码 → 恢复相同工具箱身份 → 合并游戏数据 → 恢复小组成员资格 → 回原小组”。本机缺少某个已共享游戏账号时，先同步/导入补齐，不自动撤回该账号；现有编辑器的保护要保留（`src/ui/MotherResourceEditor.tsx:219`）。

### 小组：先找到有用资源，再管理发布

当前即使无本地数据也可进入母本共享（`src/ui/Swap.tsx:118`），登录解释已明确同一人可跨设备（`src/ui/MotherSharing.tsx:40`）。当前发布编辑器却整体排在资源结果前（`:138`、`:146`）。

建议入组后先显示小组状态和可浏览的资源；本人尚未发布时展示短引导“先选共享游戏账号，发布后计算我缺的”，按钮打开编辑器。已发布日常状态只保留“共享 N 个游戏账号 · N 种母本 · 更新时间 · 管理”；有变化才突出“预览并更新”。维护账号、预览增减与撤回不删除，按状态展开。

个人导入/私有同步成功后，若共享摘要实际发生变化，在当前结果处提示“已保存到本机；你的小组资源尚未更新”，点击进入预览。不自动公开数据，不把“已同步”当作“组员已可见”。每组只提示受影响的一份共享范围，不用泛化的一键广播覆盖所有组。

小组二期的共同未收集列表，应分“已确认组内未收集”和“待确认”；全量目录保留次入口。当前 `MotherGroupResources` 的 all 是全目标目录，不能只换标题就当作任务清单。二期认领仅代表寻找分工，获得必须由导入并发布的达标事实证明。

## 4. 默认值与上下文帮助

- 不修改已选目标；首次沿用当前产品默认，并用可见摘要说明，不凭技能默认改成加速度/加生命或五窝。当前满分默认见 `src/ui/targetModeStore.ts:23`。若未来要给不同玩家预设，先让用户选择且可返回旧配置。
- 首次个人母本仍看“未收集”（现有 `src/ui/MotherView.tsx:206`）；已收集和计划都可一键切换。计划标注“想收，不计入已收集”，达成只能由实际数据确认；现有“清除已达成”保留（`:419`）。
- 普通查看默认显示少量推荐及简明理由，完整推荐、四档、矩阵、配窝图逐级展开；不要求先看完详细图才能选择一个目标。
- 查看缺口时固定显示计算范围：“我的：已选 N 个游戏账号 / 本组：已发布 N 人，另 M 人待确认”。离线、过期和版本不一致不能显示为已验证的新事实；组离线提示已有基础（`src/ui/MotherSharing.tsx:129`）。
- 同步前后若云端口径改变，说明“目标标准已随云端更新，刷新后重新计算”，而不只写“补上缺的设置”。实际口径类键是云端覆盖本机（`src/api/sync.ts:45`、`:188`），用户需要知道分数为什么变。
- 无匹配、无数据、全已收集、本人未发布、存在未知成员、离线旧结果使用不同空态；给就地动作“清除查看筛选”“导入”“发布”“更新”“重试”。目前通用空态只解决无数据（`src/ui/EmptyState.tsx:19`），母本无匹配只显示一句话（`src/ui/MotherView.tsx:463`）。

## 5. 产品词汇与事实边界

| 用词 | 应表达的含义 | 避免误解 |
| --- | --- | --- |
| 工具箱身份 | 同一个人的私有身份、恢复码与小组成员身份；手机和电脑可用同一份 | 不等于某一个游戏账号，也不以昵称识别人 |
| 游戏账号 | 导入数据来源，以游戏 UID 为稳定标识；一个人可有多个号 | 导入别人备份不自动表示对方成为组员 |
| 私有云同步 | 同一个工具箱身份的游戏数据与部分设置跨设备合并 | 同步成功不等于发布给小组 |
| 发布/更新我的资源 | 将自己明确选中的游戏账号的达标摘要向指定小组开放 | 修改选号只是草稿；私有导入不自动撤回或公开 |
| 组长 | 创建/管理小组的成员称呼，采用用户批准的新词 | 不给组长虚构当前不存在的转让、认领管理能力 |
| 我的未收集 | 我的有效数据中，没有符合“我的收集标准”的目标 | 可能已有同种但未达标；不等于全组没有 |
| 已确认组内未收集 | 全体相关成员均已发布且可比较，当前无人持有达标资源 | 只要有人未知就不能下这个结论 |
| 待确认 | 未发布、停止共享、图鉴/口径不兼容等，信息不足 | 不能当作未收集计入确定共同缺口；也不等于组员一定没有 |
| 已收集 | 指定范围、口径下有实际导入/发布的达标资源 | 计划、认领、愿望、配对方案都不算 |
| 计划收集 | 自己想优先完成的目标 | 可撤销的意向，不改变收藏进度 |
| 认领（二期） | 一位成员负责寻找某项已确认共同缺口 | 不证明拥有；某人获取发布后，其他人的个人缺口仍存在 |
| 小组资源目录 | 当前全部收集目标与拥有者/未知者信息 | 当前目录不是已经实现的共同未收集任务队列 |
| 可迭代 | 当前资源可组成尝试孵化目标的方案 | 不保证概率成功，不直接增加已收集进度 |

“未收集”可以统一用词，但必须带范围；“待确认”保持独立状态，不能只变颜色或放进解释末尾。

## 6. 可以执行的验收任务

以下为重构后的验收目标，不代表当前通过率或真实用户数据。用可复现的合成数据和未登录/已登录/离线状态完成测试；新手任务可在后续邀请未接触过工具的人验证，不将本次静态评审包装成用户测试。

| 场景 | 建议验收目标 |
| --- | --- |
| 无文件新用户，360px 手机宽度 | 首屏能说出工具用途；不关闭五步教程也能到达导入/采集器帮助；不要求先决定档位。经确认的采集器入口可达 |
| 手选与系统分享分别导入同一份数据 | 两条路径得到相同收藏事实；都能从成功结果进入进度，并指出一个具体下一步。主流程最多一次显式点击到达计算结果 |
| 只想收母本的新用户 | 不进入覆盖矩阵也能找到一个未收集母本、查看标准并加入计划；加入计划后已收集数不变 |
| 回访且原来停在小组 | 重开保持小组上下文；无需滚过展开的账号编辑表单就能看到资源；保留搜索与结果范围的可理解提示 |
| 手机 A 有两个游戏账号，电脑 B 有一个 | B 恢复相同身份后仍是同一位组员；合并保留合法本机独有账号；缺少已共享账号时不发生静默撤回 |
| 导入新增达标母本，已经开启云同步并加入两组 | 成功结果分别说明本机、私有云端、小组发布状态；未点发布前两组都看不到新摘要；只更新选择的组 |
| 三人组：甲乙有效且无布灵，丙未发布 | 显示“待确认，另 1 人待发布/更新”，不能写“全组未收集”；丙发布且仍无人持有后才可确认共同缺口 |
| 二期：甲认领布灵，随后导入并发布 | 认领阶段甲的收藏数不增；发布后目录出现甲的来源；乙丙仍在个人未收集中看到布灵及甲这个来源 |
| 个人标准含小不点，小组标准只含大块头 | 同一小不点母本可在个人达标、组内不达标；两个页面都能直接看到当前标准与差异原因 |
| 无结果、全已集齐、本人未发布、离线、同步失败 | 五种情况不能共享同一句空态；每种给出相关下一步，离线数据注明旧结果且不被误算成不存在 |

若后续加入埋点，优先衡量“从导入成功到首次查看具体缺口/加入计划”“从导入到完成发布预览”“跨设备恢复后再次到达原组”，分别统计新/回访与失败原因。现有事件基础是 `src/App.tsx:88`、`src/ui/ImportPanel.tsx:99`、`src/ui/AccountPanel.tsx:159`；本次不推断转化率，不采集背包内容证明产品价值。

## 7. 简化的风险、替代方案与优先顺序

两个可选方向：A 是保留五页签，只补摘要、直达按钮、按状态折叠与上下文帮助，迁移成本低、可以先改善首次成功；B 是按收集目标合并导航、引入“我的”身份数据页，理解成本更低，但要迁移页签存储、深链、说明与筛选职责。建议先完成 A 的状态/术语边界和成功闭环，再结合全局架构评审实施 B，避免导航先变、内容仍是旧结构。

最高价值的五项改进：

1. **让导入直接通向第一条行动。** 补采集器真实入口、成功结果和进度直达；成本低到中，不改领域算法。
2. **把专家选项放到进度后面。** 摘要常显，编辑按需；保留旧目标、已选账号及完整矩阵/配窝能力。风险是隐藏有效能力，因此每张推荐保留“为什么/查看完整”入口。
3. **拆清工具箱身份、游戏账号、私有同步、组发布。** 可以用“我的”承担身份和数据管理；必须同步修改全局教程/空态/跳转文案，旧导入路径保留兼容。
4. **让小组先展示结果，发布按状态引导。** 既有用户不反复选号；首次/变更/缺数据时仍完整预览。不能为了简化删除缺号保护或自动发布隐私数据。
5. **用明确范围保护收集事实。** 个人和本组标准分别显示，“未收集/待确认/计划”不合并。为二期的共同缺口、认领与口径迁移建立可复用状态说明，当前不提前宣称认领已实现。

不能以“简单”为由抹掉来源账号、数据时间、口径差异、未知成员与预览移除数量。这些信息决定建议是否可执行、事实是否可信；应以简短摘要与逐步展开呈现。
