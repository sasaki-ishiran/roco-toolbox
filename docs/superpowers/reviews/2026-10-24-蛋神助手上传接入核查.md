# 蛋神助手上传接入核查

状态：已完成源码核查和用户授权样本的真实协议实验；工具箱产品尚未接入第三方上传。本报告不记录应用凭据或用户抓包内容。此前人工导出、网页账号导入与辅助操作方案均已被用户否决，不作为后续实施路线。

## 协议证据

来源：用户提供的 android-collector-1.2.6-source/android-collector。

- CaptureUploadClient 使用 HTTPS POST /v3/captures/upload，原始 PCAP 二进制体，application/octet-stream，不是 multipart；原包请求上限 5 MiB。
- 请求含采集时间、SHA256、应用凭据及发布信息；源码从构建环境读取凭据，没有默认值。官方分发 APK 内存在非空应用凭据，解释了原版无需用户登录。
- 受理后持久保存 captureId，通过 GET /v3/captures/<captureId> 查询；仅 persisted 且有有效游戏 UID 才能报告入库。网络不明的 POST 不应盲目自动重发。
- CaptureUploadManager 实际走原包上传；另有 gzip 解析 JSON 方法，但工具箱精简备份不能直接当作其完整上传格式。

## 真实实验及结论限度

用户提供约 1.07 MiB 的真实 PCAP 并明确允许上传尝试。使用工具箱发布标识的 POST 遇到连接错误，没有 HTTP 响应或任务 ID；该结果不能证明断开原因，也不能断定服务器未收到请求。此前使用工具箱标识查询随机不存在任务时得到 HTTP 426，是另一条独立证据。

使用官方发布身份的请求得到 HTTP 200，返回 persisted、有效 UID、accepted=true、deduplicated=true；一次后续 GET 确认同一已入库任务。去重说明该内容已有记录，证明请求被接受并返回已有入库记录，不能声称本次新建了数据或已验收蛋交易。

实验脚本错误地对 Python st_mtime 再除以 1000，导致提交的采集时间不正确。服务端返回的是既有去重记录的时间，本次实验不能用于验证时间字段是否正确接收。后续正常实现应直接使用秒转时间，或明确使用毫秒时间戳；不重复本次 POST。

官方发布身份和版本另由源码构建配置确认；临时 DEX 字段读取器对 BOOLEAN 编码有缺陷，不能把该脚本的所有后续字段当成可靠证据。

## 产品边界与本轮结果

协议技术可行与凭据适用范围是两件事。开源许可证允许的代码复用不自动授予第三方服务器或应用凭据的使用权；也不能一概说所有第三方接入都要作者单独书面批准。当前没有可用于工具箱自身身份的上传配置，本轮不提取/复用官方 APK 的凭据、不冒用原版发布身份封装上线。

本轮继续完成用户独立提出的采集进度优化：只读实时快照、Worker 解析摘要、完整性检查与内容稳定倒计时。该功能不包含上传，不能宣称已完成“一次采集、两边可用”。用户明确要求本次不发公告，不增加 changelog 条目或更新弹窗。

后续若使用适用于工具箱的接入配置，应保留原包流式上传、5 MiB 校验、独立的本机/第三方状态、任务持久化续查、文件删除锁与真实 UID 核对；HTTP 200、mock 测试或数据入库均不能替代交易端验收。
