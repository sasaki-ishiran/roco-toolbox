# 多人母本资源共享：执行交接与审查清单

状态：规划材料，尚未实施。用户分工：其他模型实施，本会话方案模型审查。

## 交给执行模型的任务说明

先阅读：

1. 仓库根目录 `AGENTS.md`。
2. `docs/superpowers/specs/2026-10-23-多人母本资源共享-design.md`。
3. `docs/superpowers/plans/2026-10-23-多人母本资源共享.md`。

目标是熟人小组互看达标母本和个人缺口，帮助大家在游戏内自行协商互换。母本资源按人汇总、多游戏账号保留来源、多设备复用工具箱身份。一期固定母 + 大块头 + +100dB，不限制性格。自选口径二期做。

实现里不要增加交易订单、配对交换任务、收蛋确认、认领或完成勾选。资源更新来自真实导入数据和用户主动发布。查看小组不需要本地导入数据。

执行前检查工作区；规划时已有 `vite.config.ts` 未提交修改，不能还原或覆盖。不要用之前交接里的 354 个单测、61 个 e2e 作为本次结果。

## 三批交付

| 批次 | 内容 | 提交审查的最低材料 |
| --- | --- | --- |
| 第一批 | Task 1–4：领域、D1、认证 API | 提交列表、完整 diff、领域测试、真实本地 D1/API 输出、错误码与事务证明 |
| 第二批 | Task 5–6：客户端、会话隔离、资源页面 | diff、组件和 hook 测试、身份切换/冲突/未知状态证据、页面截图 |

每批审查发现阻断问题时，执行模型先修复，附上针对发现的新增断言与真实输出。不得仅回复“已处理”。审查者必须再次查看实际 diff 和测试证据，不能把执行者自评当验证。

## 第一批审查

- [ ] 母本判断复用 `isQualifiedMother`；目标单位是当前代码的 `eggGameId`；不按旧进化链文档重新设计。
- [ ] 纯母物种仍能计入母本资源；不能复用“能出公”筛选误排。
- [ ] 按账号快照及 UID 关联，重名账号、改名、同人多个号稳定；无 UID 有明确引导。
- [ ] 不读取全局筛选后的 `useOwnedPets()` 作为共享输入。
- [ ] 未发布、停止共享、已发布但无达标母本、版本不兼容四种状态明确。
- [ ] 各成员资源独立持久化，无整组 JSON 覆盖、无客户端自报写入成员身份。
- [ ] 资源替换包含删除，CAS 失败不会继续删除/插入，UID 冲突整批回滚。
- [ ] 老导出时间和同源矛盾内容被拒绝；同原始数据在新图鉴重新计算允许发布。
- [ ] 同 UID 同组互斥、不同组可共享；冲突错误不会泄露非组员数据。
- [ ] 人数上限和邀请码有效性落在数据库写条件，重置与加入竞态不会绕过规则。
- [ ] 普通成员退出、组主解散、账号注销级联行为经真实 D1 验证。
- [ ] 请求体限制按 UTF-8 字节计算，未信任 Content-Length；数量、类型和字符串长度验证完整。
- [ ] 认证响应 no-store、DELETE CORS 正常、身份限流不被同公网其他人挤占。
- [ ] 只在随机临时本地库测试，测试 runner 不会指向线上；清理路径与子进程 PID 可验证。

## 执行模型回报格式

每批报告按以下字段填写实际内容：

1. 分支/工作目录、起止提交、改动文件清单。
2. 已实现的设计条款和 S 编号。
3. 与方案不同的地方及原因；没有差异就写“无”。
4. 每条验证命令、退出码、测试数量、失败信息及原始日志位置。
5. 页面截图、真实 API/D1 验证、跨身份验证的证据路径。
6. 尚未做的项目与阻塞条件；没有执行的部署不能写成完成。
7. 数据库与发布状态：本地/test/生产分别说明。

## 审查模型回报格式

先列可行动的问题，每项给出严重程度、绝对文件路径与具体行号、触发条件、实际影响和建议验证。不为凑数提出样式偏好，不要求新增超出一期的交易功能。

- P0：数据泄漏、越权、可造成广泛不可恢复的数据破坏；立即阻断。
- P1：多人覆盖算错、资源静默丢失、身份串用、主要流程不可用、迁移不兼容；修复后再进入下一阶段。
- P2：特定失败路径、刷新/可恢复状态问题、重要文案误导；给出复现和修复建议。
- P3：局部可用性与维护问题；不掩盖更高优先级问题。

没有发现时明确“本次审查未发现需要修改的问题”，同时说明实际审查范围和没有验证的环节；不保证绝对无缺陷。修复轮逐条对照发现清单复审。
