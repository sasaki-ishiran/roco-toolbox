# 竞品评审：蛋神助手（2026-10-26）

> 状态：评审完成，结论已归档。对策已追加到 [优化升级规划](../plans/2026-10-26-优化升级规划.md) §11。
> 评审方式：三个独立视角（游戏策划 / 收集型玩家 / 同行开发者）各自只读审查，再由主评审复核本地解包材料、公开社区证据与用户口述。
> **没有**注册、下单、操作市集、接触后台或做真机验收；涉及市集与机器人的结论均标注来源与置信度。

## 0. 一页结论

**蛋神助手不是「一个孵蛋工具」，而是「采集入口 + 云端数据银行 + 蛋交易市集 + 机器人履约 + 积分账本 + 产线留存」的组合体。**
它的护城河不是 30 多个页面，也不是配窝算法，而是**交易流动性、机器人运力、积分清算和产线留存**。

| 维度        | 蛋神助手                                              | 洛克工具箱                                    | 差距判断                                 |
| ----------- | ----------------------------------------------------- | --------------------------------------------- | ---------------------------------------- |
| 定位        | 交易履约 + 数据银行                                   | 孵蛋决策 + 私域协作                           | **定位差异**，不是谁替代谁               |
| 首次可用    | 微信即开，市集可零数据使用                            | 必须先导入文件；84% 设备从未导入              | **能力差距（P0）**                       |
| 规划深度    | 有智能配窝/种公阵列/收集目标/产线，但深度未被独立验证 | 配窝几何 1:1、M1 多路径、覆盖矩阵、多账号     | **本项目优势**，但要防被补齐             |
| 交易/履约   | 真市集 + 机器人进家园取放 + 积分                      | 复制文本到群聊                                | **不追的差距**（自建市集/机器人）        |
| 留存        | 产线计数、生蛋提醒、远行商人、签到、市集稀缺          | 本次新增、7 天未导入黄条、changelog           | **能力差距（P0/P1）**                    |
| 信任/隐私   | 云端 + 扫码凭证 + 机器人；积分可调、封号/开庭不透明   | 本地优先、可导出；但第三方上传/匿名口径有硬伤 | **本项目可打赢的差异**，先修自己的不一致 |
| 合规/可持续 | 机器人履约与游戏 ToS 高度耦合；bus factor ≈1.5        | 中风险；bus factor = 1                        | **本项目相对安全**，但都很脆             |
| 综合        | 产品力约 78 / 玩家体验 66 / 竞争位置 76               | 健康度 66 / 玩家 62 / 竞争位置 56             | **不同尺子，不能直接排名**               |

**三句话：**

1. 蛋神助手赢在「找货、拿货、定目标」，尤其把**非标蛋变成可检索 SKU + 机器人履约**；这是本项目没有的最后一公里。
2. 洛克工具箱赢在「算得准、说得清、数据在自己手里、熟人协作」；但首次转化和回访钩子太弱，价值只服务 13 台导入设备。
3. 正确姿态是**互补而非对撞**：学它的「产线化、零门槛、需求单」，不学它的「市集、积分、机器人、账号池」。

## 2. 竞品全景

### 2.1 多端与服务拓扑

**【事实】** 竞品至少覆盖五类入口：

| 端                      | 形态                                                      | 作用                                           |
| ----------------------- | --------------------------------------------------------- | ---------------------------------------------- |
| 微信小程序              | 本地快照注册 32 条路由；底部 3 个 Tab：主页 / 背包 / 家园 | 市集、查蛋、图鉴、社区、积分、个人资产的主入口 |
| Web 版                  | 同一套小程序 runtime 导出到浏览器                         | 分享、PC 浏览器、未装小程序用户                |
| 原生 App / Capacitor 壳 | SecureSession、OTA 资源包、应用内更新、本机采集桥         | 移动端体验、离线资源                           |
| Android 采集器          | VpnService + zdtun + TCP/8195 + PCAP + 本机解析           | 把游戏数据变成云端快照                         |
| PC 客户端               | PyInstaller 打包（约 55 MB）                              | 历史采集入口；玩家评价差                       |
| iOS 中继                | 旧版采集链路存在 Relay                                    | 补 iOS 采集，但不是当前主路径                  |

**【事实】** 服务侧至少包括：

- `api.danking.cn/miniapp/api`：小程序与 Web 的业务 API（自建云兼容层，页面仍用 `wx.cloud.callFunction` 形状，底层改为 `wx.request`）。
- `capture.danking.cn:18443/capture-api`：采集上传与查询。
- `collector-features`：手机功能会话、查询、扫码、提醒、远行商人代理。
- `roco-miniapp-bot-core`：查询核心、机器人、VIP、积分结算。
- QQ 机器人：远行商人到货、查蛋提醒等站外触达。
- NAS / 容器 / SQLite：低成本自托管，也是单点。

**【推断】** 这是一个「移动端主产品 + 采集器管道 + 云端数据银行 + 机器人履约」的分层架构。它的多端不是每个端都强，而是每个端承担不同漏斗环节。

### 2.2 页面清单：广度是表象

**【事实】** 本地快照注册的 32 条路由，按用途可分为：

| 类别            | 页面                                                                                                             |
| --------------- | ---------------------------------------------------------------------------------------------------------------- |
| 主页/社区/交易  | 主页、广场搜索（`exchange/market`）、点赞排行、黑号查询、联名机器人管理、管理员后台                              |
| 积分/会员       | 积分管理、积分流水、会员服务                                                                                     |
| 收集/规划       | 种公母库、种公阵列、智能配窝、收集目标、迭代路线、蛋蛋鉴定、精灵图鉴、仓库、蛋分组详情、家园、角色背包、点阵背包 |
| 收集 meta       | 炫彩色卡、色卡统计、彩球模拟、闪卡收藏、炫彩花种                                                                 |
| 采集/账号       | 账号授权与采集、角色背包选择器                                                                                   |
| 疑似素材/工具页 | 两个「洛克换蛋」标题页、图片缓存、玻璃素材页                                                                     |

**【事实】** 底部 Tab 实际是 **主页 / 背包 / 家园**（`/pages/community/community`、`/pages/backpack/backpack`、`/pages/my/my`），不是 community/home/market；市集是主页里的功能页，不是一级 Tab。

**【事实】** 小程序写操作白名单有 25 个，包含：

`saveInventory`、`createCollectionCard`、`deleteCollectionCard`、`updateCollectionCardEffects`、`saveCollectionTarget`、`importCollectionTargetWants`、`saveWarehouseAccount`、`saveBreedingCollection`、`saveManualEgg`、`deleteManualEgg`、`saveCommunityProfile`、`checkInPoints`、`startRewardedAd`、`createAppLinkCode`、`completeRewardedAd`、`submitBlacklistReport`、`syncCommunityDecorations`、`redeemCommunityCode`、`likeCommunityProfile`、`reservePoints`、`commitPoints`、`refundPoints`、`reportListing`、`uploadFile`、`deleteFile`。

**【推断】** 广度的真实构成：

- **真需求**：采集/快照、市集、产线、生蛋提醒、远行商人、图鉴/查蛋、黑号。
- **半真**：种公母库/智能配窝/迭代路线（有用，但不是交易用户的核心）、色卡/闪卡/彩球（收集 meta，内容成本高）。
- **运营/装饰**：点赞排行、联名机器人、管理员后台、会员服务、两个素材页。

NGA 玩家原话「我只用这个买蛋弄产线，其他功能没用过，不评价」基本说明：**撑住产品的是市集 + 产线 + 提醒 + 采集，其余是长尾。**

### 2.3 五条核心循环

```
[采集/解析] → [云端快照] → [收集目标/产线] → [配窝/种公] → [生蛋/收蛋]
                                      ↓
                              [市集上架/购买]
                                      ↓
                          [机器人进家园取/放蛋]
                                      ↓
                              [积分/手续费结算]
                                      ↓
                          [签到/提醒/商人/点赞] → 回访
```

1. **数据循环**：采集 → 本机解析/完整性 → 上传 → 云端落库 → 小程序读取。
2. **交易循环**：市集筛选 → 上架/购买 → 机器人取放 → 积分结算。
3. **目标循环**：收集目标 → 产线 → 配窝/种公 → 生蛋 → 产线完成 → 解锁头像框/称号。
4. **治理循环**：举报 → 开庭/封号 → 黑名单 → 交易信任。
5. **内容循环**：图鉴/鉴定/色卡/闪卡/点赞 → 炫耀与回访。

**【判断】** 交易和产线是发动机；内容是装饰；治理是刹车和安全带。

### 2.4 市集与机器人履约（核心护城河）

**【社区 + 用户口述】** 市集流程：

1. 打开市集，按蛋种、性格、奖牌（满声、大块头等）筛选。
2. 卖家上架：把蛋放到自己家园或角落；平台机器人来取/验。
3. 买家购买：用积分下单；机器人把蛋放到买家家园（或约定位置）。
4. 买卖双方要避开路人，否则蛋可能被路人拿走。
5. 平台结算积分、扣手续费；异常走举报/开庭。

**【社区】** NGA 玩家原话：

> 「上架和购买都是机器人，最好自己家园或者没人角落里上架或者收蛋，不然被路人拿走了。」
> 「蛋神助手查蛋是让机器人进家园查看的（名称大概是大反派 n 号）。」

**【事实】** 小程序有 `reportListing`、`submitBlacklistReport`、`likeCommunityProfile`、`reservePoints/commitPoints/refundPoints` 等写操作，说明举报、黑名单、点赞、积分预扣/结算/退款都是真实能力。

**【推断】** 市集的难点不是 UI，而是**履约确定性**：

- 机器人能否稳定进家园、准确取/放指定的蛋；
- 如何防止路人截胡；
- 如何处理“标错/歪蛋/没声音”的纠纷；
- 如何在炸服时保证订单不丢。

这四点决定了它是「真市集」还是「挂单板」。从玩家反馈看，它已经跑通了基本履约，但稳定性与争议处理仍是软肋。

### 2.5 积分经济

**【事实】** 采集器维护交接文档写明：

- VIP 在生蛋查询、自动生蛋查询、花种查询中不扣积分；
- 非 VIP 手动生蛋查询按成功 UID 每次 1 积分，定时查蛋每 UID 每次 0.5 积分；
- 失败不收费，重试复用同一任务，不重复扣费。

**【事实】** 小程序写操作含签到（`checkInPoints`）、激励广告（`startRewardedAd/completeRewardedAd`）、社区兑换码（`redeemCommunityCode`）、积分预扣/提交/退款。

**【社区】** 新用户约 688 积分；签到、卖蛋得积分；买蛋/采集/查询花积分；失败退回；手续费按上架颗数比例收取；管理员可调积分；压力测试发过两百多万积分。

**【推断】**

- **积分是负债，不是收入**。手续费是回收机制，VIP/广告/赞助才可能是现金流。
- 积分的可信度取决于发行纪律；管理员可调分 + 通胀 + 手续费，会让用户天然怀疑「我是不是被当成猪」。
- 「大婉泛滥、冷门小粗好卖」说明积分经济是**稀缺性经济**，不是努力经济；选错产线就是库存。

### 2.6 产线与留存

**【事实】** 小程序有「收集目标」「产线」相关页面与写操作（`saveCollectionTarget`、`importCollectionTargetWants`、`saveBreedingCollection`）；个人主页显示「已完成 X 条，共 Y 条产线」；按产线数量解锁头像框/称号（1 条、100 条）。

**【社区】** 玩家按「沉默果冻水蓝蓝」「急躁狮鹫」「开朗红岚鸟」等目标开产线；产线最好用满声大块头父母本。

**【判断】** **产线是竞品最强的留存单位**：

- 可命名：这是我的产线，不是平台的矩阵。
- 可计数：已完成 X / 共 Y，天然进度条。
- 可完成：每完成一条有正反馈。
- 可炫耀：产线数量解锁装饰/称号。
- 可交易：产线产出的蛋可以上架。

本项目有覆盖矩阵、配窝、换什么，但**没有把目标包装成用户能数得清、能完成的「产线」**。这是最值得学的一点。

### 2.7 治理与风控

**【事实】** 小程序有黑号查询、举报、点赞、管理员后台入口（仅 `isAdmin` 可见）。

**【社区】** 非满分标满分会被封号；绿窝蛋歪了被举报「开庭」也会封号；RMT 被禁止；管理员可调积分；手续费进平台号。

**【推断】** 治理是运营能力，不是代码能力：

- 代码只提供举报、黑名单、后台入口；
- 真正难的是规则、证据链、申诉、执行和社区信任；
- 一旦「开庭/封号」不透明，用户会把平台当成风险源，而不是保障。

### 2.8 工程与数据流

**【事实】** 采集器 1.2.4 README：

- 原生 Java 本机解析，完整性检查通过后**只上传 gzip 压缩字段**；不含 Python 运行环境。
- 本机原包上限 128 MiB；导入上限 512 MiB；压缩请求上限 5 MiB；展开字段上限 16 MiB。
- Android 8+，三种 ABI，16 KiB 页对齐；支持游戏内悬浮窗提示。
- 1.2.4 底部只保留「采集 / 角色 / 文件 / 赞助」，移除功能页入口。

**【事实】** 本机 1.2.6 源码中 `CaptureUploadManager.run()` 仍调用 `client.upload(file, listener)`（原始 PCAP），`uploadParsed()` 只有定义、没有调用点。

**【判断】** 这说明竞品的上传策略存在**版本/分支差异**：公开说明称只传字段，源码主路径仍传原包。不能简单认定「它只传字段」；也说明其内部也在向「少传原始数据」演进。

**【事实】** 其他工程能力：

- 采集只接管目标游戏（`com.tencent.nrc`），只记录 TCP/8195。
- 完整性判定：从登录前开始、角色/盒子/队伍/蛋分页/握手/丢包/截断。
- 上传任务持久化 `captureId`，失败只续查不重发。
- 服务端每 30 分钟查询；首次只建基准；按蛋 ID 差量提醒。
- Android `JobScheduler` 15 分钟拉取提醒。
- 远行商人货架使用独立长轮询（上游 26 秒、读超时 35 秒），避免阻塞查蛋/扫码。
- 发布有正式签名、更新通道、SHA-256、源码归档。

**【判断】** 工程成熟度高于多数个人项目；但架构是「单 NAS + SQLite + 容器 + 机器人」的重运营结构，扩展性受履约约束。

### 2.9 稳定性与口碑

**【社区】**

- 「就是服务器总崩溃」「我求求你别宣传了，炸了好几天了」。
- 「PC 端简直就是一坨，只能做采集器」。
- 「管理员可以后台给自己调积分」的担忧。
- 「非满分标满分会封号」「绿窝蛋歪了开庭封号」的恐惧。

**【判断】** 竞品的口碑是「好用但可怕」：交易效率和流动性极强，但稳定性、透明度和账号风险让玩家一边用一边担心。

**关键判断：**

1. **它是一个真产品，不是堆出来的小程序。** 市集、产线、提醒、采集四条线都有人用，且互相增强。
2. **增长不靠页面数，靠流动性。** 卖家越多，买家越容易成交；买家越多，卖家越愿意来。
3. **最大风险不在产品，在治理。** 积分可调、封号/开庭不透明、炸服、机器人依赖游戏容忍度。
4. **不能照抄。** 抄页面没用；抄闭环需要机器人运力、清算规则、争议处理和 7×24 运维。
5. **最值得学的是产线化**：把「我想要」变成「已完成 X / 共 Y」，这是本项目最缺的可完成感。

## 5. 差距的本质

### 5.1 流动性 vs 决策深度

- 蛋神助手解决「**去哪里买到/换到**」；洛克工具箱解决「**我该孵什么/还缺什么/怎么配**」。
- 交易层需要双边网络、机器人运力、积分清算、争议处理；决策层需要数据、算法、可信度、协作。
- **交易层是重运营，决策层是重知识**。项目应该做自己擅长的重知识，不要背重运营。

### 5.2 最后一公里

- 玩家在项目里算出「缺 3 个蛋组」，然后要：
  1. 手动记住缺口；
  2. 去群里喊 / 去市集搜；
  3. 重新输入物种、性格、体型、声音；
  4. 赌对方靠谱；
  5. 换到后回来重新导入。
- **最痛的不是「没有市集」，而是「我知道缺什么，却要重新输入一遍、再赌一次对方靠不靠谱」。**
- 项目能做的是把「需求」结构化，降低这 5 步的摩擦；不需要自己接管交易。

### 5.3 信任 vs 效率

- 蛋神助手用「机器人 + 积分 + 平台裁判」换效率；代价是机器人进家、凭证托管、积分不透明、封号恐惧。
- 洛克工具箱用「本地优先 + 可解释 + 熟人协作」换安心；代价是门槛高、无流动性、无履约。
- **两者不是谁更安全，而是风险类型不同**：竞品是「账号/资产/合规风险」，项目是「单点维护/转化/合规披露风险」。

### 5.4 数据资产 vs 数据主权

- 竞品的资产在平台：快照、积分、订单、信用、用户网络。
- 项目的资产在用户：本地数据、导出、自己的规划。
- **项目不应为了数据飞轮放弃本地优先**；可以做 opt-in 的脱敏摘要/小组共享，但不做中心化数据银行。

## 6. 该学 / 不该学 / 不能学

### 6.1 只学 3 件事（+1 个信任补充）

**第一件：产线化（最高优先）**

把覆盖度矩阵从「一张图」变成用户可命名、可计数、可完成的目标集合：

- 字段：名称、目标精灵/蛋组、性格、奖牌、目标数量、优先级、状态。
- 首页显示「已完成 X 条 / 共 Y 条产线」。
- 每条产线展开：缺口 + 配窝方案 + 求蛋卡。
- 完成时给本地/组内徽章，不搞积分。

**为什么**：这是竞品最强的留存单位，也是项目最缺的「可完成感」。项目已有 `collectionTargets`、`coverageMatrix`、`swapPlan`、`nestPlan`，只差包装。

**第二件：零门槛首值**

- 空态提供 3 条示例产线，用真实 fixture 在内存里跑完整计算。
- 明确标注「示例数据，不保存」；禁止写库/自动发布/云同步。
- 导入成功后给「看我还缺什么 →」，不自动跳页。
- iOS 明确「让朋友代导一份」。

**为什么**：竞品市集在无自有数据时也能用；项目 84% 设备从未导入。这是产品结构问题，不是功能问题。

**第三件：履约化需求（不求成交）**

- 求蛋卡：蛋种 / 性格 / 体型 / 声音 / 数量 / 优先级 / 可回礼 / 数据版本。
- 一键复制到群、深链到现有市集/兑换码、回填「已换到」。
- 组内记录「我帮过谁 / 谁帮我」。
- 不承诺成交，不接管交付，不做自动下单。

**为什么**：竞品护城河是履约，不是列表；项目不需要造机器人，只需要把需求结构化，让现有市集/群去履约。

**+1 信任补充：验蛋清单**

- 交易前 checklist：声音 dB、体型、性格、绿窝、父母本、截图/录屏、对方 ID。
- 本地交易笔记 + 「验蛋卡」。
- 可选组内共享笔记；**不做全局黑名单/公开裁判**。

**为什么**：信息不对称是交易层最大的坑；项目不能当裁判，但可以让玩家「交易前知道看什么、交易后留得下证据」。

### 6.2 不该学

- 30 多页的广度、色卡/闪卡/彩球模拟、点赞排行、会员墙。
- PC 客户端 / 多端功能对齐（除非有真实桌面需求）。
- 管理员后台 / 联名机器人 / 黑号全局库。
- 用积分/手续费做核心留存。
- 把采集器做成第二个主产品（竞品 1.2.4 已经把采集器收窄为管道，这是正确方向）。

### 6.3 不能学（合规红线）

- **不自建机器人/账号池/进家园取放蛋/自动收蛋**：官方公告明确打击第三方工具、脚本、账号共享、扫码代练，10 年封禁、设备封禁。
- **不做批量注册/多开/设备农场**：黑产特征，设备封禁。
- **不做积分交易所/托管/提现/RMT**：虚拟货币与 RMT 边界，平台审核与诈骗风险。
- **不逆向对抗/绕过反作弊/复用竞品凭据**：技术、法律、账号风险；对方随时可收紧。
- **不默认上传原包/不隐瞒数据去向**：本地优先是项目的信任底座。
- **不冒充官方/不承诺「100% 满分」/不替卖家背书**：预测不是孵化结果。

### 8.2 本项目风险（在竞品对照下更清楚）

- 首次转化 16%、只开一次 74%：不修，永远只有 13 台核心设备。

- 无流动性：算完还要去别处交易。
- 第三方上传/匿名口径/无隐私政策：信任硬伤。
- bus factor = 1：项目本身比竞品更脆，只是失败方式更安静。
