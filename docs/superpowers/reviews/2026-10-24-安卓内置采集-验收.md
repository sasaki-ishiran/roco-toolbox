# 安卓内置采集接入验收

状态：实现与桌面验证完成，产物可安装；**采集功能尚未合并 main、尚未发布配套网页，真机采集未验收**。分支 `codex/android-collector`，基线 `21762da`。原重构修复的生产版本不受本次工作影响。

## 已接入的闭环

我的 → 游戏数据 → 本机采集 → 系统 VPN 授权 → 打开官方游戏 → 重新登录并查看仓库、背包、蛋仓 → 返回停止并保存 → 明确点解析并导入。原包保留，可重复导入、导出或确认删除；私有同步沿用用户设置，小组仍手动发布。

仅路由 `com.tencent.nrc`，TCP/8195 写入标准 Ethernet PCAP。没有原作者云端、令牌、升级、会员或悬浮窗组件。采集 API26+；应用 minSdk23 保留。采集桥还要求系统 WebView 支持 WebMessageListener 与 DocumentStartScript，不支持时保留手动导入，不显示不可用的采集按钮。

单文件128MiB，最多10文件；不会自动删除。创建时同步写入 incomplete 标记；正常停止排空队列并 flush/fsync/close 后才移除。丢包、超限、中断或保存失败的文件仍可导出，不能当作正常原包一键导入。保存完成不等于游戏数据完整，界面不声称全收齐。

原生通过 FileInputStream 返回随机令牌 URL；Worker 直接读取 URL 并调用现有解析器，不在 Java 或页面主线程持有整包 byte[]/Base64。外部 PCAP/JSON 分享和备份导入保持可用。

## 尚未验证与下一步

`adb devices -l` 没有设备。以下不能宣称通过：Android 实际 WebMessage 回调与文件流、系统 VPN 授权取消/撤销、真实游戏 TCP 转发与 DNS、从登录握手解码、OEM 后台限制、实际覆盖安装保留数据及低内存128MiB压力表现。桌面模拟和静态检查均不替代这些证据。

真机验收顺序：

1. 发布配套网页后，覆盖安装新 APK，确认原账号及设置保留；网页与旧 APK 仍可导入。
2. 开始采集，取消 VPN 授权，应回到可重试状态；再次授权并开始。
3. 重新登录游戏，查看仓库、背包和蛋仓；观察游戏联网、包计数与后台通知。
4. 用页面与通知栏分别停止，确认等保存完成才可导入；导入后核对 UID、仓库/背包个体及蛋数。
5. 导出 PCAP 再在电脑导入，结果应一致；重复导入不新增重复账号，原包保留。
6. 测试撤销 VPN、切后台、系统中止与连续启停；异常文件保留且禁止直接导入，旧文件不自动删除。
7. 删除先取消再确认；确认只删原包、不删已导入账号。检查私有同步与小组发布仍分别反馈。

发布决策尚未执行。配套网页可独立回滚到上次生产部署 `81e2d040`；回滚网页会隐藏新入口，原生原包仍在应用私有目录。原生不建议降 versionCode 覆盖安装，应以更高版本发布修复或让用户导出原包。
