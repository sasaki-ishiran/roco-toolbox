## 3. 三方复评

### 3.1 策划视角：65 → 70（+5）

**加分来自：**
1. **需求五字段 + 严格结单**：把「发出去」变成「可验收」，D1 首次出现 4 单 done。
2. **产线判据**：从「组内有人有这只」升级为「组内有人能产 蛋×档位×性格」，减少空发需求。
3. **小组统一 + 组页精简 + 7 天软校验**：去掉种公组的空转，避免「别人没更新 → 误判组内没有」。

**最被高估：**
- **种公阵列**：把已有推荐换成 蛋组×性格 表格，新决策有限，390px 下横滚 + 小字号。
- **家园 Tab**：只读快照，不执行操作；对 82% 未导入用户仍是空态。

**仍未解决：** P0 几乎全在；导入率 16%→18%、只开一次 74%→73%，属噪声级；增长 ≈0，留存增益只落在 15 台已导入设备。

**一句话：** 65→70，「已导入用户更深更可信（需求首次闭环），未导入用户几乎无感」——深度 +5，广度 0。

### 3.2 玩家视角：62 → 66（+4）

**真变好：**
- 严格结单：避免「对方说给了、其实不对」。
- 一键结单：导入时本机确有匹配个体才提醒，省去翻需求中心。
- 成员移除 + 每人「已结 N 单」：组长能清长期不更新的成员，互助有可见记录。
- 头像/稀有度/奖牌：列表更好认。
- 种公阵列：一眼看出「这一格有哪几只」。

**只是「看起来新」：**
- 家园 Tab 只展示，不做摆位；与「配窝建议」是两套配对，界面没说明以哪套为准。
- 产线没有可浏览的清单，只用于后台判断「组内能不能产」，玩家感知不到「产线」是什么。
- 种公阵列横向滑动 + 极小字号，手机阅读成本高。

**首次上手：没有改善。** 首启仍落「我的 · 游戏数据」，空态仍无示例，导入后仍无「看我还缺什么」；D1 18% 导入 / 73% 只开一次，对比 16% / 74% 基本原地。

**社交闭环：部分成立。** 36 单 → 8 接单（22%）→ 4 结单（11%）。结单提醒方向对，但接单方没有回执、没有「我帮过谁」；一键结单只服务需求方。

**旧问题：** 已换到不联动、配窝图不可照着摆、百分比口径不清，均未解决。

**一句话：** 62→66；安卓 + 已装壳 + 在跑小组的老玩家更愿意推荐；对第一次问「这怎么用」的人仍不推荐。

### 3.3 同行视角：74 → 78（+4）

**最硬的改进：**
1. **H12/H13 并发修复**：种公发布 CAS + `EXISTS(config.target_revision)`；认领成功后复核覆盖并关任务（`collectionGroupsStore.ts`）。
2. **额度修复**：需求额度排除 `done`，完成释放额度（H8）。
3. **产线抽成纯域**：无副作用、前后端共用，有上限（1024 线/30 性格）。

**最危险/最被高估：**
- **`MotherGroupResources.tsx` 1808 行**（上次 916），且 `CollectionGroups.tsx:198` 用 `hook={hook as never}` 绕过类型；旧 `useMotherGroups` 仍是生产类型契约，双栈没死。
- **H1/H2/H4 的种公部分**：10-27 已删种公组，修完即废弃；43 条里约 25 条是 UI 状态类。
- **`completeCollectionDemand` 仍未检查 0 行更新**（`collectionGroupsStore.ts:1866-1887`），与 release 的 CAS 不对称。

**审核质量：** 纪律好（回滚断点、复跑记录、API 33 条含并发抢名额）；真正数据/并发约 10/43（H8/H11/H12/H13/H6/M1/M2/M3/M8/M18）。

**测试：** 788 单测、47 管线；**Playwright 仍 88 条，家园/阵列/产线/需求条件零 e2e**。新 UI 只经 jsdom + mock，真实 D1 + Pages + PWA 未验。

**代码 78，线上仍 74**：生产旧版、D1 已跑 10-27 破坏性迁移；用户可感知提升 ≈0。
