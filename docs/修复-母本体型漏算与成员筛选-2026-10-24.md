# 母本体型漏算与成员筛选修复

## 范围

## 根因与实现

- 布灵、布灵布灵等采集图鉴条目的 `adultSmallWeight/adultBigWeight` 为空，原解析器将体型记为空，达标母本因此被排除；异色并非排除条件。
- `src/shared/bodySize.js` 统一成体体重判定：保留已有专用阈值，缺失时用本形态成体区间的 2%／98% 边界补算。不能混用蛋重；也不依据舍入后的 `weightPercent` 猜测体型。缺失、零、非法体重不判为小不点。
- 内置 PCAP 解析与 JSON 导入均接入。图鉴管线烘焙 `bodySize`；任一可孵物种缺少阈值就拒绝覆盖已有产物。目前可孵形态全部覆盖。
- 成员筛选此前同时接受拥有／缺少／未知，形成恒真条件。现在「我缺的／小组资源」按所选成员持有资源过滤；「我能补谁」按其已确认缺口过滤，未知成员不能当成缺少。
- 下拉栏按看板「满分大婉」的页内展开样式实现，支持点击外部、Esc 收起和键盘焦点返回，不增加 UI 库依赖。

## 已有数据

本次没有直接修改本机 IndexedDB、云同步快照或小组已发布摘要。已保存的旧快照没有精确体重字段，不能可靠自动恢复。修复上线后建议重新采集并导入，再手动更新共享资源。

旧采集 JSON 若保留 `weightGrams` 或 `weightKg`，重新导入可恢复体型；但服务器可能对相同导出时间、相同图鉴版本的覆盖变化返回 `SOURCE_MISMATCH`。这种情况下应重新采集取得新导出时间，不绕过服务端旧源保护。

## 第 2—4 项追加修复

### 第 2 项：图鉴更新后无法重新发布

原按钮仅比较账号与覆盖，覆盖相同就禁用；成员状态却按图鉴版本判断，造成「需更新」但更新不了。现在同时核对图鉴、口径及摘要格式版本；覆盖相同但版本变化仍能更新。覆盖差异计算保持原语义，不因时间或名字变化重复提示。

### 第 3 项：旧异步请求写回新身份或小组

- 列表、详情、手动刷新、403/404 后补拉列表统一保护会话作用域。详情还检查小组切换次数和请求顺序，切走再切回也不接纳旧详情。
- 创建/加入、发布、昵称、重置邀请码、退出/解散均在异步返回后核对发起作用域。
- 发布中修改同组选号时保留新草稿；旧组发布成功不清空新组草稿。
- 表单按身份重新创建，资源面板按身份与小组重新创建；旧发布面板卸载后不触发新小组刷新。
- 同根因扩展到认证：旧请求的 401，以及旧退出/注销请求，不得清掉后来登录的新身份。当前凭证真正失效时仍正常退出。

### 第 4 项：本机缺失的共享账号无法撤回

显示本地快照与服务器已发布账号的并集；缺失项明确标「本机无数据」，仍可取消/选回。取消只是草稿，预览并发布后才撤回。取消全部沿用确认后的停止共享；不自动缩小共享范围。
