# 验收清单：导入后「本次新增」

**这一版新增**：导入抓包数据后，看板顶部多一张「本次导入新增 · 符合看板分类」卡片。
它只列**这次新抓到的、够格进看板分类的**精灵——种公（大块头 + 100dB + 公 + 该蛋组目标性格）
和母本（满分大婉 / 大婉 / 大粗 / 小婉 / 小粗），并标出**在哪个账号的哪个盒子**。

按你的口径定的三条规则：

1. 卡片**按账号分组**（一次导入多个账号就分几组）。
2. **不报精灵总数**（数量会因放生波动，说明不了进度），只列合要求的。
3. 每条都带位置，例如「火花 · 固执 · 魔力组/巨灵组 · 100dB · 盒子01 第3位」。

## 你手动验收的 7 项

| # | 操作 | 预期结果 |
|---|---|---|
| 1 | 「看板」点「导入抓包数据」，随便导一个账号 | 按钮下面立刻出现「本次导入新增 · 符合看板分类」卡片 |
| 2 | 一次导入多个账号文件 | 卡片**按账号分组**；某账号没有合要求的精灵时，那组写「没有新增符合要求的精灵。」 |
| 3 | 看新增种公那一行 | 形如「火花 · 固执 · 魔力组/巨灵组 · 100dB · 盒子01 第3位」——标出蛋组和盒子位置 |
| 4 | 看新增母本 | 按「满分大婉 / 大婉 / 大粗 / 小婉 / 小粗」分档，每档标出只数，每条带位置 |
| 5 | **同一份文件再导入一次** | 卡片变成「本次导入没有新增符合看板分类的精灵。」——老精灵不会被误判成新抓的 |
| 6 | 点卡片右上角「收起」 | 卡片消失（下次导入会重新出现） |
| 7 | 切到别的页签再切回「看板」 | 卡片还在；点「重置导入数据」后卡片消失 |

## 一个说明：升级后的第一次导入

判定「哪些是新抓的」靠抓包里的唯一编号（`capture_<账号>_<序号>`）。
你升级前已经导进本机的数据**没有**这个编号，所以升级后的**第一次**导入会用
「物种 + 性别 + 性格 + 分贝 + 体型 + 体重」的内容指纹来比对——正常情况下结果一样准，
只有当两只精灵这些字段完全相同才可能偏差。那次导入完成后编号就存进去了，之后都是精确比对。

首次导入一个**全新账号**时，它已有的合格精灵会全部列出来（标着「首次导入」），
这是有意的——让你一眼看到这个号本来就有哪些底子。

## 顺带修的一个坑：部署后不用再手动刷新

你反馈"刚导入没显示卡片"，排查下来功能本身是好的——你打开的是**部署前被
Service Worker 缓存下来的旧页面**，跑的还是没有这张卡片的旧代码；手动刷新后就好了。

这是每次部署都会踩的坑，所以这次一并处理了：

1. **页面顶部现在显示版本 + 构建时间**（如 `版本 2026-09-26 17:40`）。
   下次怀疑"是不是没生效"，先看这行——没有这行就说明打开的是旧页面。
2. **新版本接管时自动刷新一次**：部署后你只要重新打开/切回这个应用，
   它会自己换成最新版，不用再手动刷新（首次安装时不会白白多刷一下）。

验收：顶部能看到 `版本 YYYY-MM-DD HH:MM`；把它和我每次部署完报的时间对一下就知道是不是最新版。
