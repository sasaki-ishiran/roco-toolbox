# 手机端悬浮窗 · 面板规格（实现基线 v1）

> **依据**：`手机悬浮窗原型.html`（2026-11-08 冻结版）。本文所有数值都是从该原型在 375×812 与 390×844 下用 Playwright 读 `getBoundingClientRect()` / `getComputedStyle()` 得到的实测值，不是另算的一套。
> **用途**：安卓壳（系统浮窗）与网页端对齐的唯一依据。原型改动必须回写本文；两者冲突时以原型为准。
> **边界**：本文只描述悬浮窗自身。小地图选 B（内嵌网页地图 `public/maps/10003.webp`）；不做点击穿透；明暗主题跟 PC 端。

---

## 0. 坐标与单位

- 所有 px 为 **CSS 逻辑像素**，1:1 还原，不做 DPR 换算、不做等比缩放。
- 「屏幕坐标」以屏幕内容区左上角为原点（不含状态栏 / 安全区），下文 left/top 均指此坐标系。
- 「面板内坐标」以**面板内容盒**左上角为原点（= 面板 border-box 左上角 + 1px 边框）。
- 基准屏 375×812（内容区），兼容屏 390×844。下文未标注 390 的数值，两屏完全相同（固定值）。

## 1. 尺寸与间距表

### 1.1 面板容器

| 项 | 值 | 说明 |
| --- | --- | --- |
| 宽 | **268** | 两屏固定，不随屏宽变化 |
| 高 | 见 1.2 公式 | 随「命中区有无数据 + 列表条数」变化 |
| 圆角 | 12 | |
| 边框 | 1px | 颜色见 2.1 |
| 内边距 | 0 | 内部区域各自定位，靠容器 padding=0 保证 |
| 溢出 | hidden | 圆角裁切，列表绝不滚动/溢出 |
| 阴影 | `0 14px 36px rgba(0,0,0,.45)` | |
| 贴边距 | **8** | 面板最外侧与屏幕边缘恒为 8；面板与球也恒为 8 |

### 1.2 面板高度公式（375 / 390 相同）

```
hitH    = 命中区高度：有命中数据 64；命中区无数据 45；不显示命中区 0
listH   = n*30 + (n-1)*2            （n = 列表实际条数，0 ≤ n ≤ 8；n=0 时 44）
bodyH   = 显示地图 ? max(120, listH) : max(44, listH)
footH   = 有「还有 N 只未显示」 ? 20 : 8
panelH  = 显示附近面板 ? hitH + 28 + bodyH + footH : hitH
```

实测结果：

| 形态 | 375 高 | 390 高 | 备注 |
| --- | --- | --- | --- |
| 命中 + 附近，5 条 | **258** | **258** | 默认态 |
| 命中 + 附近，8 条（截断） | **366** | **366** | 最高值 |
| 仅命中 | 64 | 64 | 无标题/列表 |
| 仅附近，5 条 | 194 | 194 | 无命中区，标题上移到 top 4 |
| 仅附近，8 条 | 302 | 302 | |
| 命中区无数据 + 附近 5 条 | 200 | 200 | 命中区 45 |

> 面板高度**不压缩、不滚动**。最高 366，在 812 屏上占 45.1%。

## 3. 布局规则

### 3.1 锚点与展开方向

球把屏幕切成四个象限，面板**贴住球所在的那个角、朝屏幕内侧铺开**，保证四角都不出屏：

| 球所在半屏 | 面板水平锚点 | 面板垂直锚点 |
| --- | --- | --- |
| 右半屏 | 面板**右缘** = 球右缘 | — |
| 左半屏 | 面板**左缘** = 球左缘 | — |
| 下半屏 | — | 面板**下缘** = 球上缘 − 8 |
| 上半屏 | — | 面板**上缘** = 球下缘 + 8 |

结果：球在右下 → 面板在球左上；球在左上 → 面板在球右下。随后整体再夹紧到 `[8, 屏宽−宽−8] × [8, 屏高−高−8]`。

> 这是产品已确认的口径：**贴着球那个角、朝屏幕内侧**，不采用字面上的「向右/向左展开」（那样会出屏）。

### 3.2 拖球时的跟随

- 面板位置**不单独存储**，每帧由球位置重新推导（`panel = f(orb)`），拖动球时面板实时跟随，无过渡动画（跟手优先）。
- 拖动过程中球始终夹在 `[8, 屏宽−56] × [8, 屏高−56]`。
- 松手不吸附：停在手指抬起的位置（四角只是顶部控制条给的快捷定位）。
- 球在**收起 / 展开两种状态下都渲染、都可拖**；展开时拖动球，面板跟着走。
- 注意：375 屏上面板宽 268，left 的可用区间只有 **8–99**（91px）。所以横向跟随只在球跨过左右半屏、或球接近边缘时才明显，纵向跟随（上/下换向）最直观。这是几何决定的，不是动画缺失。

### 3.3 球贴边

- 球贴边不吸附、不自动隐藏、不改变朝向逻辑；只保证 8px 边距。
- 390 上按「离最近边的距离」换算：球靠右/靠下时补上 390−375 = 15、844−812 = 32 的差值，所以右/下依然贴边 8；靠左/靠上直接取原值。

### 3.4 最大高度与截断

- 列表最多 **8 条**，排序：需求 > 稀有 > 距离近。
- 超过 8 条：只渲染前 8 条，**不滚动、不折叠**，脚注写「还有 N 只未显示」（N = 总数 − 8）。
- 面板最高 366（375 上 45.1%、390 上 43.4%）；屏幕更矮时优先贴边，不做等比缩放。

## 4. 状态与文案清单

### 4.1 命中区（战斗命中）

结构照搬 PC `src/ui/BattleHudOrb.tsx` 的 `battleOverlayFields()`：

- 标题行：`战斗采集 · 赛季奇遇` + 右侧 `⌄`（点击收起面板）。
- 第一排：主名（`rewardName || guardName`）→ `♂/♀` → `{等级}级` → 性格（仅 `natureConfirmed` 时）→ `{声音}dB`（±96 达标用达标色）→ `命中目标`（玫红）。
- 第二排：`{身高/100}m（{身高百分位}%）` → `{体重/1000}kg（{体重百分位}%）`（百分位 ≥98 或 ≤2 用达标色）。
- 无命中数据时：标题行保留，下方一行灰字 `进入赛季奇遇战后，这里会显示守卫的个体数据。`

### 4.2 状态表（文案均为一句话以内）

| 状态 | 显示 | 文案 |
| --- | --- | --- |
| 收起态 | 只有球（48px） | 球内：`附近` / 数字（当前数量） |
| 首次提示 | 球 + 气泡，无面板 | 气泡：`点我展开` |
| 展开 · 命中 + 附近 | 命中区 + 标题 + 地图 + 列表 | 标题：`附近 {N} · 稀有 {M}`；脚注（仅截断时）：`还有 {N} 只未显示` |
| 中心为估算 | 标题右侧小牌 + 地图中心虚线空心圈 | 小牌：`中心为估算` |
| 只有列表 | 无命中区、无地图，列表占满宽 | 标题同上；空态见下 |
| 只有命中 | 仅 64px 命中区 | 标题行：`战斗采集 · 赛季奇遇` |
| 空数据（附近无精灵） | 列表空态 | `附近暂时没有精灵` + 次行 `进入野外后自动出现`；球数字 `0` |
| 等待登录 | 列表空态（**原型未覆盖，按此实现**） | `登录后显示附近精灵`；球数字 `—` |

- 空态文字：主行 10 / 400 / 次级色；次行 9 / 400（「进入野外后自动出现」）。
- 设置态勾选项描述：`展开后顶部：名字 / 等级 / 性格 / 声音 / 身高体重`、`展开后左侧：小地图 + 右侧紧凑列表`（以原型为准）。
