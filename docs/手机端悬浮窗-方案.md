# 手机端悬浮窗扩展方案（列表 + 小地图）

> 2026-11-08 方案稿，**本轮只做方案，不实施**。等 PC 端 UI 审核通过后，再决定是否排期。

## 1. 现状

- 手机端已有系统悬浮窗（`BattleHudOrb` → `RocoCapture.updateBattleOverlay`），
  由安卓壳用 `WindowManager` 画悬浮球，显示战斗/附近命中信息；
- 数据由网页端推送：`{ visible, hit, fields[] }`（见 `src/collector/nativeCollector.ts`）；
- 网页端无法直接画系统浮窗，所以安卓侧是「原生渲染 + 网页供数」。

## 2. 目标

在现有悬浮球基础上增加一个可展开的「附近列表 + 小地图」面板：

```
┌───────────────────────┐
│ 附近 12 只 · 稀有 3    │   ← 标题条（可拖动）
│ ┌───────┐ ┌─────────┐ │
│ │ 小地图 │ │ 雪豆丁 Lv45│ │   ← 左侧 120×120 小地图
│ │ 120px │ │ 88m 西南  │ │
│ │       │ │ [需求·炫彩]│ │
│ └───────┘ │ 冰川企鹅 Lv38│  ← 右侧紧凑列表（名字/等级 + 距离/方向 + 一个牌子）
│           │ 42m 东北   │
│           └─────────┘ │
│  [停止采集]      [收起] │
└───────────────────────┘
```

- 收起后就是一个悬浮球（沿用现有形态，遮挡最小）；点球展开 / 再点收起；
- 展开后显示什么可配置（见 §2.1）：战斗命中占顶部一行，附近面板（地图 + 紧凑列表）在下方；
- 列表项点击只做高亮，不跳转（游戏在前台时跳回工具箱会打断操作）；
- 稀有 / 需求命中沿用现有颜色语义（异色橙、炫彩粉、污染紫、需求红圈）；
- **地图视野与 PC 完全一致**：小地图默认展示半径 150m（横向 300m），只画一个 120m 距离圈（带「120m」标注）；
- **附近页地图（手机浏览器）已同步**：默认 150m 半径 / 120m 圈，右上角可缩放，缩放倍率记在 localStorage（`roco.nearbyMapZoom`），下次打开沿用；小窗小地图固定同一视野；
- **信息密度与 PC 一致**：地图尽量大、列表紧凑，只展示「名字 / 等级 / 距离 / 方向 / 一个牌子」；
- **明暗主题**：与 PC 小窗共用同一个设置项（默认暗色，可切明色），原生侧只换一套颜色变量；
- **不做「鼠标穿透」这类桌面概念**：手机端只有收起 / 展开；
- 停止采集时自动收起并隐藏。

### 2.1 展开内容可配置（2026-11-08 新增）

只有一个球，但展开后显示哪些面板由用户决定：

- **设置项位置**：「附近」页的悬浮窗设置区，和明暗主题放在一起，两项开关——「战斗命中」「附近面板」；
- **默认真值**：两个都开；
- **约束**：至少留一项——关到只剩一项时，最后一个开关置灰并提示「至少保留一项」；
- **两个都开**：顶部一行战斗命中（命中数量 + 当前目标），下方是地图 + 紧凑列表的面板，整体尺寸同当前这一版；
- **只开附近面板**：顶部战斗行不占位，面板直接顶到标题条下方；
- **只开战斗命中**：展开后只有一条战斗横幅，不显示地图与列表；
- **收起表现**：无论开几个，收起都是一个球；球上角标按开启项显示（都开 → 「命中 N / 附近 M」，只开一个就只显示对应数字）；
- **出现时机**：采集开始只出球，不自动展开；首次采集给一次「点我展开」提示，用户看过就不再重复；
- **配置归属（2026-11-08 已定）**：只本机记忆，不跟随账号、不与 PC 同步，理由见 §7。

## 3. 数据与接口

新增一个与 PC 同构的 payload（不改变现有 `updateBattleOverlay` 的兼容行为）：

```ts
interface NearbyOverlayPayload {
  visible: boolean;
  capturing: boolean;
  hasKey: boolean;
  scene: number | null;
  self: { x: number; y: number } | null;
  pets: Array<{
    key: string; name: string; level: number; kinds: string[];
    rare: boolean; alert: boolean; nature: string | null; gender: string | null;
    distanceM: number | null; bearingLabel: string | null;
    x: number | null; y: number | null;
  }>;
  /** 展开内容配置（§2.1）；缺省时两端都按「两个都开」处理 */
  panels?: { battle: boolean; nearby: boolean };
  updatedAt: number;
}
```

- 网页端在「附近」页已有全量数据，判断 `window.RocoCapture?.updateNearbyOverlay` 存在时推送（节流 800ms，与 PC 相同逻辑）；
- 安卓壳新增 JS 桥方法 `updateNearbyOverlay(json)`，解析后更新原生悬浮面板；
- **兼容约束（前置）**：旧 APK 不认识 `panels` 字段时按「两个都开」渲染，不报错、不弹初始化提示；
- 旧壳没有该方法时静默跳过，保持现有悬浮球行为不变。

## 4. Android 原生改动（估）

| 文件 | 改动 |
|---|---|
| `MainActivity.java` | 注册 `updateNearbyOverlay` JS 桥（与现有 `updateBattleOverlay` 同一套来源校验） |
| `BattleOverlayService`（并入现有服务，不新建前台服务） | 新增列表 + 小地图视图；`WindowManager` 布局、拖动、收起/展开 |
| 新布局 `overlay_nearby.xml` | 标题条、战斗命中一行、列表 `RecyclerView`、小地图 `WebView`（承载网页地图） |
| 地图资源 | `assets/maps/10003.webp` + 标定 JSON（与网页同一份） |
| 权限 | 复用现有悬浮窗权限；无需新权限 |

**小地图路线：已选「内嵌 WebView 复用网页地图」**（2026-11-08 定）。直接加载网页那套地图组件，
观感与 PC / 网页完全一致、只维护一份；代价是内存与首帧更重。真机实测明显掉帧时，再退回备选
「原生裁剪」（`ImageView` + `matrix` 按自身坐标裁剪，轻、省电，但要在安卓工程里重实现一套地图，
以后改 UI 要改两遍）。

标定常量一律与 `src/pcap/worldMap.ts` 保持一致，不复制数值。

**兼容前置**：悬浮窗读取 `panels` 配置时必须能容忍缺字段——旧 APK / 旧网页组合下缺字段，
按「战斗命中 + 附近面板都开」渲染。

## 5. 风险与限制

- **悬浮窗渲染性能**：列表每秒刷新一次即可（与采集巡检同频），不要 60fps 重绘地图；
- **电量**：地图裁剪只在数据更新时重绘，避免定时器空转；
- **权限**：部分 OEM 会限制后台悬浮窗，沿用现有引导文案；
- **兼容**：旧 APK 不装新桥时仍走原悬浮球，不影响现有用户；
- **审核**：原生界面同样遵守「新增 UI 先审核」，实施前先给安卓侧原型/截图确认。

## 6. 实施顺序（若批准）

1. 网页端 payload + 桥方法（可先发网页，无副作用）；可再拆两步：
   先加「payload 组装纯函数 + 单测」（不碰现有页面，零冲突），再接进「附近」页；
2. 安卓壳新增悬浮面板 + 小地图（需重打 APK，且安卓工程不在本仓库）；
3. 真机验收：展开/收起、拖动、稀有高亮、断线、权限拒绝、切后台。

## 7. 已定事项（工程自主决策）

> 2026-11-08。以下都是不影响观感、可回退的工程口径，已直接定下，实施时不再讨论。
> 需要用户拍板的另见 §8。

- **小地图技术路线已选「内嵌 WebView 复用网页地图」**（2026-11-08）：先按此实现，真机实测明显掉帧再退「原生裁剪」备选（见 §4）。
- **一个球 + 展开内容可配置**（2026-11-08）：合并成一个悬浮球，展开后显示哪些面板由「附近」页的两个开关决定
  （战斗命中 / 附近面板），至少留一项、默认都开；战斗命中占顶部一行，附近面板在下方（见 §2.1）。
- **配置缺字段容错**：旧 APK / 旧网页组合缺 `panels` 字段时按「两个都开」渲染，不报错、不弹提示。
- **附近面板内容已定**（2026-11-08）：地图 + 紧凑列表，与 PC 一致；不做「只列表」「只地图」两种精简形态。
- **采集开始不自动展开**（2026-11-08）：只出球；首次采集给一次「点我展开」提示，看过即止。
- **服务结构已定**（2026-11-08）：并入现有悬浮服务，不新建前台服务——避免通知栏多一条常驻通知、避免部分机型重新授权。
- **展开内容配置只存本机**（2026-11-08，可回退的工程决定）：不跟随账号、不与 PC 共用。理由：手机横屏与 PC 桌面观感差异大，
  同步容易出现「在 PC 关掉战斗命中，手机上也没了」的互相干扰；先本机，真机用下来确有跨端需求再改（改回同步只需加一个云端字段，不动界面）。
- **不做桌面式「鼠标穿透 / 点击穿透」**：手机端只有收起与展开，避免「点不到窗不知道怎么办」。
- **明暗主题与 PC 共用一套口径**：默认暗色、可切明色，选择记在本机、重开沿用；原生侧只换一套颜色变量。
- **视野口径与 PC 一致**：默认半径 150m（横向 300m），只画一个 120m 圈并标注；用户缩放后记忆，下次沿用。
- **地图资源与标定只维护一份**：图用 `public/maps/10003.webp` + `maps.json`，换算以 `src/pcap/worldMap.ts` 为准
  （100 世界单位 = 1 米）；安卓侧读同一份，不复制常量。
- **无地图场景回退**：没有对应地图时，地图区域退回雷达 / 列表，不影响列表与提醒。
- **列表口径与 PC 一致**：最多 8 条，只显示「名字 / 等级 + 距离 / 方向 + 一个牌子」，按 提醒 > 稀有 > 距离 排序。
- **列表项点击只做高亮**，不跳回工具箱（游戏在前台，跳转会打断操作）。
- **刷新节奏**：数据推送节流 800ms，只在数据变化时重绘地图，不做 60fps 轮询。
- **停止采集即收起并隐藏**，不留空面板。
- **不新增悬浮窗总开关**：跟随「采集中」状态自动出现 / 消失；「附近」页那两个开关只管展开后显示什么（见 §2.1）。
- **桥方法向后兼容**：`updateNearbyOverlay` 不存在时静默跳过，旧 APK 仍走现有悬浮球。
- **payload 与 PC 同构**：直接复用 PC 的字段定义（`src/collector/desktopOverlay.ts`），不另起一套字段。

## 8. 仍需用户确认

只剩一条：**手机面板原型待审核**——排版、两种地图观感（内嵌网页地图 vs 原生裁剪的观感对比）、
配置的三种组合（只战斗命中 / 只附近面板 / 两个都开）。原型通过后再动安卓实现。
