## 三、领域约定（最新口径）

**必读** `project_memory.md` 的「家园/孵蛋机制」一节。关键：

- **单位（已 1:1 对齐游戏）**：小窝 = **8×8 个家园地板最小移动单元**（用户 2026-10-06 游戏内实测：横竖各移 7 下仍冲突、8 下才不冲突 → 正方形）。**代码坐标单位现在就是「地板单元」**：`NEST_SIZE = 8` / `PAIR_RANGE = 17` / `GROUP_GAP = 24`（坐标是整数，即 1 单元精度 = 游戏里的微调粒度）
- 距离：**中心欧氏 ≤17 单元 = 2.125 窝**（不是曼哈顿 ≤5 / ≤2）；1 窝占 8×8 单元、不可重叠（切比雪夫 ≥8 单元）；斜向可连，但 16,6 单元 = 17.09 就断了
- 摆位：**贪心密排**——每放一个新窝，挑「与已放置的窝连线最多、其次最紧凑」的落点（`nestGeometry.placeGreedy`）。
  **目标不是「簇内两两全连」**（用户 2026-10-06 明确）：一簇里各窝蛋组/性格本来就不全相容，有些窝天然配不上对；摆一起只为**尽量多连上能连的边**（M1 下线越多机会越多）。
  游戏硬上限：**最多 6 个窝可以两两相连**（1 单元精度；纯几何密排已能达成）。组间仍拉开 ≥24 单元防串窝
- 摆位自检：`checkLayout(clusters, intendedPairs)` 的 `outOfRange` 专门抓「声称成立却超距」的边；`nestPlan` 只把**真的连得上**的边写进 `pairings`，摆不出来的缺口自动回到 `unfilled`（不虚报已排上）
- 资源模型：**窝是资源、配对是边**（1 只精灵占 1 窝，但可同时与多只异性配对）
- **配窝分配**：① 普通 60% → ② 学院补差 → ③ 普通 30%；每档**内部按「这条线的总期望产出」排**（`pairValue`：一条线能覆盖的每个缺口各算一份概率，「母平和 × 公开朗」=0.6 排在只补平和 0.3 前面）。
  **每档收线时按「公母尽量均衡」排序**（`acceptTier`，2026-10-06 晚用户改口径：**11 窝的最优是 5 公 6 母、公母比约 1:1**，M1 下公母连线最多、命中机会最大）：每收一条就重算公母差，先收「收下后 |公−母| 最小」的那条线（同级里仍按期望产出从高到低）。
  **推翻旧的「母优先、公复用」**（那是按「新母+复用公 → 新母 → 复用已有母」三轮收，会把窝挤成「1 公挂 N 母」、公母失衡、连线反而少）。新口径是**软偏好、不强制 1:1**：公本/母本/窝位不够时该失衡就失衡。
  学院那只的配对方还要**优先挑候选度数低的**（`candidateDegree`）：配对方要被保留、不能再配别人，挑到「某缺口唯一的载体」会把那个缺口堵死。
  **不再「把线挂满」**：`tryAccept` 只收**能补新缺口**的线，同一格不叠第二条（旧 Pass2 已删）——冗余线只会产同一种蛋、把窝占死，玩家就没窝自己孵**对性蛋**去换蛋了（自家产的全成迭代蛋，没人换）
- 判定模型：先按 **M1 多路径**（但「多线多机会」不等于「挂满」，见上一条）
- 学院 100% 遗传的是**学院那只自己的性格**
- **母方物种必须能出公**（`maleCapable`，已烘焙全部 625 物种：568 true / 57 false）——覆盖度 / 换蛋 / nestPlan / breedPlan 都用 `buildCanBreedMale`

- **发版流程（本轮实测可用）**：
  `npm run build` → `npx wrangler pages deploy dist --project-name roco-toolbox --branch=main --commit-dirty=true`
  - wrangler 4.147.0 **已登录**（OAuth，无需 token）；生产分支是 `main`；`--commit-dirty=true` 必加，否则它会因工作区脏而提示/失败

  `npx wrangler pages deploy dist --project-name roco-toolbox --branch=test --commit-dirty=true` → 独立 URL `https://test.roco-toolbox.pages.dev`
