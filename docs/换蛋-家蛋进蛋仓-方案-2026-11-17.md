## 2. 适配器：home 快照 → `EggStockSnapshot.home`

新增 `src/ui/plan/homeEggAdapter.ts`，导出：

```ts
homeStockFromSnapshot(snapshot: AccountSnapshot, accountId: string): {
  gameAccountKey: string; capturedAt: number; complete: boolean;
  eggs: HomeEggObservation[]; unresolvedCount: number; ambiguousCount: number;
}
```

`HomeEggObservation` 结构上等同 `EggObservation`，额外带 `location:'home'`、`labelSource`、`parents`。

### 2.1 每颗蛋的字段来源

| 字段 | 来源与优先级 | 取不到时 |
| --- | --- | --- |
| `id` | `home:${actorId}`（加前缀，避免与背包实例 id 冲突） | 无 `actorId` → 跳过并计入 `unresolvedCount` |
| 窝 | `sceneEgg.furnitureGuid` → `home.nests` / `resident.nest.furnitureGuid` | 找不到窝 → 仍出蛋，窝名留空 |
| 母本 | 该窝内 `gender==='母'` 的住户（住户 `gender` → 背包精灵 `gender` 兜底） | 无母本 → 降级，见 §2.2 |
| 父本 | `layEggCouples` 里 `femaleActorId === 母本.actorId` 的 `maleActorIds`，映射回住户；**排除与蛋同窝的父本**（游戏规则：父本窝 ≠ 蛋窝） | 无配对 / 父本都不在快照 → 父本缺失 |
| 物种 `eggGameId` | ① 母本背包精灵 `pet.gameId`；② 母本 `confId` → `cfgPetMap`（`src/pcap-decoder/.../generated/cfgPetMap.json`）；③ `npcConfigId` 暂无映射表，不用 | 三者都无 → 跳过并计入 `unresolvedCount`（不编物种） |
| 父母属性 | 住户 → 背包精灵（`captureId` 末段 = 家园 `instanceId`；实例对不上时**仅同名唯一**时按名字兜底，与 `Home.tsx` 现有口径一致） | 缺背包条目 → 该亲本只留名字/窝，属性留空 |
| `capturedAt` | `Date.parse(home.capturedAt)` | 非法 → 本次不产 home 部分 |
| `complete` | `home.snapshotKind !== 'delta'`（增量快照可能缺住户，不能删旧数据） | — |
| `couplesStale` | 写入 `parents.stale`，界面提示「采集期间有精灵进出，配对可能已过期」 | — |
| `kind` | 固定 `'ordinary'`（家园蛋没有异色/特殊信号；且不可挂出，不影响流通） | — |
| `provenance` | `'self-bred'`（自家家园、自家配对） | — |
| `obtainedAt` | 不写（抓包没有蛋的获得时间） | — |

### 2.2 降级矩阵

| 缺失情况 | 结果 | 界面表述 |
| --- | --- | --- |
| 无母本 | 不出蛋行，`unresolvedCount++` | 不显示（与背包未解析实例同口径） |
| 有母本、无父本 | 出蛋行；物种=母本；性格/声音/体型未知 | 详情「父母暂无完整记录」 |
| 父本多个（学院 1:2） | 各父本算出的性格/声音/体型**全部一致**才落值，否则留空 | 详情列「父本候选 2 只」，属性写「待确认」 |
| 住户在背包里找不到 | 只按 `confId` 取物种；性格/声音/体型未知 | 详情该亲本标「属性未采集到」 |
| 增量快照 | `complete=false`：只增改，不删旧家蛋 | 沿用现有「本次是增量」提示 |
| 配对过期 | `parents.stale=true` | 详情琥珀色提示，不阻止标注 |

## 3. 推算规则与置信度（对齐设计文档 §8.5 / §8.7）

| 项 | 规则 | 落库值 | 说明 |
| --- | --- | --- | --- |
| 性格 | 绿窝（`nestType==='academy'` 那只）→ 100%；普通窝双亲同性格 → 60%；双亲不同 / 只有一方 → 各 30% + 随机 40% | 100% / 60% 时写 `nature`；否则写 `''`（待标注），候选留给详情 | 不把 30% 写成确定性格，避免 `canMatchDemand` 误判 |
| 声音 | `averageVoice(父dB, 母dB)` = `Math.trunc((父+母)/2)`（`src/domain/nestPlan.ts`）→ 映射 `+100/-100/婉转声/粗嗓门` | 双亲分贝都有才写 | ±96~99 仍是婉转声/粗嗓门，不是满分 |
| 体型 | `bodyGradeOf`（`src/shared/bodySize.js`）双亲都 `大块头` → `大块头`；都 `小不点` → `小不点` | 只有这两种 | 父本多候选需全部一致 |
| 满重 / 零体重 | **不给确定值**；详情按 `eggWeightOf(物种)` 算「约 1/N」：`N = round(max*1000) - round(big*1000) + 1` | 不写 `body` | 收进背包后由蛋重升级为确定值 |
| 性别 | 不标注 | — | 设计口径 |

置信度：

- 有任何一项由父母推算成功 → `confidence:'system'`、`labelSource:'system'`；
- 全部推算不出（只有物种）→ `confidence:'unknown'`、`labelSource:'unknown'`；
- 用户手动改 → 服务端 `label` 动作写 `labelSource:'manual'`（沿用现有 `confidence:'manual'`）。

`lastConfirmedAt` 由 `reconcileEggStock` 用该次 home 部分的 `capturedAt` 写入，不在适配器里伪造。

## 4. `complete` 语义：home 不能覆盖背包

`reconcileEggStock` 目前只有一个 `capturedAt` 和每个 part 的 `complete`。接线要补两点：

1. **分部位时间**：`SnapshotPart` 增加可选 `capturedAt`。背包时间来自 `snapshot.exportedAt/importedAt`，家蛋时间来自 `home.capturedAt`（家园轻量刷新只换 `home`，两者天然不同）。`lastConfirmedAt` 用 `part.capturedAt ?? snapshot.capturedAt`；水位仍用整次 `capturedAt`。
2. **删除只看本部位**：现有 L53-59 已按 `egg.location === location` 删除，天然满足「home 完整只删 home、bag 完整只删 bag」。要保证的是**不把两边的 complete 合并成一个布尔**。

服务端 `stock-sync` 同步扩展：

- 请求体保持向后兼容：`{type:'stock-sync', gameAccountKey, capturedAt, complete, eggs, homeComplete?}`；
- `complete` 继续表示背包完整（老客户端语义不变）；
- `homeComplete` 只影响 `location==='home'` 的旧记录；
- 每条蛋带 `location`（缺省 `bag`）、`lastConfirmedAt`、`labelSource`、`parents`。

同步入口（`EggMatchingHub`）：

```ts
const stock = reconcileEggStock(stockRef.current, {
  accountId: me,
  capturedAt: Math.max(bagTime, homeTime),
  bag:  { eggs: bagEggs,  complete: bagComplete,  capturedAt: bagTime },
  home: home ? { eggs: homeEggs, complete: homeComplete, capturedAt: homeTime } : undefined,
});
stockRef.current = stock;
api.mutate({ type:'stock-sync', gameAccountKey, capturedAt: ..., complete: bagComplete,
  homeComplete: home?.complete ?? false, eggs: stock.eggs });
```

- `stockRef` 首次拿到服务端状态时用现有 `state.eggs` 水合，避免把已同步的蛋当成新蛋；
- 触发条件从「背包水位」改为「背包或家园任一部位时间前进」；`attemptedCaptures` 的 key 同时带两个时间。

## 5. `label_source=system` 的服务端口径

现状 `normalizeEgg` 无条件写 `confidence:'manual'`，注释明确「浏览器导入/手标不是服务端证据」。本次按最小改动：

- `stock-sync` 的条目允许带 `labelSource`，服务端只在**同一次 stock-sync 且 `location==='home'` 且带 `parents`** 时接受 `system`；`label` 动作永远写 `manual`；
- 服务端不重新推导规则（父本事实由采集侧提供），但会校验字段形状与 `parents` 至少一侧存在，避免空壳「系统确认」；
- 展示上 `labelSource==='system'` 的蛋在详情显示「系统确认」，并在下方注明「按采集时的当前配对推算；游戏未确认亲子关系」（对齐 §8.8 展示口径）。

## 6. 已知限制（需要产品确认，不在本次代码里自造规则）

1. **身份不贯通**：家园蛋 `home:<actorId>` 收进背包后变成背包实例 id，两套 id 无法对应。收蛋后、下一次完整家园采集前，可能出现「一颗家园蛋 + 一颗背包蛋」并存。
2. **空家园无法表达**：`parseHomeSnapshot` 在四类数据全空时返回 `undefined`，所以「家园里一颗蛋都没有且没有住户/小窝」不会产生 `complete:true` 的空 home 快照，旧家蛋不会被自动清掉。需要时用「当前家园有住户/小窝但 `sceneEggs` 为空」的快照清理。
3. **不可挂出**：设计文档 §7.7 明确「家园窝里的蛋不自动变成现货」。本次实现里家园蛋状态为「在地家园」、不提供挂出；如要允许挂出需要单独确认。

## 8. 提醒侧：旧蛋要不要补提醒（不替用户定）

现状：`observeNewEggs` 在 `previousActorIds === null` 时直接返回 `[]`；`egg_patrol_cache.scene_json` 首次成功后写入基线。因此**基线里已有的蛋永远不会触发「已产出」提醒**，用户只能手动 `rc生蛋了吗` 查询。

| 选项 | 做法 | 后果 | 状态怎么记 |
| --- | --- | --- | --- |
| 1. 保持现状（当前已选） | 只提醒基线之后新出现的蛋 | 首次接入/缓存被清空时，地上的旧蛋不会提醒；不会重复打扰 | 无需新增字段；`egg_patrol_observations` 的 UNIQUE 继续按 (uid, actor_id, task_key) 去重 |
| 2. 首次也补提醒 | 首次查询把基线蛋当作观察结果，匹配到的任务直接发「已产出」 | 接入瞬间可能一次补发多条；任务若建在蛋生成之后，会把旧蛋误报为「已产出」；缓存/换 uid 后有重复提醒风险 | 需要给 `egg_patrol_cache` 加 `baseline_imported` 标记；观察表仍按 UNIQUE 去重，但无法区分「补发」与「新产」 |
| 3. 只补「建单后仍在地上的蛋」 | 首次查询只对 `task.createdAt <= now` 且蛋仍在场时提醒 | 蛋没有生成时间，无法判断「建单时是否已经在地上」，只能按建单时间粗判，仍可能误报 | 需记录任务建单时间与首次观测时间，复杂度和口径都要再定 |
| 4. 手动补一次 | 用户点「检查一次」时忽略基线，按当前场景匹配一次 | 不改变自动巡检规则；用户可控，但多一个入口 | 记录一次手动巡检时间；不写入自动基线 |

当前按选项 1 实现，不改巡检代码；上表留给后续确认。
