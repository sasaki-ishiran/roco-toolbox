# 数据字段说明（已用真实数据核对）

本文记录两套数据源的字段含义，以及它们之间**唯一的正确连接方式**。全部结论都是拿你四个账号的
备份文件实跑核对过的，不是推测。

## 一、上游图鉴数据（wiki，`data/pets.json`）

来源：`Module:Pets/data/Catalog`，625 只精灵，版本 `s4-2026-09-24`。

| 字段             | 含义                                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------------ |
| `key`            | wiki 内部 id，形如 `pet_000483`。**只在 wiki 内部有效**                                                      |
| `game_id`        | 游戏侧物种 id，如 `3200`。625 条全部有值且不重复，是**跨数据源的唯一主键**                                   |
| `number`         | 图鉴号（字符串，如 `210`）。有形态变体共用同一编号的情况                                                     |
| `name` / `title` | 名称；`title` 会带形态后缀                                                                                   |
| `egg_group`      | 蛋组 id 数组。`1` = 未发现（不可孵蛋），`2`~`15` = 14 个可孵蛋组                                             |
| `gender_ratio`   | `{male, female}`，10 分制（如 `{male:5,female:5}` 是公母各半，`{male:0,female:10}` 是母系专属）              |
| `egg_size`       | **蛋**的重量区间：`{min, mini_max, max, huge_min, unit:"g"}`；大块头 = `>= huge_min`，小不点 = `<= mini_max` |
| `stats`          | 种族值 `{hp, atk, spa, def, spd, spe}`                                                                       |

## 二、账号备份数据（`补充数据/*.json`，hatch-backup 导出）

结构：`meta`（导出信息）+ `collections`（你的资产）+ `rawProtocol`（原始抓包，本项目不用）。

| 位置                                                    | 含义                                             |
| ------------------------------------------------------- | ------------------------------------------------ |
| `collections.petBackpack.items[]`                       | 你拥有的精灵，每只一条                           |
| `collections.eggInventory.eggs[]`                       | 蛋仓库，每条含 `weightGrams`（蛋重）与 `petName` |
| `collections.fruits[]` / `fashions[]` / `guluInventory` | 果实、时装、咕噜球                               |
| `collections.topics`                                    | 图鉴课题进度，键形如 `喵喵:1`                    |

### 单只精灵的关键字段

| 字段                            | 含义                                   | 实测                                    |
| ------------------------------- | -------------------------------------- | --------------------------------------- |
| `speciesPetId`                  | 游戏侧物种 id                          | 与 wiki 的 `game_id` 一一对应           |
| `runtimePetId`                  | **备份工具自己的编号，不要用来对图鉴** | 会把机械方方标成 `pet_000193`（菊花梨） |
| `gender` / `nature`             | 性别 / 性格                            | 如 `母` / `大胆`                        |
| `bloodline`                     | 血脉，如 `机械系血脉`                  |                                         |
| `voiceDb`                       | 声音分贝，整数                         | 实测范围 -100 ~ 100                     |
| `medalVoice`                    | 声音奖牌                               | `婉转声` / `粗嗓门` / 空                |
| `medalBody`                     | 体型奖牌                               | `大块头` / `小不点` / 空                |
| `weightGrams` / `weightPercent` | 精灵自身体重 / 在同种内的百分位        | 与蛋重不是同一刻度                      |
| `individualStats`               | 个体资质                               |                                         |
| `acquisitionType`               | 获取方式                               | `孵化` / 抓捕等                         |
| `isShiny` / `isColorful`        | 异色 / 炫彩                            |                                         |
| `formId` / `form`               | 形态                                   |                                         |

## 三、声音规则（从 3965 只实测数据反推）

- 婉转声 470 只，`voiceDb` 全部落在 **+96 ~ +100**
- 粗嗓门 182 只，`voiceDb` 全部落在 **-96 ~ -100**
- 无奖牌 3313 只，全部落在 **-95 ~ +95**

即：`|voiceDb| >= 96` 拿奖牌，正数为婉转声、负数为粗嗓门。

**遗传规则（用户确认）**：子代 = `(父 + 母) / 2` **向零取整**。
例：100 与 99 得 99；-100 与 -99 得 -99（不是 -100）；100 与 -100 得 0。
推论：想要婉转声要父母同号且和 `>= 192`；要 ±100 必须父母双双 ±100。

**性格遗传（与窝类型挂钩，2026-10-03 确认；2026-10-04 修正普通窝机制）**：

| 窝类型           | 性格遗传                      | 体型 / 声音 / 满分判定 |
| ---------------- | ----------------------------- | ---------------------- |
| 绿窝（学院小窝） | **100%** 传给配对蛋           | 不受影响               |
| 普通窝           | 每只亲本 **30%** 遗传自己性格 | 不受影响               |

普通窝的具体概率（用户 2026-10-04 拍板修正，旧文档记 60% 不准确）：

- 父母本**同性格**：遗传父亲 30% + 遗传母亲 30% + 随机 40% → 得到目标性格合计 **60%**；
- **迭代蛋**（一方不是目标性格）：只剩一方可遗传 → **30%**。

换句话说，换普通窝蛋的代价只是「孵出来性格可能不对、要重孵」，
体型与满分（仍需双满分父母）不会被打折。工具里的「换蛋清单」据此提供
绿窝 / 普通窝开关，影响复制出去的要蛋文本；配窝建议的段尾提示也写这套规则。

## 四、体型与蛋重（两套刻度，不要混）

- **蛋重区间表**（`补充数据/大块头区间统计（已核对）.xls`）：列是 `档位 | 名字 | 大块头 | 极限值 | 区间`，
  152 只精灵、10 个档位，且 `区间 = 极限值 - 大块头` 对 152 行全部成立。
  与 wiki 的 `egg_size` 完全一致（喵喵 1.829/1.84；蒲公英 0.118/0.12），可互相校验。
- 判定蛋：`重量 >= 大块头` 为大块头，`重量 == 极限值` 为满重。
- **精灵自身体重约为蛋重阈值的 2~2.5 倍**，是另一套数据；备份里已有 `weightPercent` 与奖牌，
  直接用，不要拿蛋重的表去套精灵自身。

## 五、蛋（道具名 / 形态 / 可换性）

**道具名按物种唯一，不带形态**。上游物品模块 `模块:Items/data/Catalog`（1481 条物品）里有 **193 个精灵蛋**：
`雪绒鸟的蛋`、`丢丢的蛋`、`鸭吉吉的蛋`……**0 条**带形态后缀，**0 条**同名蛋对应多个图标。
所以「雪绒鸟的蛋（夏天的样子）」不是道具名——道具就只有「雪绒鸟的蛋」。

**但形态是可分辨的**，两条路：

| 途径             | 依据                                                                                                                                                                                                              |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 抓包（自己的蛋） | 蛋记录带 `petConfId`，经 vendored 解码器的 `eggConfigIdentities` 表解析出**带形态的名字**：`petConfId=3280001 → 雪绒鸟_夏天的样子`（表在 `src/pcap-decoder/miniprogram/utils/`，295 条）                          |
| 游戏内辨认       | 每个形态的蛋有**各自的花纹图标**（宠物数据的 `image.egg`）：雪绒鸟 春天=`Item_107106`、夏天=`Item_107107`、秋天=`Item_107108`、本来=`Item_107014`；全库 **43 个物种**的形态蛋图标互不相同，其余物种的蛋看起来一样 |

这就是「观察其花纹可以看出」（物品描述原文）与蛋神助手能分辨的原因。

**只有基础形态有蛋道具**：

- `stage === 1` 的 222 个物种里 220 个有蛋；`stage ≠ 1`（进化形态）的物种**一个都没有**
  （火神、喵呜、蹦蹦草…都没有蛋，只能由基础形态进化而来）。
- 例外 2 个：迪莫(001)、凡雀(351) —— `stage=1` 但上游没有它们的蛋道具。
- 3 个特殊蛋名不带形态而是带**体型**：`小不点雪灵兽的蛋`、`大块头雪灵兽的蛋`、`唯一小独角兽的蛋`。
- 208 条多阶段链里，**图鉴号顺序恰好等于阶级顺序**（0 例外）——但这是编号巧合，不能当规则用；
  判断「能不能换到蛋」要看 `stage === 1`。

**对工具的约束**：换蛋清单的候选与建议物种**只能取 `stage === 1`**（否则会推荐一个根本没有蛋的进化形态）；
蛋名按 `{物种名}的蛋` 生成。形态不影响蛋组，所以换蛋时不必指定形态——
需要某个形态时（母本全收集按形态算）才说明「要哪个花纹 / 哪个样子的蛋」。

### 显示名：有官方名就用官方名

带形态的精灵/物种，显示名用**游戏自己的写法**：`雪绒鸟_夏天的样子`（下划线分隔）。
数据在 `catalog.gen.json` 的 `officialName` 字段，由 `tools/data-pipeline/trim-catalog.mjs`
从上面两张 vendor 表合并而来（625 个物种里 314 个能取到；物种级表优先于蛋级推断，本次合并**零冲突**）。

**为什么不能自己拼**「名字 + 形态」——实测有两种出入：

| 情况               | 图鉴                    | 官方名                  |
| ------------------ | ----------------------- | ----------------------- |
| 形态文字本身不同   | `地鼠_储水时**的**样子` | `地鼠_储水**期**的样子` |
| 单形态物种不带后缀 | `护主犬_本来的样子`     | `护主犬`                |

所以：有 `officialName` 就用它，没有才退回自己拼（分隔符与官方保持一致，也用下划线）。
统一入口是 `src/domain/speciesName.ts` 的 `speciesDisplayName()`，**不要在各处自己拼字符串**。

注意：**蛋名不用官方名**。蛋道具按物种命名（`雪绒鸟的蛋`），与形态无关。

## 六、连接两套数据的正确做法

```
备份 items[].speciesPetId  ←→  wiki pets[].game_id
```

实测：3965 条记录全部命中，0 条落空；比按名字匹配多出 34 个物种的准确度
（形态后缀会让名字对不上），比按 `runtimePetId` 匹配则避免大量错配。
按此口径，四个账号合计拥有 **409 / 625** 种，还缺 **216** 种（其中可孵蛋 199 种，只能抓或换的 17 种）。
