## B7-H01 采集完成时切页会让「待补完成提示」在没导入的情况下谎报「导入完成」

- **等级**：高
- **文件:行号**：[NativeCollectorPanel.tsx:190-193](file:///d:/desk/洛克工具箱/src/ui/NativeCollectorPanel.tsx#L190-L193)、
  [96-98](file:///d:/desk/洛克工具箱/src/ui/NativeCollectorPanel.tsx#L96-L98)、
  [262](file:///d:/desk/洛克工具箱/src/ui/NativeCollectorPanel.tsx#L262)、
  [343-353](file:///d:/desk/洛克工具箱/src/ui/NativeCollectorPanel.tsx#L343-L353)；
  [captureSessionStore.ts:28-36](file:///d:/desk/洛克工具箱/src/collector/captureSessionStore.ts#L28-L36)
- **问题描述**：
  本轮把「等文件落盘期间切页」从静默 `return` 改成 `setPendingCompletion(session)`：

  ```ts
  const saved = await waitForSaved(session);
  if (!mounted.current) { setPendingCompletion(session); return; }
  ```

  但 `pendingCompletion` 原本只服务于「**已经发起导入**、只是没看到结果就切走」的场景：
  重新挂载时 [NativeCollectorPanel.tsx:97-98](file:///d:/desk/洛克工具箱/src/ui/NativeCollectorPanel.tsx#L97-L98) 只做
  `takePendingCompletion() → setCompleted(session)`，**不会再调用 `importCapture`**。
  而弹窗标题/正文按 `outcome.local` 推断：

  - `importFailed = autoStage==='failed' || outcome.local==='failed' || completionError`；
  - 这条路径上三者都不成立（本次根本没导入，`outcome.local` 往往是 `idle` 或上一次的 `saved`），
    于是标题 = 「导入完成」，正文 = 「导入完成，游戏数据已保存到本机。」

  另外 `hasAutoStopped(session)` 已被标记、`CaptureProgressView` 只在 `phase==='capturing'` 时触发
  `onReady`，重挂载后也不会补触发自动导入——所以这次采集**永远不会**被自动导入。
- **影响面**：采集进度稳定后自动停止，用户在「等保存」的 ~8 秒内切到别的页签（或在「我的」里从
  「游戏数据」切到「身份 / 私有同步」，`Profile` 是条件渲染会卸载面板），回来就会看到
  「导入完成，游戏数据已保存到本机」，但本机数据其实没有变化；用户很容易不再手动点「解析并导入」，
  从而带着旧数据去看板/小组看结果。原包仍在文件列表里，可手动补救。
- **修复建议**：`pendingCompletion` 需要带阶段，例如 `setPendingCompletion(session, 'saved-only' | 'importing')`；
  重挂载时：

  - `saved-only`：不要弹「导入完成」，改为提示「采集已保存，尚未导入」并给「解析并导入」按钮
    （或直接续跑 `handleCaptureReady` 的导入段，但必须先确认 `hasAutoImported` 语义）；
  - `importing`：维持现有「导入完成 / 未完成」逻辑。

  同时把 `takePendingCompletion` 的返回值改成能区分阶段的对象，避免再出现同类误判。
- **置信度**：高（调用链与状态初始值都能静态确认；触发窗口取决于用户是否在保存期切页）

## B7-M01 紧凑卡昵称没有长度兜底，6 字真实物种/长昵称会压到右上角性格徽标

- **等级**：中
- **文件:行号**：[PetCompactCard.tsx:104-107](file:///d:/desk/洛克工具箱/src/ui/PetCompactCard.tsx#L104-L107)、
  [136-149](file:///d:/desk/洛克工具箱/src/ui/PetCompactCard.tsx#L136-L149)、
  [44-56](file:///d:/desk/洛克工具箱/src/ui/PetCompactCard.tsx#L44-L56)
- **问题描述**：规范把「普通名字最长 5 个字」当成布局前提
  （`docs/产品交互规范.md:104`、`:116`，`docs/…` 里坐标也是按 5 字留的：昵称 `left=64`、
  字号 14px × `scale 0.75` ≈ 10.5px/字，5 字到 116.5px；性格徽标 `left=125`）。
  实现只做了「去掉 `_形态`」，没有任何截断/自适应：

  ```ts
  const displayName = name.split('_')[0] || name;
  ```

  实测图鉴里有 1 个基础名是 6 字：`3746 睡铃雪影娃娃`（`catalog.gen.json`，无形态、官方名同名）。
  它渲染到 64 + 6×10.5 ≈ 127px，已经压进性格徽标（`left:125`，且 DOM 上性格在后、会盖住名字最后一字）；
  家园住户名若是玩家自定义昵称（`HomeResident.name` 直接来自抓包）、或需求中心的 `speciesDisplayName`
  落在该物种上，都会复现。再长 1~2 字时会把整个性格徽标盖住。
- **影响面**：家园精灵卡与需求中心「推荐配对」卡（同一组件）在窄屏上出现名字与性格叠字/被裁切；
  不是数据错误，但正是这次手动调坐标最在意的观感。
- **修复建议**（涉及元素位置/大小，按 AGENTS.md 先给可交互 HTML 或 375/390 截图方案，不要直接改）：
  1. 名字超过 5 字时缩短字号（如 `scale 0.6`）并保持左对齐；或
  2. `displayName.slice(0, 5)` + 末尾省略号，`title` 保留全名；或
  3. 给昵称容器加 `max-w-[56px] overflow-hidden text-ellipsis whitespace-nowrap`。

  建议同时给 `PetCompactCard` 补一条「6 字名字」的渲染测试，避免以后加物种时再踩。
- **置信度**：高（物种数据与字宽可复算；最终像素表现需截图确认）

## B7-L01 `PetAvatar` 的加载兜底状态不随 `gameId` 变化重置

- **等级**：低
- **文件:行号**：[PetAvatar.tsx:33-38](file:///d:/desk/洛克工具箱/src/ui/PetAvatar.tsx#L33-L38)、
  [60](file:///d:/desk/洛克工具箱/src/ui/PetAvatar.tsx#L60)
- **问题描述**：`stage` 是组件内 `useState('primary')`，只在挂载时初始化；`gameId` / `shiny`
  变化时不会回到 `primary`。一旦某个精灵因官方未收录走到了 `fallback`，同一组件位置换成另一只精灵

  **首字占位**，而不是新精灵的头像；从异色档退回 `normal` 的情况同理。
- **影响面**：少数官方未收录头像的精灵之后，同一卡片位换人时头像不出现；不影响数据。
- **修复建议**：`useEffect(() => setStage('primary'), [gameId, shiny])`，或调用处给
  `<PetAvatar key={`${gameId}-${shiny}`} …>`（两者挑一，不要同时做）。
- **置信度**：中（组件层可确定；是否真的复用同一实例取决于各调用处的 key/条件渲染）
