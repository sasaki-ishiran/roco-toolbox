### B6-H01 直达聚焦 effect 反复生效：从看板进小组后，打开任何小组都会被弹回「个人求蛋」

- **等级**：高
- **文件:行号**：`src/ui/CollectionGroups.tsx:113-127`（调用方 `src/ui/Dashboard.tsx:204,245`、`src/App.tsx:189`、`src/ui/navigation.ts:119-127`）
- **问题描述**：

  直达聚焦的副作用依赖里放了「当前组 id」，而 effect 设计成「只要当前组类型和 focus 不一致就切走」：

  ```tsx
  // CollectionGroups.tsx:114-127
  useEffect(() => {
    const type = focus?.groupType;
    if (!type) return;
    if (hook.currentGroup?.group.groupType === type) return;
    if (hook.pageMode === 'group' && hook.currentGroupId && hook.currentGroup == null) return;
    const compatible = hook.groups.find((group) => group.groupType === type);
    if (compatible) { hook.selectGroup(compatible.id, type); return; }
    hook.selectPersonal();          // ← 没有兼容组时无条件切个人模式
    hook.setPersonalType(type);
  }, [focus?.groupType, focus?.eggGameId, hook.groups.length, hook.currentGroup?.group.id]);
  ```

  调用链：看板「去看怎么收集 / 去看怎么迭代」→ `onNavigate({ type: 'open-groups', groupType: 'stud' })`（`Dashboard.tsx:204,245`）→ `App.tsx:189` 把 `navigation.groupType` 原样传给 `CollectionGroups` → `focus.groupType` 一直是 `'stud'`（只有 `tab` / `open-collection` 意图才清掉，`navigation.ts:95-101,119-127`）。

  而 2026-10-27 起服务端只剩 `mother` 类型的小组（changelog `2026-10-27b`）。于是：

  1. 进页面时 `compatible = groups.find(g => g.groupType === 'stud')` 为 `undefined` → 切到「个人求蛋 · 求种公」；
  2. 用户点任意组名 chip → `selectGroup` 把 `currentGroup` 置 null（此时 `currentGroup?.group.id` 仍是 `undefined`，effect 不会触发）；
  3. 组详情返回 → `currentGroup.group.id` 变为 `'g1'` → **effect 依赖变化重跑** → 类型仍是 `'mother' ≠ 'stud'`、`compatible` 仍为空 → 再次 `selectPersonal()`。

  结果：从看板进入小组页后，点任何组都会在详情到达的一瞬间被踢回「个人求蛋」，看不到组头卡、成员、资源。上一版（`3824a7a`）的 effect 只依赖 `focus?.groupType / focus?.eggGameId`，不会在手动切组后重跑，属于本次改动引入的回归。

- **影响面**：触发条件是「从看板进入小组页（带 `groupType='stud'`）后点任意组名」。用户看到的是点了组名、屏幕闪一下又回到个人求蛋；底部再点一次「小组」页签（`navigate({type:'tab'})` 会把 `groupType` 清空）后才恢复正常。首次使用、从看板找组的路径基本必踩。
- **修复建议**：把「这次 focus 是否已处理」持久到本地（例如 `useRef` 记录 `focus.groupType + focus.eggGameId` 的已消费值，或者在 App 侧复用 `focusRevision / consume-focus`），effect 只在 focus 值变化时执行一次；`selectPersonal` 之后也不要在 `currentGroup` 变化时重跑。回归用例：进入页面 → 点 chip → 断言 `group-card` 仍可见。
- **置信度**：高（纯静态推演，依赖关系与调用链均已逐行核对；e2e 的 `enterGroup` 走 localStorage，不会经过带 `groupType` 的导航，所以现有测试覆盖不到）

- **文件:行号**：`src/ui/CollectionGroups.tsx:62-86`、`src/ui/demandCompletionNotice.ts:25-32`
- **问题描述**：

  ```ts
  // demandCompletionNotice.ts:28-32
  const mine = demands.filter(d => d.status === 'done' && d.claimerAccountId === claimerAccountId);
  if (mine.length === 0) return null;                 // ← 没有任何 done 单时不返回水位
  const watermark = Math.max(...mine.map(d => d.updatedAt));
  ```

  ```tsx
  if (!notice) { setCompletionNotice(null); return; }   // ← mine 为空，什么都不写
  ```

  水位只在「该组已经存在至少一条我承接的 done 单」时才会写入。用户首次进入一个从未结过单的新组时，`mine.length === 0` → 不写水位、`seenAt` 永远是 `null`；等第一条需求真正被需求方确认完成，`mine.length` 变成 1 但 `seenAt` 仍为 `null`，于是被判为「本机第一次见到这个组」→ `count: 0` → 只写水位、不弹提示。

- **影响面**：本次 B3-U04 新增的「XX 已确认你承接的 N 单需求 / 感谢你对小组的贡献」在**每个组的第一单完成时不出现**，而这恰恰是新小组、低频小组最常见的场景；用户以为贡献没被记录。第二次及以后的完成单才正常。
- **修复建议**：把「该组已初始化」与「已完成水位」分开记：首次进入组（无论有没有 done 单）就写入一个初始化标记（例如 `saveDemandCompletionSeenAt(account, groupId, 0)` 并让读取端把 `0` 视为「已初始化、无历史」），或改用 `Date.now()` 作为首次基线；同时补一条「首次进入时没有 done 单 → 之后第一单要提示」的用例。
- **置信度**：高
