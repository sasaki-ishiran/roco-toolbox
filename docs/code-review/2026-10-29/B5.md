### B5-H01 红边沉底 / 禁止勾选只在「默认目标」下生效，改动目标筛选后整段失效

- **等级**：高（实现与需求不符）
- **文件:行号**：`src/ui/MotherGroupResources.tsx:606-618`（判定）、`2036`（勾选守卫）、`1128-1133`（发布前提示）
- **问题描述**：

```tsx
const isDefaultTarget =
  !targetNature && targetBody === '大块头' && targetVoice === '+100';
const publishableRows = filtered.filter((row) => row.canSupplyMissing);
const dataIncompleteRows = filtered.filter(
  (row) => !row.canSupplyMissing && (!isDefaultTarget || row.unknownMemberIds.length > 0),
);
const blockedRows = filtered.filter(
  (row) => !row.canSupplyMissing && isDefaultTarget && row.unknownMemberIds.length === 0,
);
```

  `blockedRows`（红边、沉底、`data-blocked`、禁止勾选）额外要求 `isDefaultTarget`。用户在
  「我缺的」顶部把体型改成「小不点」、把声音改成「-100 / 婉转声 / 粗嗓门」或任选一个性格之后，
  `isDefaultTarget` 变为 false：**所有「全员可比、全员新鲜、确实没人能补」的行都会落进
  `dataIncompleteRows`**（黄边「数据不全」），`mother-blocked-section` 整段消失、行变为可勾选，
  `publishWarningFor` 还会提示「有人还没发布资源，可能有人能孵但没发布」——而实际上所有人都发布过。
- **规范依据**：`docs/产品交互规范.md:222`「全员数据新鲜且确实没人有 = 红边沉底，不能勾选发需求」；
  `:235`「只有『相关账号都新鲜 + 确实没人能孵』才硬拦」；changelog `2026-10-26c` 同一条。
- **影响面**：用户按「小不点」或某个性格去找缺口（最常见的使用方式之一）时，看到的是整页黄边、
  红边分区消失、统计「可发需求 N 项」把没来源的行也算进去；勾选发布后得到一条大概率没人接的需求，
  并且会弹出与实际数据相反的「有人还没发布」警告。
- **修复建议**：把 `isDefaultTarget` 从 `blockedRows` / `dataIncompleteRows` 的判定里去掉，
  只保留「`!canSupplyMissing && unknownMemberIds.length === 0`」→ 红边沉底；
  「`!canSupplyMissing && unknownMemberIds.length > 0`」→ 数据不全。
  若产品认为「临时目标筛选下不应硬拦」（`docs/产品交互规范.md:219` 说筛选条「只影响看什么」），
  则应改成：红边沉底恒按**任何成员是否有这颗蛋**判定、而可发/不可发按目标判定，需先定口径。
  改动后需补一条「切到小不点后红边仍在」的用例。
- **置信度**：高（可达路径明确，规范原文可引）。**修复前需确认口径二选一**（见文末）。

### B5-M01 派生层在「行 × 成员 × 性格」循环里反复重建全图鉴索引

- **等级**：中（明显性能 / 职责耦合）
- **文件:行号**：`src/ui/MotherGroupResources.tsx:294-420`（`targetRows`）、`446-464`（`selfBreedableEggIds`）、
  `712-749`（`viewerCanSupply`）、`2002`（渲染期再算一遍性格）
- **问题描述**：
  1. `targetRows` 对**每一行**调用 `suppliedNaturesOf(viewerAccountId, …)`（`365`），随后在成员循环里
     对同一个 viewer **再算一次**（`377`）；viewer 分支走 `hasStockForDemand`，而该函数内部每次都
     `eggMapOf(species)` 全表建 Map（`domain/demandCriteria.ts:78-107`）。当前图鉴 633 个物种、
     200 颗蛋，一轮 `targetRows` 约 `200 行 × 2 × 性格数` 次全表构建（≈ 数十万次 Map 写入）。
  2. `selfBreedableEggIds` 只用于蓝边框提示（`2041-2043`），却对**全部 200 颗蛋**各调一次
     `findBreedableSupply`；该函数每次重建 `eggMapOf` / `eggInfoOf` / `groupsByGameId` 三张全表 Map
     （`demandCriteria.ts:141-147`）。切目标体型/声音/性格就会整体重算。
  3. 渲染期 `const natures = configuredNaturesOf(row.eggGameId)`（`2002`）对每张卡再跑一次
     `eggNatures → defaultEggNatures`，内含 `species.find` + 可能的 `filter/Math.max`，随瀑布流展开
     到 200 行后每次按键搜索都会整批重算。
  4. `demandCenter` 对每条「我能接的」需求调用 `viewerCanSupply`；种公分支
     `findStudBreedableSupply` 会对蛋组内**每颗蛋**各跑一次 `findBreedableSupply`（又是三张全表 Map），
     需求与蛋组一多就是「需求数 × 蛋组物种数 × 全图鉴」。
- **影响面**：安卓 WebView 上切换目标筛选、或需求轮询刷新时出现可感知的卡顿（当前规模下估算几十至
  上百毫秒/次，属渲染阻塞）；不是功能错误。
- **修复建议**：沿用 B1 已引入的思路（`productionLines.ts:168-185` 的 `buildProductionIndex`）：
  在组件里 `useMemo` 一次 `eggMapOf / eggInfoOf / 物种索引`，把 `hasStockForDemand / findBreedableSupply`
  改成接收索引的重载（需与 B1 同口径，避免两套实现）；同时：viewer 的 `suppliedNaturesOf` 结果按行缓存复用；
  把 `natures` 存进 `TargetRow` 供渲染与二级页直接读，去掉 `2002` 的重复计算。
  若本轮不扩到域模型，最小改动是：去掉 `377` 的 viewer 重复计算 + `natures` 预存 + `selfBreedableEggIds`
  改成一次建索引后逐蛋判定。
- **置信度**：高（调用链与建索引点均可静态确认）；实际收益依赖真机，需在手机上跑一次确认。

### B5-M02 种公需求「已发到 X」不区分 `done`，完成后永远不能再发

- **等级**：中（状态判定不一致）
- **文件:行号**：`src/ui/MotherGroupResources.tsx:1934-1956`
- **问题描述**：

```tsx
const already = target != null && demands.some(
  (demand) => demand.demanderAccountId === viewerAccountId &&
    demand.eggGameId === -group.groupId && demand.nature === rec.natureName &&
    demand.body === target.body && demand.voice === target.voice,
);
if (already) { /* 渲染「已发到 {组名}」*/ }
```

  这里没有过滤 `status`。B3 已把完成的需求改成归档（接口仍返回 `status='done'`），于是该性格/档位的种公需求
  一旦完成，按钮永久变成「已发到 X」且不可再发；而母本需求在 `missingPublishItem`（`1102-1106`）里明确
  排除了 `done`，两侧口径相反。另外 `open / claimed / done` 三种状态在按钮上显示同一句「已发到」，
  用户分不清是待承接还是已完成。
- **影响面**：完成（或历史归档）过的种公需求无法再次发布（例如换号、精灵被放生/交易后再要一只）；
  卡片文案也无法反映「已完成」。不影响已存在数据的正确性。
- **修复建议**：`already` 只统计 `status !== 'done'` 的需求；`done` 的单显示「已完成」中性标签，
  不阻止重新发布（与母本口径一致）。若产品认为完成即目标达成、不应再发，则改成明确文案「已完成」，
  至少不要写成「已发到」。
- **置信度**：高（代码确定）；业务取舍需一句话确认。
