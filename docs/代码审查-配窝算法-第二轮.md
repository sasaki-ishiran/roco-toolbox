## 二、问题清单

[严重度: 重要] src/domain/nestPlan.ts:483 — `partner: toNestPet(A.pet === motherPet ? fatherPet : motherPet)` 恒等于 `placements[j].pet`（i<j 的第二只），而普通档正确语义应是「非母本」= 父本；当母本恰好是第二只时 `partner === mother` — 违反规则 2/6（配对必须是异性、卡片要能看清谁配谁）：`NestPlanCard.tsx` 只渲染 `mother × partners`（L160–174，**从不渲染 `view.father`**），于是普通 60%/30% 行会显示成「同一只精灵 × 自己」（例：`母方兽 ♀ × 母方兽 ♀`）；当学院小窝那只为「公」时（规则 2/3 明确允许放公），`father` 才是学院那只、`mother===partner` 又是非学院那只，卡片既不显示学院那只、也不打「学院小窝」标记 — 建议：普通档 `partner` 改用 `fatherPet`（等价于「另一个亲本」）；学院档 `partner` 用「非学院那只」（`academyPet===A.pet?B.pet:A.pet`），并让卡片额外渲染父本/学院那只，而不是用 `partner` 顶替母本。

[次要] src/domain/nestGeometry.ts:40-46（`componentOffsets`）、:56-66（`buildGroupedLayout`）、被 src/domain/nestPlan.ts:390 调用 — 组内「紧凑块」按 `ceil(√k)` 列铺，**组规模 ≥5 时并非两两相连**：size=5 的 `(4,0)` 与 `(0,2)` 中心距 `hypot(4,2)=4.472 > 4.25`（size=11 最大 `hypot(6,4)≈7.21`）— 与文件注释「组内紧凑（最大化连线）」不符（不违反规则 1 的距离阈值，因为不产生错误蛋，但也不「最大化」）：被贪心接受的某条配对若正好落在不相连的两点上，就**白占一个窝位且不产生连线**（`nestsLeft` 照扣、`slots` 照放），Pass2 未补回时该缺口还会丢覆盖 — 建议：组内改为满足「任意两点 ≤4.25 格」的排布（或直接按目标配对边布局，而非先并查集再硬塞进方格）。

[次要] src/domain/nestPlan.ts:269-277 — `academyList` 预过滤用 `candidate.groupIds.every(g => !has60.has(...))`，**多组学院候选只要有一组存在 60% 候选就整条丢弃** — 与规则 4「学院补差只服务凑不出 60% 的缺口」不符：另一组（确实凑不出 60%、只能 30%）连学院 100% 的机会都被一起砍掉，可能白白丢覆盖 — 建议：按组拆分（只保留候选里「无 60」的那几组），或把过滤下沉到 `tryAccept` 的 `addsNewGap`。

[次要] src/domain/nestPlan.ts:541 — `const unfilled: UnfilledItem[] = []` 是死赋值，随后在 L604-612 被整体覆盖 — 规则无关，纯冗余：删掉。

[次要] src/domain/nestPlan.ts:506-526（`reasonFor`）— 只检查账号里「有没有母本 + 有没有合适公」，不看这些精灵是否已被 `reserved`/`placed`；学院第二遍挤占掉唯一配对方时，会把原因报成 `no-room`（实为「配对方被占用/已被普通配对吃掉」）— 与规则 5「学院配对方不再配别的异性，宁可牺牲」导致的真实原因对不上，用户看到的提示会误导 — 建议：把「因保留/占用而不可用」也算进判定，或新增一个原因码。

[次要] src/ui/NestPlanCard.tsx:26（`CELL` 注释「2 格」）、:37（`px` 用「1 格 = CELL 像素」）— 两处单位差 2 倍：相邻两窝（相距 2 格）画成相距 `2*CELL`，而窝块只有 `CELL`，摆位图上出现整整一个窝的空隙，间距视觉失真 — 不影响算法/不重叠，仅观感：把 `CELL` 当「1 格」或让 `px` 用 `CELL/2`。

[次要] src/ui/NestPlanCard.tsx:103-106（`mergePairings`）、`src/domain/nestPlan.ts:544-553`（`chosenKeys`）— 去重/合并键用**物种显示名**（`mother.name|father.name`）而非 `pet.key`：同物种同档位同性格的多个不同个体（`captureId` 为空时内容指纹也相同）会被并成一条展示，`partners` 被塞进多只、看起来像学院式 1:2，甚至吞掉个体 — 与规则 2 的「一窝一精灵」表述不一致 — 建议：合并键改用 `pet.key`（或 include `key`）。

[次要] src/domain/nestPlan.ts:92（`NestPlan.layout`）、:597 — `checkLayout` 只校验 `buildGroupedLayout` 自身的产物，而该布局的跨组最小水平间距恒为 `GROUP_GAP=6 > 4.25`，故 `layout.ok` **恒为 true**（等价于常量），信息量为零；另 `GROUP_GAP`/`DEFAULT_NEST_COUNT`/`MAX_ACADEMY_PARTNERS` 仅模块内部使用却对外导出，`NEST_SIZE` 同理 — 可维护性：或删掉 `layout` 字段，或让它校验「实际配对是否发生串窝」（用真实 `slots` 而非构造出来的 `clusters`）。

## 三、逐条核对（未发现问题的项）

- **规则 1（距离几何）**：`nestsConnect` 用 `centerDistance`（`Math.hypot`）比 `PAIR_RANGE=4.25`，`nestsOverlap` 用切比雪夫 `<2`；(2,2)=1.414 窝✓、(3,3)=2.121 窝✓、(4,2)=2.236 窝✗、(5,0)=2.5 窝✗ 与规则示例逐条吻合。**正确。**
- **组间不串线**：`cursor += width + GROUP_GAP`，任意相邻两组最小水平间距恒为 6 格 > 4.25，跨组不可能连线（与组规模无关）。**正确。**
- **规则 2（窝=资源、配对=边）**：一只精灵只占 1 个窝（`placed` 去重），但几何枚举允许它与多个异性连线，未出现「1 只只能进 1 条配对」的错误约束。**正确。**
- **规则 3（三档遗传）**：`natureChanceFor` 学院分支按「学院那只**自己的**性格」返回 1、否则 0；普通档同性格 0.6 / 单方 0.3；双方都无目标性格的候选在生成期就被 `if (!aCarrier && !bCarrier) continue` 挡掉。**正确。**
- **规则 4（分配顺序）**：Pass1 依次 `normal60 → academy → normal30`，Pass2 用 `allowRedundant` 回收冗余线；顺序正确（`academyList` 过严见清单第 3 条）。
- **规则 5（学院唯一/最多 2 条/配对方干净）**：`academyPet` 单例锁定、`MAX_ACADEMY_PARTNERS=2`、`reserved` 使学院簇的精灵不再进普通配对、学院簇单独成组且与普通簇间隔 6 格；两个学院配对方性别相同（都异于学院那只）故彼此不会连成非目标线。**未发现脏簇。**
- **规则 6（硬约束）**：候选生成与几何复核（`targetOf`）都校验 异性 + 同档位 + `sharesGroup` + 母方物种在目标蛋组。**正确。**
- **规则 7（多账号）**：按账号切分生成、`capability` 降序挑活、`claimedCells` 保证同一格只被一个账号认领。**正确。**
- **规则 8**：`DEFAULT_NEST_COUNT=11`。**正确。**
- **边界**：空 `owned` → `plans=[]` 不抛；单只精灵 → 无候选、`slots=[]`；性别未知 → 候选生成 `filter(pet.gender!=='未知')` 已排除（上一轮 B2 已修）；蛋组为空 → `groupsOf=[]`、`sharesGroup` 恒 false、不产配对；`nestCount=0/1` → 无配对；同一只同时当母本与配对方 → 候选用 `i<j`/`partner===academy` 排除。
- **`unfilled` 与真实配对一致性**：已改为从几何 `pairings` 反推 `filledFromPairings`（L499-504）再算，上一轮 B3 已修。
- **UI/域契约**：`NestPlanCard` 引用的字段（`slots/pairings/blockedLinks/alternatives/unfilled/nestsUsed/nestsTotal/account`、`fatherPosition/motherPosition/academyParent/expected`）都与 `nestPlan.ts` 返回类型一致；`academyParent` 普通档为 `null`，与类型注释一致（上一轮已修）。异常仅在第 2 条（`partner` 语义）。
- **`petKey` 唯一性（审查点 5）**：算法内部身份判定用的是**对象引用**（`petIndex`/`placed`/`reserved`/`componentOf` 都是 `OwnedPet` 对象），`petKey` 只进入 `NestPet.key` 供 UI 用；且指纹含 `gender`，学院标签比较的是 `academyParent.key` 与 `mother/partner.key`，跨性别不可能相等 → **不会把不同精灵当同一只来复用、也不会误标学院那只**。存储侧每账号一个快照（主键=账号名），不会重复入 `owned`。真正会「张冠李戴」的是 UI 用**名字**合并（见清单第 7 条），不是 `petKey`。
