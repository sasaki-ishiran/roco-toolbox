## 六、已知差异与未覆盖

1. **页面内切换页签**不会拦截未发布的选号草稿：目前只有 `beforeunload`（关闭/刷新）提醒。设计要求的「页面内离开确认」未做，避免改全局导航。
2. live e2e 覆盖「多身份/多设备查看与共享」，**没有**用浏览器走完整「导入 fixture → 勾选 → 预览 → 发布」链路；发布链路由 API 集成测试 + 组件测试覆盖。
3. `tools/test/verify-mother-groups-schema.mjs` 使用 `node:sqlite`：需要 Node ≥23.4（本机 24.22.1）。Node 22 需加 `--experimental-sqlite`。
4. 组列表只在进入页面/切换组时刷新，成员数不会随轮询实时更新；当前组详情每 15 秒刷新。
5. 读取限流用例会真实打满 1800 次/账号，单次约 37 秒（本地）。
6. 二期：自选母本体型/声音口径、每个小号独立全收集、组主转让/移除成员、发布自动化。

## 七、旧缓存排查与手动刷新（2026-10-23b）

有朋友反馈「网页一直不更新」（iQOO 手机）。排查结论：

- **服务端没问题**：生产 `/` 与 `/sw.js` 的哈希和本地 `dist` 完全一致，`Cache-Control: public, max-age=0, must-revalidate`。
- **自动更新链路本身可用**：用真实 Chromium 复现「build A 已由 SW 接管 → 换成 build B → 普通刷新一次」，新 SW 约 2.6 秒装好、`skipWaiting` + `clients.claim` 触发 `controllerchange`，页面自动重载到 B（验证脚本为临时文件，未入库）。
- 复现时踩到的两个前提：① 模拟构建必须同时改 `sw.js` 里 `index.html` 的 precache revision，否则 workbox 直接复用旧缓存条目（真实构建由 vite-plugin-pwa 保证）；② 首启的「更新公告 / 使用教程」模态会盖住顶部按钮，验证前要先标记已读。
- 未能复现用户设备上的滞留：iQOO 自带浏览器 / 应用内 WebView 可能长期保留旧 Service Worker 与页面缓存，且不触发任何导航。

因此加了兜底：**顶部「刷新」按钮**（`app-refresh`，[hardRefresh.ts](../src/pwa/hardRefresh.ts)）——
检查更新 → 注销 Service Worker → 清空 Cache Storage → 带 `?v=<时间戳>` 重新加载。
线上实测（test 与生产各一次）：点击后约 4 秒落到 `/?v=...`，SW 重新注册、页面正常，版本号可对照。

遇到「没更新」的用户，让他先看右上角版本时间；仍是旧的就点「刷新」。

## 八、关后台回来「小组不见了」（2026-10-23c）

复现与定位（真实浏览器 + 拦截接口，均已实测）：

1. **落在别的页面**：关后台被杀 → 整页重载后 App 的 `tab` 回到「导入数据」（子视图回到「换蛋清单」），
   用户看到的是换蛋清单，以为小组没了。修法：`roco.lastTab` + `roco.swapView` 记住页签与子视图。
2. **自动跳看板把导入页弹走**：原来「有数据就自动落看板」只在首次打开时做一次；加了页签记忆后，
   重开点「导入数据」会被再次弹回看板。修法：本机已有页签记录时不再自动跳（`hasSavedTab()`）。
3. **弱网误报「没有小组」**（真实 bug）：冷启动拉组列表失败时，旧实现会 `groups=[]` + `currentGroupId=null`，
   页面显示「还没有加入任何小组，新建一个小组…」——像小组被删了。修法：失败时保留本机记住的组、
   继续拉该组详情；列表确实没拉到且没有记住的组时，显示「暂时读不到…点重试」（`mother-groups-unavailable`）。
4. 网络错误不再显示英文 `Failed to fetch`，统一成「网络连接失败，请检查网络后重试」；错误横幅加了「重试」。

线上实测（test 与生产各一次）：进入母本共享 → 整页重载 → 仍停在「换什么 · 母本共享」且小组卡片在；
弱网（接口 abort）重载 → 显示中文错误 + 重试，不再出现「还没有加入任何小组」。
