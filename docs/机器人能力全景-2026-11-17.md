## 0. 先看结论

- **群内查询类已经在正常用**：图鉴、查蛋、配种、技能、查找精灵、家园、生蛋了吗、炫彩/异色排行都能在群里直接用，不依赖工具箱网页。
- **远行商人推送是当前最稳定的一条自动线**：每天 8/12/16/20 点整拉取并推群，今天四轮都推成功了。
- **换蛋方向已经打通一半**：网页小组 ↔ QQ 群的绑定、以及「催换蛋进度」提醒已真实跑通，今天凌晨实际发出 2 条 @ 提醒。
- **「孵好自动提醒」（家园巡查）还没有真正查过一次**：线上确实有 6 笔已接单任务，但全部是旧蛋组迁移过来的遗留单，没有产线/亲本信息，巡查链路没有可查的 UID，所以观察记录和配额都是 0。
- **三个最容易误判「功能没生效」的静默点**：
  1. 换蛋桥接凭据没配：机器人**既不报错也不发消息**；
  2. 网页重新绑定/换群后，机器人里的群订阅版本号会对不上，提醒**静默不发**；
  3. 任务不是「现孵」而是旧遗留单/现货单，巡查和孵好提醒**不会产生**。

### 4.2 每条联动的前提，按「从网页到群」的顺序

**A. 换蛋提醒（含催进度、孵好提醒）**

1. **工具箱侧有小组、有成员**：提醒只认工具箱小组，不认 QQ 昵称。
2. **网页组主生成接入码**：位置在网页当前小组的机器人接入设置里；码 10 分钟有效、只能用一次，服务端只存摘要。
3. **群主/管理员在目标群发 `rc换蛋接入 <码>`**：机器人会校验群管理身份，再向工具箱兑换；成功后群里会收到「已接入『小组名』，产蛋后会在本群提醒孵蛋方」。
4. **机器人侧有桥接凭据**：`ROCO_TOOLBOX_BRIDGE_TOKEN` 必须存在且长度 ≥24，且和 Pages 的 `EGG_BOT_BRIDGE_TOKEN` 一致。没有时机器人不会报错，只是完全不工作。
5. **任务要能对上人**：任务里要能解析出「孵蛋方」的游戏 UID（`uid:数字`），并且这个 UID 在 RocomUID 里被**明确绑定**过（主 UID 或家园 UID 都算）。
6. **一个 UID 只能对应一个 QQ**：如果同一个 UID 被两个 QQ 绑定，机器人不会随便选人，会按「未绑定」处理，群里不 @ 人。
7. **群绑定必须启用且版本一致**：网页解绑/重新生成接入码/换群后，绑定版本会变；机器人里保存的是旧版本，提醒会被过滤掉。

**不通时的典型现象：**

- 完全没接入：网页能看到提醒记录，群里永远没消息。
- 只接入没绑 UID：队列被标成 `unbound`，群里没消息，也不会提示「请绑定」。
- 重新绑定后没重新接入：新提醒版本号是新的，机器人订阅还是旧的，**静默不发**。
- 机器人桥接凭据缺失/不一致：首次 `rc换蛋接入` 会提示「换蛋提醒尚未配置连接凭据」；如果之前已经接入成功、后来凭据丢了，轮询会静默跳过，群里没有任何消息，日志里也不明显。

**B. 家园巡查（孵好提醒）**

在 A 的 1~7 全部满足之外，还要：

- 任务是**已接单（accepted）且未完成**的「现孵」任务，任务行里带产线/亲本信息；
- 处于巡查时段：代码里是**北京时间 08:00 之后**才开窗，00:00~08:00 不查；
- 当日第三方查询次数没用完（预算 100 次/天，按实际 HTTP 调用计）；
- 同一个 UID 30 分钟内只查一次；
- Pages 配了 `ROCOM_PATROL_API_KEY`（已确认存在）；巡查由服务端直接请求 `wegame.shallow.ink` 的家园场景接口，网页和机器人都拿不到这把 key。

**当前为什么没跑：** 线上这个组有 6 笔 `accepted` 且未交付的任务，但它们的类型全部是 `legacy`（旧蛋组迁移单），没有产线/亲本字段，巡查代码取不到可查的 UID。所以巡查缓存、产出观察、配额三张表都是 0 行。**不是坏了，是没有可巡查的任务。**

### 4.3 哪些数据是两边共用的

| 数据 | 存在哪 | 谁在用 |
| --- | --- | --- |
| 游戏 UID（主 UID + 家园 UID） | 机器人 `rocomuser` 表 | 机器人查家园、查蛋、排行、换蛋提醒匹配 QQ |
| 工具箱小组 ID | 机器人 `subscribe.uid`、网页 `egg_bot_bindings.group_id` | 换蛋绑定 |
| QQ 群号 / 机器人账号 | 网页 `egg_bot_bindings`、机器人 `subscribe` | 决定提醒发到哪个群、由哪个机器人发 |
| 绑定版本号（bindingVersion） | 网页绑定表、机器人订阅的 `extra_data` | 防止换群/重绑后把提醒发错地方 |
| 换蛋任务、蛋名、成员显示名、催办时间 | 网页任务状态与提醒队列 | 生成提醒文案 |
| 已发送事件 ID | 机器人 `rocomtoolboxsent` | 防止重启后重复提醒 |

机器人**拿不到**：网页的恢复码、登录 token、账号密钥；网页也**拿不到**机器人的扫码登录态。两边只通过 UID、群号和任务摘要对齐。

## 6. 如果用户问「这个功能为什么没生效」，按这个顺序查

### 第一步：消息到底有没有到机器人

看 `D:\QQBot\gsuid_core\data\logs\2026-11-17.log`：

- 有没有「⚡ [收到事件]」和「⚡ [命令触发]」；
- 有没有把命令前缀 `rc` 写全；
- 有没有 `插件未启用` / `SV 未启用` / 黑名单提示。

### 第二步：插件和命令开关

- `data/plugins_configs/RocomUID.json`：插件 `enabled` 为 true，各 SV 也应为 true；
- 前缀是强制的 `rc`，空前缀不会触发。

### 第三步：推送类先看订阅在不在

机器人本地库 `data/GsData.db` 的 `subscribe` 表：

```sql
SELECT task_name, user_type, group_id, bot_self_id, uid, extra_data
FROM subscribe
WHERE task_name IN ('[洛克王国] 远行商人', '[RocomUID] 工具箱换蛋提醒');
```

- 远行商人没记录 → 没执行过 `rc开启远行商人`；
- 换蛋提醒没记录 → 没执行过 `rc换蛋接入`，或接入失败。

### 第四步：换蛋先对「群绑定」和「版本号」

```sql
-- 线上 D1
SELECT group_id, qq_group_id, bot_id, enabled, updated_at, binding_version
FROM egg_bot_bindings;
```

- `enabled` 必须是 1；
- `binding_version` 必须和机器人 `subscribe.extra_data` **完全一致**；
- 不一致的典型原因：网页解绑过、重新生成过接入码、换过群。处理方式：群管理员重新 `rc换蛋接入 <新码>`（必要时先 `rc换蛋停用`）。

### 第五步：任务是不是「现孵」

```sql
-- 线上 D1：看任务里有没有产线/亲本，而不是只有 legacy 单
SELECT group_id,
       json_extract(t.value,'$.status')  AS status,
       json_extract(t.value,'$.legacy')  AS legacy,
       json_extract(t.value,'$.type')    AS type,
       json_extract(t.value,'$.line')    AS has_line
FROM egg_matching_groups g,
     json_each(json_extract(g.state_json,'$.trades')) t
WHERE json_extract(t.value,'$.status')='accepted';
```

- `legacy=1` 或没有 `line` 的任务不会进入巡查；
- 现货单（直接交付库存蛋）也不会巡查。

### 第六步：问的人有没有和游戏 UID 对上

```sql
-- 机器人本地库
SELECT user_id, bot_id, uid, home_uids, framework_token
FROM rocomuser;
```

- 任务里的 UID 必须出现在某个用户的 `uid` 或 `home_uids` 里；
- 同一个 UID 被两个 QQ 绑定时，机器人不会 @ 人；
- `framework_token` 为空只影响「档案」类命令，不影响换蛋提醒匹配。

### 第七步：看提醒队列，而不是只看群里

```sql
-- 线上 D1
SELECT id, trade_id, side, status, attempts, error_code, created_at, sent_at
FROM egg_patrol_notifications
ORDER BY created_at DESC;

SELECT day, used FROM egg_patrol_quota;
SELECT * FROM egg_patrol_observations;
```

- `status=sent` 才代表机器人确认发出；
- `error_code=unbound` 表示找不到唯一 QQ；
- `attempts` 增加但不发，通常是发送失败或租约反复过期；
- 配额满了会停在 `quota`，第二天 00:00 归零，但 00:00~08:00 不巡查。

### 第八步：凭据和网络

- 用户环境变量 `ROCO_TOOLBOX_BRIDGE_TOKEN` 是否存在（长度 ≥24）；
- Pages 的 `EGG_BOT_BRIDGE_TOKEN`、`ROCOM_PATROL_API_KEY` 是否存在（只看名字）；
- 机器人日志里有没有 `poll_toolbox` 的 `ConnectTimeout` / `ReadTimeout`；
- 正式站 `/api/egg-bot/*` 是否能访问（有换蛋桥时应返回 401 而不是 404）。

### 第九步：上游数据源

- 管理员是否配了 wegame key；
- `data/RocomUID/merchant/merchant_today_cache.json` 当天有没有四轮；
- 商人接口在整点未刷新时，日志会写「远行商人商品未刷新，本轮跳过推送」。

### 第十步：运行环境

- 日志里是否出现「同群被多个 WS 适配器桥接」，有就只保留一个；
- 机器人是否在提醒生成的时间段断网或重启过；今天 00:17~00:48 就出现过三次桥接超时，提醒直到 01:29 才发出；
- 手机/主机网络是否能访问 `roco-toolbox.pages.dev`。

## 7. 运维注意事项（按影响排序）

1. **别把测试站当成正式站用**：换蛋桥只连正式站，测试站的操作不会产生群提醒。
2. **重新绑定后一定要重新接入**：网页改绑/换群后，群订阅版本会失效，表现为「网页有记录、群里没消息」。
3. **桥接凭据缺失是静默失败**：没有 `ROCO_TOOLBOX_BRIDGE_TOKEN` 时，机器人既不报错也不发消息；排查时先确认这个环境变量。
4. **旧任务不会巡查**：只有带产线/亲本的「现孵」任务才会进入家园巡查；旧蛋组遗留单只支持手动催进度提醒。
5. **一个 UID 只能对应一个 QQ**：多绑不会自动选人，宁可发不出去也不发错人。
6. **提醒是「一次机会」和「可重试」两种语义**：催进度提醒失败一次就标记失败，不会无限重试；孵好产出提醒会按退避重试。
7. **商人推送有筛选就会静默跳过**：设置过 `设置商人推送` 后，不包含目标商品的轮次完全不会发，这是设计行为。
8. **帮助图不能当命令清单**：帮助里缺换蛋接入、换蛋停用、今日远行商人、扫码登录等一批命令，还把 `远行商人推送` 写成了不存在的命令。
9. **同一个群只留一个适配器**：日志已经报过 HTTP 与 NoneBot2 同时桥接同群，建议尽快收敛。
10. **巡查时段是 08:00 之后**：凌晨 00:00~08:00 不会查家园，不要在这个时间段判断「巡查坏了」。
