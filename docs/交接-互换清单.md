## 关键设计（改之前先看）

1. **名单里的「我」= 发布方**（手里有全部数据的那台设备）。加入方按 `role` 翻转标签：
   - 发布方：「他能给我孵」= `heCanHatch`，「我能给他孵」= `iCanHatch`
   - 加入方：反过来
2. **云端只存「算好的名单 + 每条的 owner/done/at」**，不传精灵数据 —— 加入方不需要有对方的账号数据。
3. `owner` 存发布方视角（`'mine' | 'theirs' | null`），界面按 `role` 翻译成「我方 / 对方」。
4. **合并必须按条**（`at` 大者赢），不要改成整份覆盖，否则两人同时勾不同条会互相冲掉。
5. 分享码即权限：拿到码的人都能读/改；泄漏就「退出共享」后重新发布换一个码。

## 待办 / 已知缺口

1. **真机双人验收还没做**：两个手机各打开一次 → 一人勾选，另一人 15 秒内应看到（这是唯一还没实测的环节）。
2. 互换清单**没有 e2e**：e2e 的 preview 里没有 Functions（`API_BASE=''`），调接口会 404；目前靠领域单测 + 手工 API 往返。
3. 「退出共享」只清本地 code，**不删云端**；要删除得加接口。
4. 分享码不能原地重置（只能退出再发布）。
5. 互换清单的账号选择**独立于顶部 AccountFilterBar**（有意：这里分的是「我方/对方」，不是全局筛选）。
6. 生产已上线，**没有加 changelog**（按用户「技术向不发公告」的约定）。
7. 发布方目前支持多账号勾选（如石岚 + 昭序），其余账号自动算对方。
