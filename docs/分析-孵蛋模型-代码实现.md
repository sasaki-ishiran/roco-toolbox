## 1. 现状评审

### 1.1 贪心顺序（`nestPlan.ts` L225-252）

现状：`① 普通 60% 主力 → ② 学院补差(1 个目标) → ③ 普通 30% 兜底`，每步 `accept(candidate, 2)`（恒定成本 2 个窝）。

问题：

- **顺序把「概率档」当第一排序，把「窝位/精灵稀缺度」当第二排序。** 60% 先手会先吃掉**互斥精灵**（见 1.2），学院（唯一 100% 档）只能捡 60% 吃剩的缺口。用户已明确学院是「精度高、产能低、稀缺」，先保 60% 的大方向没错，但「先到先得」式排序没做任何全局权衡：一个高价值缺口若同时能 60% 与被学院 100% 覆盖，会被 60% 锁死，学院白闲置。
- **`byGroupsThenStable`（L118-121）只按「覆盖组数」排，不算「新缺口数」。** 一个覆盖 3 组但 0 个新缺口的候选择序靠前，一个覆盖 2 组全是新缺口的候选择序靠后；虽然后者会被 `addsNewGap` 放行、前者会被拒，但**排序与筛选用了两个不一致的度量**，局部会产生次优（先被低收益大组候选占用精灵）。
- **`normal30` 排在学院之后**，且学院在这一轮里恒定只取 1 条（见 1.4），导致 30% 兜底的实际决策空间被学院先占的精灵压缩。

### 1.2 pet 互斥的落地方式（L226、L235-246）

`used: Set<OwnedPet>` 用**对象引用**做 key，`accept` 里 `used.has(p1) || used.has(p2)` 就拒。

问题：

- **互斥粒度是「精灵 = 一个窝位」，与游戏机制不符。** §2.3 明确「一个公可以同时跟范围内多只母配对」——同一只种公理论上能服务同一连通组里多条连线。当前模型强制 1 只 = 1 窝，**复用率被压死**；而隔离式摆位又把簇间连线全切断（`CLUSTER_GAP=12`），于是「一只万能种公省窝」这条最强的省窝路径根本走不通。
- **互斥只看「被谁用了」，不看「多稀缺」。** 一只双蛋组、双性格的公可能同时是 3 个缺口的最优父本，贪心按遍历顺序先到先得，后续高价值缺口只能换更差的父本。缺一个 `demand[petId]`（该精灵被多少候选需要）来给「稀缺精灵」加价。
- **学院 1:2 与 pet 互斥天然冲突**：学院那条的候选是 `(academy, partner)` 二元组，第 2 个 partner 必须复用同一只 `academy`——而 `used` 一旦把 `academy` 标记为已用，第 2 条按现有 `accept` 恒被拒。这是 1:2 无法在现结构里表达的直接原因（见 1.4）。

### 1.3 「只补新缺口」的落地方式（L231-246、L306-308）

`addsNewGap(candidate)` + `filledCells: Set<natureName|grade|groupId>`：

- `accept` 内 `if (!addsNewGap(candidate)) return false;` —— **硬门槛**，一个缺口格被填后就再也不接受任何指向它的候选（含学院第 2 条、含「同目标再来一只更高的公」）。
- `filledCells` 的 key 是**缺口格**（蛋组×性格×档位），不是「配对」——所以同一格的第 2 条配对天然被判为「无新缺口」而拒。这对「普通窝去重」是对的，但对「学院买命中率/催化」是错的。
- **归并多组的候选只要求「任一为新」**（`.some`），若同时含新组与旧组会被整体接受，语义尚可；但 `academyList` 的预过滤（L215-223）用的是 `every(groupId => !has60 ...)`（**全部**组都得没有 60 路径），于是一个「G1 无 60、G2 有 60」的学院候选被整条排除，**丢掉了它对 G1 的 100% 价值**（过度严格）。
- `unfilled` 只输出 `{groupId,natureName,grade}`，**不带原因**（窝位不足 / 无配对 / 无性格 / 缺异性 / 母方不在组），前端与用户都无法解释"为什么没排上"。

### 1.4 学院被限制成 1（L249-251）

```ts
for (const candidate of academyList) {
  if (accept(candidate, 2)) break; // 学院一次只服务 1 个目标
}
```

- `break` 硬编码，注释也写明"一次只服务 1 个目标"。这**既丢了 1:2 的产能设计**（`breedPlan.ts` 里 `MAX_PARTNERS_PER_ACADEMY = 2` 才是用户确认的口径），又与 §四用户诉求「第 2 条可以补同一目标」直接冲突。
- 成本模型错误：学院 1:2 应是 `1 个学院窝 + 2 个普通窝 = 3`，现结构一律按 `2` 记账，`nestsUsed` 会算少。
- `clusterPets`（L281-293）虽然写成 `[academyParent, ...partners]`，暗示支持多 partner，但 `NestPairing` 的 `partner: NestPet`（单值）与 `used` 互斥让它实际上永远只有 1 个 partner——**数据结构与摆位代码已经"半支持"1:2，唯独分配逻辑不支持**。

### 1.5 与旧 `breedPlan.ts` 的关系

- `breedPlan.ts`（看板仍在用，`Dashboard.tsx` L3/L122-124 引用）：学院中心、**只有 100% 一档**、无几何、无档位排序；`MAX_PARTNERS_PER_ACADEMY=2`、按学院父本分组取 top2。
- `nestPlan.ts`（**无任何 UI 引用**，仅 `nestPlan.test.ts` 消费；Grep 确认）：档位排序 + 几何 + 隔离式摆位 + 按账号。**设计上是 breedPlan 的超集**。
- 三处重复实现同一套领域判定，已经出现口径漂移：
  - `computeStudCoverage`（`studCoverage.ts` L94-99）自带一套简化的「学院可配」判定（不校验「母方在目标蛋组」、不看档位）；
  - `breedPlan.buildBreedSuggestions` 一套；
  - `nestPlan` 一套（最严，`classifyGrade` + `inGroup(mother)` 都查）。
  - 例：`classifyGrade(pet,'perfect')` 要求 `|dB|==100`，但 `studCoverage` 里 `academy` 判定按 `nature` 命中即算 `breedable`，**不看声音档**——三处对"能不能孵"给出的答案可能不一致。
- 结果：看板显示的是旧的、不含几何/档位排序的建议；新的更强实现躺在仓库里没人用。这是**当前最大的结构风险**（功能已实现却不生效 + 逻辑三份漂移）。

### 1.6 其它实现层面的观察

- `byPair` 去重 key（L165）用 `tier|nature|grade|keyOf(p1)|keyOf(p2)`，`keyOf` 走 `Map<OwnedPet,number>`（引用身份，正确）。但跨 cell 归并只在「同 tier+同 nature+同 grade+同两只精灵」时发生——同一对能服务两个**不同性格**缺口时无法归并（合理，因为性格目标不同）。
- 枚举复杂度：对每个 cell 都做 `graded` 过滤 + 双层 `for` 组合 → **O(C · P²)**（C=缺口格数，P=账号内精灵数）。P 到几百、C 到几十时是主要热点，且每 cell 重算 `classified`/`groupsOf`，有重复计算。
- `checkLayout`（`nestGeometry.ts` L71-92）是 **O(N²)**（N=窝数 ≤11，可忽略），但**只校验跨簇连线与重叠，不校验「同簇内是否两两连通」**。一旦 1:2 或未来出现 >3 的簇，可能出现"以为同簇其实断了"的静默错误。

## 2. 改造方案（设计层，不写实现）

### 2.1 「不要求、但尽量补新缺口」的表达式

核心思路：**把「硬可行性」与「偏好打分」彻底分离**。可行性只负责"这个配对合不合法"；打分负责"在合法的里挑最好的"。

**候选分级（显式 rank），让"尽量"可测：**

| rank | 定义                            | 说明                    |
| ---- | ------------------------------- | ----------------------- |
| R1   | 补新缺口 且 60%                 | 主力                    |
| R2   | 补新缺口 且 学院 100%           | 稀缺缺口（无 60 路径）  |
| R3   | 补新缺口 且 30%                 | 兜底                    |
| R4   | **不补新缺口**，但提升命中/催化 | 学院第 2 条、同目标冗余 |

**打分函数（纯函数草案）：**

```ts
// 单位：缺口格 key = `${natureName}|${grade}|${groupId}`
export interface Candidate {
  // 泛化自现 Candidate，见 §4
  tier: NestTier;
  natureName: string;
  grade: PetGrade;
  groupIds: number[];
  academy: OwnedPet | null; // 学院档：学院那只；普通档：null
  core: OwnedPet; // 普通档=p1；学院档=学院那只
  partners: OwnedPet[]; // 学院档=配对方列表（1~2）；普通档=[p2]
}

export const countNewCells = (c: Candidate, filled: Set<string>): number =>
  c.groupIds.reduce(
    (n, g) => n + (filled.has(`${c.natureName}|${c.grade}|${g}`) ? 0 : 1),
    0,
  );

/** 分数越大越优先。newCells 给大权重，保证「尽量补新缺口」；tierWeight 让 100% > 60% > 30%。 */
export const scoreCandidate = (
  c: Candidate,
  filled: Set<string>,
  demand: Map<OwnedPet, number>, // 该精灵被多少候选需要（稀缺度）
): number =>
  10 * countNewCells(c, filled) + // 新缺口：主导项（"尽量"）
  2 * c.groupIds.length + // 一次补多组
  1 * TIER_CHANCE[c.tier] - // 档位权重（1 / 0.6 / 0.3）
  1 * (c.academy ? (demand.get(c.academy) ?? 0) : 0) -
  // 稀缺精灵加价（可选，第一版可省）
  1 * c.partners.reduce((n, p) => n + (demand.get(p) ?? 0), 0);
```

**两遍扫描（推荐，兼顾"不要求"与"尽量"）：**

- **Pass 1（主扫描，仍然"只补新缺口"）**：按 `scoreCandidate` 降序，`accept` 时硬性要求 `countNewCells(c, filled) > 0`。这一遍保证「尽量补新缺口」这个主目标，且与现状行为向后兼容。
- **Pass 2（补位扫描，"不要求"）**：用剩余窝位，接受 `countNewCells === 0` 但**有正收益**的候选——即 R4（学院第 2 条 / 催化 / 同目标冗余）。Pass 2 里若仍有 `countNewCells > 0` 的候选（因 Pass 1 精灵互斥漏掉的），**Pass 2 排序仍把它们排在 R4 之前**（等价于"尽量补新缺口"的软约束）。

> 一句话：`不要求` = Pass 2 不再用 `addsNewGap` 当门槛；`尽量` = 打分里 `newCells` 权重最高，两遍排序都优先新缺口。

**候选分级 vs 两遍扫描：建议两者都用**——分级用于**排序/展示/测试断言**（可读、可快照），两遍扫描用于**资源受限时的退化顺序**（先保主目标，再用余量买命中率）。

### 2.2 学院恢复 1:2 的分配逻辑

**结构改造**：把 `NestPairing` 从 1:1 升级为「学院组」概念：

```ts
export interface AcademyGroup {
  academyParent: OwnedPet; // 学院小窝那只（带目标性格 + 目标档位）
  partners: OwnedPet[]; // 1~2 只异性、同档位、共蛋组、母方在目标组的配对方
  groupIds: number[]; // 这组覆盖/服务的缺口组
  natureName: string;
  grade: PetGrade;
}
```

**分配算法（学院部分）：**

1. **选学院父本**：遍历所有 `graded ∩ nature===target` 的精灵当 `academyParent`；对每个父本枚举可行 partner（异性 + 同档 + 共蛋组 + 母方在该组）。
2. **优先选「只差学院」的缺口父本**：保留现状"学院补差"的动机——用 `academyList` 时，把「该缺口无 60 路径」作为**加分项**而非**硬过滤**（修掉 §1.3 里 `every` 过度严格的问题：改为 `some(groupId => !has60)`，只要**有一个**组没有 60 路径就保留，该组按 100% 计入）。
3. **Partner #1**：在候选里取 `scoreCandidate` 最高；**尽量补新缺口**（Pass 1 语义）。
4. **Partner #2**：
   - **允许同目标**（用户诉求）：`countNewCells === 0` 也不再拒绝；
   - 优先选能补**另一个**新缺口的 partner；若没有，则选**同目标**的另一只异性（买"多一条连线 → 绿窝更早命中、顺带催化"）；
   - 需与 `academyParent`、`partner #1` 都不互斥（partner #1 与 #2 必须是**不同精灵**，但可以同性别/同组）。
5. **成本**：`costOf(group) = 1 + partners.length`（1:2 → 3 个窝；1:1 → 2 个窝）。`nestCount` 预算里按实际占用扣。
6. **蛋落哪**：`expected.species` 仍随母方（`academyParent.gender==='母'` 则为学院那窝的物种，否则为 partner 的母方物种）。

**复杂度**：枚举学院候选 **O(C · P²)**（与现状同阶）；1:2 的 partner #2 只是对已枚举的 partner 集合再取一次 top，**O(K log K)**，不增阶。

### 2.3 是否需要贪心之外的机制

**结论：第一期保留贪心 + 打分 + 局部交换（swap），暂不引 ILP。**

- 问题本质：在「精灵互斥 + 窝位预算」下最大化覆盖（缺口格 + 档位权重）= **带冲突图的加权最大覆盖 / 加权集合覆盖**，是 **NP-hard**。
- 贪心：对集合覆盖有 **H_n ≈ ln n 的近似比**，分配问题上有 1/2 近似（多种子模覆盖），**天然适合"可配建议"这类需要可解释、要稳定的场景**，且快（毫秒级）。
- 局部搜索（推荐加）：贪心后做**成对交换（swap）**——尝试用被拒候选 `c'` 换掉已接受候选 `c`：若 `score(c', filled − cells(c)) > score(c, ...)` 且两者都可行（精灵/窝位重新校验）则换。迭代到无改进或达上限 K。复杂度 **O(I · A · R · G)**（I=迭代轮数、A=已接受数、R=被拒数、G=平均组数），A,R 都是几十量级、I 设小常数，代价可忽略。**收益主要在精灵互斥造成的"先到先得"次优上**。
- 匈牙利/指派：只适合「已定好哪些配对，把配对铺到窝位」这一子问题（**O(n³)**，n≤11，几乎免费），**但表达不了多组候选、档位权重、催化/1:2**，不是主问题的解药。
- ILP / 分支定界：规模小（候选几十、约束精灵互斥 + 11 窝）**可精确求解**，但引入求解器/自研 B&B 的维护成本高，且**隔离式摆位已经把复用砍掉**，问题树很浅，精确解相对贪心的增量收益有限。**建议第二期（引入产出速率/CD 目标函数后）再评估**，届时可把数学建模专家给出的"期望填满时间"当目标函数，用 ILP 校验贪心解最优性缺口。

**可测切分（纯函数边界）：**

```ts
// 全部纯函数、无 I/O、无 Date/Math.random，便于单测与快照
enumerateCandidates(pets, cells, mode): Candidate[]                 // O(C·P²)
scoreCandidate(c, filled, demand): number                           // O(G)
assign(candidates, nestCount): AssignResult                         // 贪心+两遍扫描
improveBySwaps(accepted, rejected, nestCount): AssignResult         // 局部交换，限迭代
placeClusters(accepted): { clusters, slots, isolation }             // 几何，O(N²)
buildPlanForAccount(account, pets, cells, nestCount): NestPlan      // 编排
buildNestPlans(input): NestPlan[]                                   // = 分组 + 循环 + 排序
```

`assign` 与 `placeClusters` 之间**零耦合**（前者只产出 `Candidate[]`，后者只吃 `Candidate[]` 出坐标）——这样"算法对不对"和"摆位对不对"可以分开测。

## 3. 几何层改造（曼哈顿 ≤5 → 欧氏 ≤2.125 窝）

### 3.1 单位换算（关键前提，先对齐口径）

蛋神助手截图 `补充数据/小窝排布可视化.jpg` 标注「中心距离 ≤ 2.125 个窝」，并列出 `1 / 1.414 / 2 / 2.062 窝`。
逐一代回「小窝 2×2 格、位置取左上角整数坐标」的现有模型：

- 1 窝 ⇔ 相邻两窝左上角差 `(2,0)` → 中心距 **2 格**；
- 1.414 窝 ⇔ `(2,2)` → √8 = 2.828 格 ÷2 = **1.414 窝** ✓；
- 2 窝 ⇔ `(4,0)` → 4 格 ÷2 = **2 窝** ✓；
- 2.062 窝 ⇔ `(4,1)` → √17 = 4.123 格 ÷2 = **2.062 窝** ✓（截图里 `#1 ↔ #7` 正是斜向一格错位）。

→ **1 窝 = 2 格，阈值 2.125 窝 = 4.25 格**。该口径能唯一解释截图上全部四个距离值，可信度高。

### 3.2 改造点

```ts
// nestGeometry.ts（改造后草案）
export const CELLS_PER_NEST = 2; // 每窝 2×2 格
export const PAIR_RANGE_NESTS = 2.125; // 蛋神助手口径
export const PAIR_RANGE_CELLS = PAIR_RANGE_NESTS * CELLS_PER_NEST; // 4.25 格
const PAIR_RANGE_SQ = PAIR_RANGE_CELLS * PAIR_RANGE_CELLS; // ≈18.0625

/** 中心欧氏距离（格）。 */
export const centerDistanceCells = (a: NestPosition, b: NestPosition): number =>
  Math.hypot(a.x - b.x, a.y - b.y);

/** 中心欧氏距离（窝，UI 显示用，对应截图上的「x.xxx 窝」）。 */
export const centerDistanceNests = (a: NestPosition, b: NestPosition): number =>
  centerDistanceCells(a, b) / CELLS_PER_NEST;

/** 两窝能否配对：中心欧氏 ≤2.125 窝。比较平方，整数输入、无开方、无浮点边界抖动。 */
export const nestsConnect = (a: NestPosition, b: NestPosition): boolean => {
  const dx = a.x - b.x;
  const dy = a.y - b.y;
  return dx * dx + dy * dy <= PAIR_RANGE_SQ; // 整数时等价于 dx²+dy² ≤ 18
};
```

- `nestsOverlap` **不变**（切比雪夫 `<2`，是"占位不重叠"的几何定义，与配对阈值无关）。
- 原 `centerDistance`（曼哈顿）若仍被需要，改名保留为 `centerDistanceManhattan`；`nestGeometry.test.ts` 里对曼哈顿与 `PAIR_RANGE=5` 的断言**全部需要重写**（属迁移动作，本文不动）。
- `checkLayout` 不用改逻辑（它调 `nestsConnect`/`nestsOverlap`），但**阈值一变，跨簇间距的成立性要重新验算**（见 3.3）。

### 3.3 `buildIsolatedLayout` 的隔离间距还成立吗？

**簇内（横排 `0,2,4`，即 3 窝）：仍两两连通。**
最大簇内距离 = `(4,0)` = 2 窝 ≤ 2.125 ✓；`(0,0)-(2,0)=1窝`、`(2,0)-(4,0)=1窝`、`(0,0)-(4,0)=2窝`。→ 现网最大簇 = 3（学院 1:2），安全。
⚠️ 但这是**临界**的：若簇做到 4 窝（横排 `0,2,4,6`），首尾 `(6,0)=3窝 > 2.125` **断了**，簇不再是"全连通团"。所以规则应固定为：**单簇横排 ≤3 窝**（学院 1:2 恰好是上限）。

**簇间（`CLUSTER_GAP=12`）：仍隔离，但已不是最紧值。**
两簇最小横向距离 = `CLUSTER_GAP − 前簇最大 offset`。

- 前簇 ≤3 时最大 offset = 4 → 最小距离 `12 − 4 = 8 格 = 4 窝`。判定用**格**做平方比较：`8² = 64 > 18.0625`，故**不连通** ✓（换窝：`4窝 > 2.125窝`，一致）。
- 隔离成立的充要条件：两簇任意两窝的**欧氏格距平方 > 18.0625**（即格距 ≥ 5 格）。横向最小格距 = `CLUSTER_GAP − maxOffset(前簇)`，要求 `≥ 5` → 前簇 ≤3 时 **`CLUSTER_GAP ≥ 9`**（4 格距会连：`4²=16 ≤ 18.0625`；5 格距不连：`5²=25 > 18.0625`）。
- 结论：**`CLUSTER_GAP=12` 在新口径下仍成立**（余量 `12−4=8` 格 ≥ 5），但**可以收紧到 9**；若为了画布美观可保留 12。更稳妥的写法是**按前簇实际宽度动态算**：`base_i = base_{i-1} + maxOffset_{i-1} + SAFE_GAP`，其中 `SAFE_GAP = 5`（格）。这样簇大小变化时不会静默串窝。

**新口径相对旧口径的连通集差异（具体到 offset，供回归断言）：**

| 左上角差 (dx,dy) | 欧氏距离（窝）    | 旧（曼哈顿≤5）  | 新（欧氏≤2.125） |
| ---------------- | ----------------- | --------------- | ---------------- |
| (3,3)            | √18/2 = **2.121** | ❌ 曼哈顿 6 > 5 | ✅ **新增连通**  |
| (0,5) / (5,0)    | 5/2 = **2.5**     | ✅ 曼哈顿 5 ≤ 5 | ❌ **取消连通**  |
| (1,4)/(4,1)      | √17/2 = 2.062     | ✅ 5 ≤ 5        | ✅ 保留          |
| (2,3)/(3,2)      | √13/2 = 1.803     | ✅ 5 ≤ 5        | ✅ 保留          |
| (0,4)/(4,0)      | 2.0               | ✅ 4 ≤ 5        | ✅ 保留          |

即：**新增 `(±3,±3)`，取消 `(0,±5)/(±5,0)`**，其余不变。

### 3.4 校验方式

1. **阈值一致性测试**：枚举 `(dx,dy) ∈ [-6,6]²`，断言 `nestsConnect` ⇔ `dx²+dy² ≤ 18.0625`（整数即 ≤18）；显式断言 `(3,3)=true`、`(0,5)=false`、`(4,1)=true`。
2. **距离标签测试**：`centerDistanceNests({0,0},{4,1})` ≈ 2.062，`(2,0)` = 1，`(2,2)` ≈ 1.414 —— 与蛋神助手截图逐条对齐。
3. **簇内连通性**（新增校验，补 `checkLayout` 的盲区）：对每个簇做 BFS，断言单簇横排 ≤3 时连通分量 = 1；若允许 >3，报 `clusterDisconnected` 告警。
4. **隔离回归**：对 `buildIsolatedLayout(sizes)` 全枚举几组 `sizes`（含 `[3,3,3]`、`[2,2,2,2,2,1]`），断言 `checkLayout(...).ok === true` 且最小跨簇格距 > 4.25。

**改造成本评估：低。** 变化集中在 `nestGeometry.ts` 的 3 个常量 + 2 个函数；`nestPlan.ts` 只通过 `buildIsolatedLayout/checkLayout/nestsConnect` 间接依赖，**调用面无需改**。主要成本是**重写 `nestGeometry.test.ts`** 与重新验证 `CLUSTER_GAP`。风险点仅一个：**若真实阈值不是 2.125 而是别的（三家口径不一）**，务必先把 `PAIR_RANGE_NESTS` 做成**单一常量 + 可配置**，别把 4.25/18.0625 散落多处。

## 4. 接口 / 数据结构

现有 `NestPlan { pairings, slots(含坐标), unfilled, nestsUsed/Total, clusters, isolation }` 对「一键配窝 + 后续可视化」**不够**，缺以下字段：

| #   | 缺口                                                                      | 建议补充                                                                                                                                                                                       |
| --- | ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- | ------------------------------------------------------------------------------------------------ | ----------- | --------------------- |
| 1   | **学院 1:2 表达不了**：`NestPairing.partner` 是单值、`academyParent` 单值 | 引入 `AcademyGroup{academyParent, partners[], groupIds, natureName, grade}`；或 `NestPairing.partners: NestPet[]`（普通档长度 1，学院档 1~2）                                                  |
| 2   | **没有连线（连线=可视化核心）**                                           | 新增 `links: Array<{from: SlotId, to: SlotId, tier, natureChance, expected}>`，或给每个 `pairing` 挂 `slotIds: SlotId[]`。截图那种"公↔母线 + 距离标签"需要显式边                               |
| 3   | **slot 无稳定身份**                                                       | `NestSlot` 加 `id: string`（如 `acct/cluster/index`）供前端 key 与连线引用；`NestPet` 加 `petId`（captureId 兜底指纹，复用 `breedPlan.petKey`），否则跨视图（我的精灵/母本清单）无法定位同一只 |
| 4   | **连线/距离标签缺"单位+中心"**                                            | slot 加 `center: {x,y}`（或提供 `nestCenter(pos)`），`NestPlan` 加 `unit: 'cell'` / `cellsPerNest`，前端才能画"2.062 窝"                                                                       |
| 5   | **簇信息太薄**：`clusters: NestPosition[][]` 只有坐标                     | 升级为 `Array<{id, slotIds: SlotId[], bbox:{minX,minY,maxX,maxY}}>`，画布可直接布局/缩放                                                                                                       |
| 6   | **unfilled 无原因**                                                       | `unfilled: Array<{groupId,natureName,grade, reason: 'noNest'                                                                                                                                   | 'noPair'  | 'noNature'                                                                                       | 'noPartner' | 'motherNotInGroup'}>` |
| 7   | **档位/角色不显式**                                                       | slot 加 `role: 'academy'                                                                                                                                                                       | 'partner' | 'normal'`（现在只有 `academy: boolean`，看不出谁是 partner #1/#2）；pairing 里已可推导，建议显式 |
| 8   | **运行时状态无处放**（第二期：绿窝 CD、蛋占位退出计数）                   | 预留 `slot.status?: {academyCooldown, eggOccupied}`，**第一期不填**，但结构上别事后硬塞                                                                                                        |
| 9   | **多账号坐标系**                                                          | 返回 `NestPlan[]` per 账号，坐标是"每账号一套家园"；若一次画多账号，需要顶层 `{plans, unit}` 并明确不同账号**不能共用画布坐标系**（否则簇会假重叠）                                            |

**草案（增量、保持向后兼容）：**

```ts
export type SlotId = string;

export interface NestSlot {
  id: SlotId;
  position: NestPosition; // 左上角 2×2
  center: NestPosition; // = position + 1（画连线用）
  pet: NestPet;
  cluster: number;
  role: "academy" | "partner" | "normal";
  petId: string; // captureId 兜底指纹
}

export interface NestLink {
  from: SlotId;
  to: SlotId;
  tier: NestTier;
  natureChance: number;
  distanceNests: number; // 前端直接显示「x.xxx 窝」
}

export interface NestPlan {
  account: string;
  pairings: NestPairing[]; // academy 组用 partners[] 表达 1:2
  slots: NestSlot[];
  links: NestLink[]; // ← 新增
  clusters: Array<{
    id: number;
    slotIds: SlotId[];
    bbox: { minX: number; minY: number; maxX: number; maxY: number };
  }>;
  nestsUsed: number;
  nestsTotal: number;
  isolation: LayoutReport;
  unit: { cellsPerNest: number };
  unfilled: Array<{
    groupId: number;
    natureName: string;
    grade: PetGrade;
    reason: UnfilledReason;
  }>;
}
```

## 5. 测试策略（该补的单测清单）

**几何层（`nestGeometry.test.ts`，需重写阈值相关断言）**

1. 阈值一致性：(dx,dy)∈[-6,6]² 全枚举 ⇔ `dx²+dy² ≤ 18.0625`；点断言 `(3,3)=true`、`(0,5)=false`、`(4,1)=true`、`(2,3)=true`。
2. 距离标签：`centerDistanceNests` 输出 `1 / 1.414 / 2 / 2.062`（对齐蛋神助手截图）。
3. 簇内 3 窝（横排 0,2,4）两两连通；簇内 4 窝（0,2,4,6）首尾**不**连通（边界）。
4. `buildIsolatedLayout([3,3,3])` / `[2,2,2,2,2,1]` 隔离 `ok===true`，且跨簇最小格距 > 4.25。
5. 新增「同簇连通性」校验：人为造断簇 → 报 `clusterDisconnected`。

**一键配窝（`nestPlan.test.ts` 扩展）**

6. **窝位不够**：`nestCount = 2/3/4` 分别断言取舍——保 60%、学院按 2 或 3 个窝记账、剩余进 `unfilled`（含 `reason`）。
7. **无 30% 缺口**：所有 gap 都有 60% 路径 → 学院不接手（`academyList` 应为空/不产生 academy pairing）。
8. **学院当公 / 当母**（两条）：
   - 学院那只是公 → 后代物种随侧边母方，`expected.species === partner 的物种`；
   - 学院那只是母 → `expected.species === 学院那只的物种`；两种都断言 `natureChance===1`。
9. **「不要求但尽量补新缺口」**（核心新用例，两条）：
   - 场景 a：学院 partner #2 能补**另一个**新缺口 → 断言优先生成补新缺口的那条（rank ≠ R4）；
   - 场景 b：partner #2 只能**同目标** → 断言**仍然生成**（`countNewCells===0` 也接受）、`tier==='academy'`、`natureChance===1`、`nestsUsed` 扣 3。
10. **学院 1:2 vs 1:1**：只有 1 个可行 partner 时不硬凑第 2；有 2 个时按 rank 选；成本 `1+partners.length` 正确。
11. **pet 互斥**：一只双蛋组公不得同时出现在两条配对；断言 `slots` 里 `petId` 唯一（学院父本在 1:2 里被 partner #1/#2 共享的**例外**要有明确断言）。
12. **跨账号**：A 账号学院父本不得配 B 账号 partner；1:2 同样按账号隔离（扩展现有用例）。
13. **隔离失败路径**：把 `CLUSTER_GAP` 人为调小（测试内参数化）→ `plan.isolation.ok===false` 且 `crossLinks` 非空；合法布局恒 `ok===true`。
14. **缺口语义去重**：同一 `(nature,grade,group)` 被两个不同父本覆盖 → 只算 1 格；`unfilled` 无重复项。
15. **排序稳定性**：同 `groupIds` 数量、同 rank 时按 `natureName → groupId` 稳定排序（防快照抖动）。
16. **空输入**：无精灵 → `pairings=[]`、`unfilled=全部 cells`、`slots=[]`。
17. **30% 兜底 + 学院并存**：学院拿 1 个目标后，另一目标仍可由 `normal30` 补上（现有用例的 1:2 版本）。
18. **档位权重**：同一缺口既有 60% 又有 30% 候选 → 断言选 60%。

## 6. 迁移路径（新 `nestPlan` 替换看板旧 `breedPlan`）

**现状关键事实（决定迁移几乎零风险）：**

- `buildNestPlans`（nestPlan）**未被任何 UI 引用**——Grep 全仓只有 `nestPlan.ts` 与 `nestPlan.test.ts`。
- 看板 `Dashboard.tsx`（L3/L122-124）只用 `buildBreedSuggestions`（breedPlan）。
- 因此**可以并行新增、最后切换**，不存在"原地改坏看板"的风险。

**分步路径：**

1. **几何层先行**（独立、无 UI 依赖）：`nestGeometry.ts` 改阈值 + 重写几何单测（§3、§5.1-5.5）。此步纯 domain，可单独合并。
2. **nestPlan 结构升级 + 算法**：加 `AcademyGroup/partners/links/slot.id/reason`，加打分 + 两遍扫描 + 局部交换（§2）；`buildNestPlans` 保持签名兼容（新字段可选）。补 §5.6-5.18。
3. **新增只读可视化组件**：消费 `NestPlan.slots + links`（SVG 画 2×2 方块 + 连线 + 距离标签，风格对齐蛋神助手截图）。此时看板**同时**展示旧 `breedPlan` 与新面板，肉眼比对。
4. **切换默认**：给新面板加 feature flag（本地开关 / URL query），灰度若干账号比对后设为默认；旧 `breedPlan` 区块降级为「旧版建议」或移除。注意保留 `BREED_EMPTY_NOTE` 之类的**无配对引导文案**（新实现要能生成等价文案，否则用户会失去兜底提示）。
5. **收敛重复实现**：`breedPlan.buildBreedSuggestions` 被替换后，评估 `computeStudCoverage` 里的简化「学院可配」判定是否统一到 `nestPlan`/共享纯函数，消除 §1.5 的三处口径漂移。`breedPlan.ts` 在确认无引用后再删（含 `breedPlan.test.ts`）。

**不回归保障：**

- **双跑对比门槛**：同一输入同时跑 old `breedPlan` 与 new `nestPlan`，断言 **new 的新缺口覆盖数 ≥ old**（old 只有学院 100% 档，new 是超集）——作为"新版不比旧版差"的自动化回归线。
- **不变量断言**（对多组 fixture 恒成立）：`nestsUsed ≤ nestsTotal`、`isolation.ok === true`、每条 pairing `natureChance ∈ {0.3,0.6,1}`、`slots` 内 `petId` 唯一（学院父本共享除外）、簇内两两 `nestsConnect`。
- **快照锁**：用 `补充数据/*.json`（真实备份）跑 nestPlan，对 `pairings`（排序后）/`unfilled`/`nestsUsed` 做快照，防算法微调引起意外抖动。
- **CI**：`vitest run` 全绿 + `tsc --noEmit` 无类型错误。
- **可回滚**：切换用 feature flag，出问题一键回旧面板。

## 附：复杂度速查

| 环节                       | 复杂度           | 备注                                                              |
| -------------------------- | ---------------- | ----------------------------------------------------------------- |
| 枚举候选                   | **O(C · P²)**    | C=缺口格数，P=账号内精灵数；热点，建议按 (grade)/(group) 预建索引 |
| 打分 `scoreCandidate`      | O(G)             | G=候选覆盖组数                                                    |
| 贪心分配（两遍）           | O(K log K)       | K=候选数（排序主导）                                              |
| 局部交换                   | O(I · A · R · G) | I=迭代上限（小常数），A/R=接受/拒候选数                           |
| 摆位 `buildIsolatedLayout` | O(N)             | N=窝数 ≤11                                                        |
| `checkLayout`              | O(N²)            | N ≤11，可忽略                                                     |

> 结论一句话：`nestPlan` 的骨架（枚举 → 打分 → 分配 → 摆位）已经是对的，缺的是**把"只补新缺口"从硬门槛降级为打分项**、**学院 1:2 的表达与成本**、**几何阈值口径**，以及**统一到 UI 的迁移**。
